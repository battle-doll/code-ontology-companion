# 품질 개선 사이클과 충실한 전달 — 0.9.3

개발자: battle-doll(배틀돌). 로컬 MCP, 사람용 오프라인 HTML, 5개 언어 및 Windows·macOS·Linux 지원을 유지합니다.

## 현재 공개 소스 파이프라인의 사람용 화면

공개 `analyze`·`refresh`·일반 `pipeline-html`은 영역 → 주요 구조 모듈 → 핵심 개요의 bounded human 표시가 기본이며 기본 2단계·최대 3단계입니다. 화면당 노드 32개·집계 관계 64개 이내, 5언어 UI는 로컬 script chunk 한 벌을 공유하고 검색은 현재 요약 페이지만 다룹니다. 전체 모드는 전체 범위 집계 root로 돌아가며 카메라 초기화는 범위를 바꾸지 않습니다. 소스 정책 카드는 의미 UNKNOWN인 opaque 근거 타일이며 조건·계산·예외를 완전하게 사람말로 설명한 정책서가 아닙니다. 정확한 깊은 데이터는 MCP에 남습니다. `--presentation records`·legacy workbench·명시적 partitioned record 내보내기는 별도 지원 경로이며 모든 business export가 human 요약이라는 뜻이 아닙니다. HTML 추상화는 AI 답변·정책서에 필요한 정책 의미를 삭제하는 근거가 될 수 없습니다. 개인정보·ACL·현재 소스 결속·무효화 검사는 필수입니다.

## 반복 가능한 사실 → 정책서 품질 흐름

Prose 전에 snapshot·근거 ID와 모든 필수·기존 지원 사실의 evidence mapping을 갖춘 사실 worksheet를 만듭니다. 조건의 모든 피연산자·AND/OR 묶음·참/거짓 분기·조기 종료·단위·계산식·반올림·예외·권한·소유권·식별자·상태·정확한 시간 경계(`<`와 `<=`)·복구 동작을 보존합니다. 닫힌 집합을 열거하고 가려짐·미지원·미확인을 명시하며 값을 추정하거나 부재로 바꾸지 않습니다. Guard는 실제 `controlFlow.kind`로 분류합니다. `synchronized`·`try`·`if`·`switch`는 loop가 아니며 실제 반복 구문만 loop라 부를 수 있습니다.

문서상 계약과 구현의 강제 여부, 정적 관측과 runtime 근거를 각각 구분합니다. 각 의무를 확인한 뒤 worksheet를 prose로 바꾸고, 모든 문장을 근거로 역추적하고 모든 필수 사실이 prose에 반영되었는지 정방향 대조합니다. 추출 worksheet 자체는 완전한 정책서가 아닙니다. HTML은 화면을 추상화할 수 있지만 필수 정책 의미 누락을 정당화하지 못합니다. 파일 처리·선언/타입·exact calls·정책 의미·MCP 전달·문서 coverage의 여섯 차원을 분리합니다. 원 분모·실패·누락·UNKNOWN을 보존하고 합계 혼용이나 임의 부분점수를 만들지 않습니다.

기존 지원 사실의 evidence mapping을 남겨 회귀를 막습니다. 정확히 같은 hash와 영향 범위/도달 경로를 입증하고 parent/new consumer pins를 명시할 때만 검증을 재사용하며, 그 외에는 바뀐 범위를 재검증합니다. Hash 일치도 개인정보·ACL·소스 결속·무효화 검사를 면제하지 않습니다. 이 일반 흐름은 특정 앱 답안·runtime 주장·추가 parser 지원을 만들지 않습니다.

원시 식 목록·opaque guard 이름·위치 기반 생성자 tuple은 자동으로 사람의 정책 의미가 되지 않습니다. Prose 전에 증명된 선언/생성자/component/accessor/helper/provider binding을 이름 있는 매개변수·결과 필드 역할에 연결하고 상태·효과·전제조건·권한·예외 의미를 빠짐없이 확인합니다. 선언되지 않은 단위·효과는 UNKNOWN입니다. 관련 사실을 ESSENTIAL → 본문 단락, SUPPORTING → 기계 인덱스, ALREADY_COVERED → 특정 단락, UNKNOWN → 명시 사유로 분류합니다. 모든 AST node를 나열하는 것으로 정책 설명을 대신하거나 추상화하면서 필수 사실을 조용히 버리지 않습니다. 문서 의도·정적 근거·runtime 강제는 별개입니다.

**Legacy / 명시적 records workbench 범위** — 사람용 HTML은 `data/`의 페이지별 원시 기록을 5개 언어가 공유합니다. 오프라인 스크립트가 읽기 좋은 JSON 보기와 원시 값 검색을 제공하며, 스크립트를 불러오지 못해도 정적 JSON 링크로 내용을 확인할 수 있습니다. 모든 기록·소스 고정 정보·개인정보 검사·출력 한도를 유지합니다. 내보낸 폴더 전체를 함께 보관하세요.

깊은 JSON 필드는 `companion.flat-json.v1` 형식을 사용할 수 있습니다. 순서가 있는 `nodes` 표와 `$ref` 연결로 `root`를 복원하고 `originalSha256`과 `sourceBinding`을 검증하세요. 레코드 ID·근거·페이지 정보는 유지됩니다. 정보 손실 없는 전달 형식이며 새로운 분석 결과나 권한이 아닙니다. 기존 바이트·노드·깊이·개인정보 제한도 유지됩니다.

Java 선언은 제네릭 인자, 애너테이션, throws와 헤더·선언·본문 위치를 구분해 보존합니다. 타입별 원문, 해석된 타입 또는 null, 해석 사유를 제공합니다. 선언을 유일하게 식별해 정적 호출을 연결하더라도 미해결 타입 정보는 그대로 남깁니다. 모호한 후보는 정확한 호출로 세지 않으며, 정적 해석은 런타임 구현체 선택의 증거가 아닙니다.

정책 조각은 지원되는 구문의 제어 문맥과 동작 순서를 보존합니다. 불투명 리터럴, 미해결 호출, 런타임 구현체 선택과 미확인 단위는 명시적으로 남깁니다. 구문만으로 업무 규칙의 실행 가능성·승인·의미 완전성을 보증하지 않습니다.

민감 표현은 `structuralOnly` 호출·참조·대입·제어 구조를 남기면서 숫자·따옴표 값·불리언을 `masked_value`로 가립니다. null은 소스 표식으로만 보존합니다. 중첩된 지연 실행 본문에도 민감 문맥을 이어갑니다. 이 조각은 부분 표현이며 값·표준 API·단위·레코드 구조 검증을 부여하지 않습니다. 가려진 값을 0·false·빈 문자열로 바꾸거나 내용을 추정하지 않습니다.

지원하는 Java 라이브러리 연산은 정적 타입과 오버로드 근거로 표준 시그니처를 식별한 경우에만 `expression.staticContract`를 제공합니다. `contractId`는 같은 조각의 `standardApiContracts`에서 찾으며 별도 조회 레코드가 아닙니다. 카탈로그는 일차 명세와 함께 산술·반올림·단위·예외 조건을 기록하지만 값·실행·동적 구현체 선택을 증명하지 않습니다. enum 생성자 연결은 인자 순서와 직접 필드 대입을 보존하며 모호하거나 조건부인 연결은 후보로 남깁니다.

선택한 Java `record`에서 수신자·컴포넌트 타입·소스 위치·선언 근거와 호출자의 접근 권한이 확인되면, 암시적인 인자 0개 컴포넌트 접근자를 통해 선언된 정적 반환 타입을 연결할 수 있습니다. `staticAccessorBinding`은 컴포넌트 근거를 보존하며 명시적인 인자 0개 접근자 선언을 우선합니다. 컴포넌트·팩터리 반환 연결에서도 호출자의 패키지·최상위 타입 내부 접근 권한을 확인합니다. 지원하지 않는 제네릭·지역 record, 접근 불가 타입, 이름 가림과 모호성은 UNKNOWN으로 남깁니다. 이 반환형 연결은 정확한 `CALLS` 연결을 추가하지 않으며 컴포넌트 값·런타임 구현체 선택·실행을 증명하지 않습니다.

고정한 스냅샷의 MCP 페이지를 끝까지 조회합니다. 바이트 제한 오류는 빈 성공이 아니라 페이지 크기를 줄여야 하는 상태입니다. 실패 ID를 전달 분모에 남기고, 평탄화된 레코드를 복원한 뒤 중첩 조건을 해석하며, 타입 계약이 참조하는 호출 위치 근거도 조회합니다. 이 참조 집합은 전체 소스 호출의 분모가 아닙니다.

참조 누락을 판정하기 전에 내장된 `references[].declarations[]`를 확인합니다. 파라미터의 어휘적 식별자는 별도 조회 레코드가 아니어도 이곳에 소스 위치·타입과 함께 정의될 수 있습니다. 이를 담은 실제 MCP 조각을 인용하고, 정의 부재와 런타임 파라미터 값 미확인을 구분합니다.

소스 해시·범위·합격 기준 고정 → 지식 생성 → 실제 MCP 페이지 조회 → 온톨로지만으로 문서 작성 → 원본에서 독립 도출한 기준과 대조 → 합성 재현 테스트 → 제품 수정 → 같은 입력으로 반복합니다. 수정에 사용하지 않은 별도 검증 사례도 유지합니다.

파일 처리, 선언·타입, 정확한 호출, 정책 의미, MCP 전달, 정책서 커버리지를 따로 보고합니다. 실패 항목을 원래 분모에 남기며 부분 서술에 임의 반점을 주지 않습니다. 직접 소스 보완을 온톨로지 단독 성공으로 계산하지 않습니다. 소스·스냅샷·분석·모델/프롬프트·문서 변경 시 재검증합니다. UNKNOWN/PARTIAL은 유효한 결과입니다.

선택 사항인 비공개 `companion.reviewed-literals.v1` 계약은 독립 검토한 비민감 정책값을 보존합니다. `analyze --literal-review FILE` 또는 `refresh --literal-review FILE`로 직접 선택합니다. 소스 지문·파일 해시·정확한 UTF-8 토큰 바이트 범위와 해시에 묶이며 전역 문자열 허용 목록은 받지 않습니다. 비공개 워크스페이스가 갱신·복구용 계약을 보관합니다. 입력이 바뀌면 재검토하거나 `refresh --clear-literal-review`로 명시적으로 해제하기 전까지 재사용을 차단합니다. 기존 개인정보·민감 문맥 차단은 계속 적용합니다. 요청한 모든 위치는 허용·거부·미관측 상태로 남고, 허용만으로 추출·정책서 완전성을 뜻하지 않습니다. 검토 메타데이터는 신뢰하는 호출자가 제공하는 입력이며 신원 증명이나 공개 권한이 아닙니다. 해제는 이후 스냅샷에 적용되며 기존 스냅샷·내보낸 사본은 내용을 유지합니다.

계약의 최상위 필드는 `format`, `purpose`(`private-policy-analysis`), `sourceFingerprint`, `review`, `entries`입니다. `review`는 `reviewId`, `reviewerKind`(`independent_source_review`), `reviewedAt`을 기록합니다. 각 항목은 `path`, `sourceSha256`, `tokenByteStart`, `tokenByteEnd`(끝 제외), `tokenSha256`, `classification`(`nonsecret_policy`), `reasonCode`, `usageContext`, `reviewId`를 기록합니다. 범위는 따옴표를 포함하며 사유·문맥 코드는 원문 값을 담지 않습니다. 검토 계약을 사용하면 기존 타입 기반 소수 추출이 다루던 숫자 문자열도 포함해, 미검토 따옴표 값은 가려집니다. 검토 파일은 비공개로 보관합니다. CLI는 소스 문구에서 승인을 추론하거나 검토 파일을 자동 탐색하지 않습니다.

배열 초기화와 애너테이션 인자는 원문의 순서·구조와 정확한 발생 위치의 검토 근거를 보존합니다. 애너테이션 대상은 소스 선언 근거이며, 적용 가능성·프레임워크 경로·런타임 동작은 UNKNOWN입니다. 민감한 구조 전용 조각에서도 정확한 소스 바이트·요청 인덱스·개인정보 검사를 통과한 검토된 길이 0 문자열은 빈 표식으로 보존할 수 있습니다. 나머지 민감값 가림, 발생 위치별 격리와 승인 철회는 유지합니다.

파일별 `literalReviewDelivery`는 생성된 조각 트리의 보존 상태입니다. 스냅샷 요약의 `literalReviewRetention`은 허용·보존·미보존 수를 구분하고, 각 `SemanticCoverage` 기록에 미보존 요청 인덱스를 남깁니다. 허용은 사용 권한, 보존은 생성 결과이며 MCP 전달과 정책 의미의 완전성은 각각 별도 검증합니다. 허용 대상이 0개면 100% 대신 NOT_APPLICABLE로 표시합니다.

Java 소스 주석에는 별도의 선택 사항인 비공개 `companion.reviewed-documentation.v1` 계약을 사용합니다. `analyze --documentation-review FILE` 또는 `refresh --documentation-review FILE`로 직접 선택합니다. 기본적으로 인식한 모든 줄·블록·Javadoc 주석은 원문 없이 불투명한 위치·해시 메타데이터를 보존합니다. 독립적으로 비민감 여부를 검토한 정확한 발생 위치가 기존 개인정보 프로필·기본 검사를 통과한 경우에만 원래 토큰을 `sourceText`로 담습니다. 원문과 서식 정규화 검사본을 모두 검사하며, 정규화 결과로 출력 원문을 바꾸지 않습니다.

문서 검토 manifest의 최상위 필드는 `format`, `purpose`(`private-policy-analysis`), `sourceFingerprint`, `review`, `entries`입니다. `review`는 `reviewId`, `reviewerKind`(`independent_source_review`), `reviewedAt`을 담습니다. 각 항목은 `path`, `sourceSha256`, `tokenByteStart`, `tokenByteEnd`(끝 제외), `tokenSha256`, `classification`(`nonsecret_documentation`), `reasonCode`, `usageContext`, `reviewId`를 기록합니다. 지문·파일 해시·UTF-8 바이트 범위와 해시는 주석 구분자를 포함한 정확한 토큰 전체에 묶이며, 줄 주석의 줄바꿈 문자는 제외합니다. 부분 문자열은 허용하지 않습니다. manifest에는 원문이나 실제 값을 넣지 않습니다. 한도는 512 KiB, 5,000개 항목, 주석 토큰당 8,192바이트입니다.

비공개 워크스페이스는 갱신·복구용 문서 검토 계약을 보관합니다. 입력이 바뀌면 일치하는 새 검토를 제공하거나 `refresh --clear-documentation-review`로 해제해야 합니다. 해제는 이후 스냅샷에만 적용되며 기존 스냅샷과 내보낸 사본은 내용을 유지합니다. `DocumentationCoverage`는 미검토 주석, 허용·거부·미관측 요청과 누락을 명시합니다. 인식한 토큰 목록의 커버리지와 `lexicalComplete`를 구분하며, 미지원 언어·Java Unicode 전처리·미확인 어휘 경계에서는 전체 주석 분모가 UNKNOWN입니다. 한도로 누락한 항목의 수와 사유를 보존하고 목록을 미완료로 표시합니다. 주석과 표현 조각은 기존 파일별 한도를 공유하며, 허용이나 전달만으로 정책의 완전성을 뜻하지 않습니다.

문서화된 표준 오버로드에는 소수 나머지와 나노초 차감이 포함됩니다. 나머지는 음수일 수 있어 항상 비음수인 modulo와 다릅니다. MathContext는 내부 정수 몫을 제한하며 나머지 계산 자체는 정확합니다. 시간 계약은 단위·예외 조건을 보존하고, 숫자 타입만으로 업무 단위를 확정하지 않습니다.

최종 검토에서 정의가 누락되거나 불일치·철회되면 이에 의존한 타입·접근자·생성자·API 근거도 철회합니다. 원래 구문과 독립적인 다른 근거는 보존합니다. 의존 근거 확인이 보류된 상태로 최종 스냅샷을 완료하지 않으며 UNKNOWN을 확정 주장으로 바꾸지 않습니다.

파이프라인 RDF는 커버리지·누락·검토된 문서를 포함한 의미 조각에 기존 조회용 `co:Symbol`을 유지하고, `co:SemanticFragment`와 실제 `co:extractorVersion`을 추가합니다. 가상의 `ruleVersion`으로 대체하지 않습니다. Java Record 심볼은 생성자 호출과 독립적으로 `recordComponents`를 제공합니다. 컴포넌트의 순서·이름·선언 타입과 확정/UNKNOWN 타입 쌍은 부모 record ID·경로·소스 해시·문자 범위에 묶입니다. `recordHeaderRange`는 컴포넌트 목록의 괄호를 포함하고, `recordComponentCoverage`는 확인된 원래 개수·생성 항목·누락·미지원 항목을 구분합니다. 목록은 최대 64개를 내보내지만 공유 parser와 기존 필드·호출 분석은 자르지 않습니다. 너무 긴 텍스트 필드는 사유와 함께 가립니다. 미확정 타입은 null/UNKNOWN이며, 잘못된 문법이나 불완전한 목록은 PARTIAL로 남습니다. 애너테이션 인자값은 포함하지 않습니다. 선언 관측은 저장값·실행·추가 정확 CALLS를 증명하지 않습니다.

Java 블록 안의 `var` 지역 변수는 소스에 연결된 표현식 분석에서 이미 확인한 초기화식의 정적 타입만 이어받을 수 있습니다. `localTypeInference`는 선언·초기화식·어휘 범위를 파일 해시에 묶고, 사용 위치의 타입은 `localTypeBinding`으로 그 정의를 참조합니다. 연결은 간결하게 유지하며 기존 의존 깊이 제한을 지킵니다. 미확인·잘못된 문법·자기 참조·복수 선언자·가려진 값·미지원 초기화식은 UNKNOWN입니다. 정의가 누락되거나 철회되면 의존 타입/API 근거도 철회하되 구문과 독립된 다른 근거는 보존합니다. 생성된 `var` 선언의 집계와 원래 조각 목록의 누락을 구분합니다. 이는 제한된 정적 타입 전달이며 값 계산·확정 대입 증명·일반 제네릭 추론·실행 증거가 아닙니다.

초기식 타입 재사용은 토큰 범위와 Java 인덱스의 명명된 타입·메서드 소유 범위가 일치할 때만 허용합니다. 지역·익명 클래스, 소유 범위 누락·불일치, 증명되지 않은 바깥 필드 참조는 UNKNOWN으로 유지합니다. 가장 가까운 멤버 선언을 확인하며 상속 멤버가 바깥 필드를 가릴 수 있습니다. 소유 심벌 누락이나 사용 위치의 소유 범위 변경은 종속 근거를 철회합니다. 기존 미지원 문장 영역은 분모에 계속 표시합니다.

소유 근거는 실제로 투영된 Java 심벌 정의와 대조합니다. 심벌의 sourceRange는 전체 declarationRange와 같고 bodyRange는 본문 범위를 나타내며, 위치 단위는 Unicode 코드포인트입니다. declarationSpan은 전체 선언을 설명하고 span/headerSpan은 헤더만 설명할 수 있습니다. 지원되는 controlFlow.owner.id는 실제 메서드 심벌 ID입니다. 정의 누락, 경계 변조, sourceRange 불일치, 다른 메서드 ID 대체 또는 소유 정의 조회 불가는 종속 추론을 철회합니다. 복사된 메타데이터끼리 같다는 사실만으로 근거를 인정하지 않습니다.

Java 상속 이름 검사는 정확한 플랫폼 정체성에 한해 제한된 `java-se21-member-inventory-1` 카탈로그를 사용할 수 있습니다. 스냅샷과 분석 명세의 `javaStaticModel`은 Java SE 21을 유효 정적 모델로 가정하며, `actualTargetJdk`는 `UNKNOWN`입니다. `platformTypeContracts`에는 필드·멤버 타입·부모 목록과 공식 명세 링크가 중복 없이 들어갑니다. 간결한 `platformInheritance` 참조는 같은 fragment 또는 Record 심볼의 `platformInheritanceChecks`를 가리키며, 선택된 소스 선언 ID·경로·다이제스트·헤더 범위·부모 참조 위치를 보존합니다. 타입 심볼의 `sourceRange`와 `declarationHeaderRange`는 0부터 시작하는 끝 제외 문자 오프셋입니다. 이는 제한된 어휘 관찰과 문서화된 플랫폼 가정이며, 대상 JDK 탐지·전체 멤버 내보내기·정확 CALLS·실행·런타임 값 증거가 아닙니다. 미확인 부모, 모호한 import, 선택 소스의 플랫폼 정체성 충돌, 실제 가림 멤버, 투영 한도는 불확실성을 명시합니다. 지역 `var` 타입은 이 모델에서 추론하지 않습니다.

완전한 한정 이름이나 단일 명시 타입 import는 관련 없는 on-demand import와 독립적으로 알려진 부모를 고정할 수 있습니다. 미확인 부모·충돌하는 명시 import·고정하지 못한 모호한 on-demand import는 `UNKNOWN`입니다. static on-demand 부모 import는 선택된 owner도 별도의 소스 결합 멤버 부재 근거를 제공하기 전까지 `UNKNOWN`입니다. 이름이 비슷하다는 이유로 렉시컬 멤버 타입을 표준 타입으로 승격하지 않습니다. 소스 반환형 수신자는 계속 정확한 접근 가능 소스 선언과 callsite를 요구하며 미해결 overload에 표준 API 계약을 부여하지 않습니다. 이름공간·import 규칙은 [JLS 6.5.5](https://docs.oracle.com/javase/specs/jls/se21/html/jls-6.html#jls-6.5.5)와 [JLS 7.5](https://docs.oracle.com/javase/specs/jls/se21/html/jls-7.html#jls-7.5)를 따릅니다. 제한된 정적 검사이며 실제 대상 JDK·런타임 계층·값·실행은 `UNKNOWN`입니다.

인라인 플랫폼 정의는 ID와 canonical JSON 내용을 함께 대조합니다. 내용이 완전히 같은 중복은 기존 64개 검증 한도 안에서 동등하게 취급합니다. 객체 키 순서는 무시하지만 배열 순서와 JSON 값의 타입은 구분합니다. 같은 ID에 서로 다른 내용이 있으면 배열 순서로 우선 정의를 선택하지 않습니다. 종속 타입·API 근거는 `platform_inheritance_definition_conflict`와 함께 `UNKNOWN`이 되며, 독립 형제 근거는 유지됩니다. 소스 모델과 6개 canonical 플랫폼 계약 내용은 바뀌지 않습니다.

`platformInheritance` schema 2는 각 타입 사용 위치를 한도 내 `platformTypeProofs` 그래프에 연결합니다. 직접 근거는 실제 전달된 선언 또는 소스 구문 위치와 소유자·타입 표기·이름공간·경로·소스 해시를 식별합니다. 전파 근거는 같은 IR 레코드의 실제 수신자·인수·피연산자 위치를 가리키며, 표준 API 서명과 피연산자·반환 타입은 공통 카탈로그와 대조합니다. 따라서 기본형 API 반환값이 수신자의 타입 해석 근거를 이어받아도 수신자 타입을 반환 타입으로 간주하지 않습니다. 누락·충돌·철회되거나 잘못 연결된 원천은 `UNKNOWN`으로 처리하고 독립 형제 근거는 유지합니다. canonical 내용이 같은 중복은 기존 한도 안에서 동등합니다. 검사와 타입 증명은 합계 64개, 공통 카탈로그·검사·증명은 합계 64 KiB 메타데이터 한도를 공유하며 순환·깊이·탐색 한도 초과는 근거를 확정하지 않습니다. 타입·메서드의 선언 및 본문 범위, 한도 내 import 관측, 정확한 callsite ID로 대조합니다. 인라인 증명 ID와 JSON pointer는 별도로 조회하는 소스 레코드가 아닙니다. 명시된 Java SE 21 가정 아래의 정적 소스 근거이며 실제 대상 JDK·런타임 값·디스패치·실행·업무 정책 완전성은 `UNKNOWN`입니다.

`platformTypeProofs` 정의의 유효성 캐시는 각 실제 소비자 검증을 대체하지 않습니다. 캐시된 의존성 결과를 재사용하기 전에 IR 위치·역할·타입·검사 참조가 일치해야 합니다. 탐색 순서와 관계없이 다른 소비자의 유효한 증명을 가져와 확정 근거로 사용할 수 없습니다.

선택적 업무 지식 오버레이는 소스 스냅샷과 기존 3D 지도를 보존합니다. 별도의 오프라인 5개 언어 보기에서 선택한 모든 업무 레코드, 방향 관계, 정책의 단위·시간·조합 요소, 소스 계보와 독립적인 근거·승인 상태를 확인합니다. 누락되거나 지원되지 않는 요소는 UNKNOWN으로 남습니다. 지식 승인은 실행 권한, 런타임 동작이나 전체 정책 완전성을 증명하지 않습니다. 소스·명세·검토 변경 시 재검증하며 원래 선택·실패·누락 분모를 보존합니다.

업무 HTML·번들 내보내기는 export_html/export_bundle과 read_structure, read_policy, read_evidence 권한을 모두 요구합니다. 신뢰된 콜백이 게시 잠금 안에서 정확한 소스·업무 핀, ACL 리비전, 현재 개인정보 프로필과 안정된 리더를 재확인합니다. 신규 비공개 폴더에 모든 원본 업무 JSON과 범위를 보존하고, 비활성 텍스트와 상대 오프라인 링크를 사용하며 소스 출력과 기존 총 1 GiB 예산을 공유합니다. RDF 1.1/PROV와 선언 SHACL shape에는 원본 JSON 참조를 포함한 레코드별 매핑 손실 보고가 따릅니다. 직렬화나 shape 통과는 업무 명제의 사실성을 증명하지 않습니다. 네이티브 브라우저·shape 검증은 별도 실행 전까지 NOT_RUN입니다. 이후 ACL·철회 변경으로 이미 내보낸 사본을 철회할 수 없습니다. 개발자: battle-doll.

한정된 TypeScript boolean 정책 파서는 명명된 빈 클래스 또는 세미콜론으로 끝나는 초기값 없는 `boolean`·`number`·`string` 필드와 함께 있는 순수 타입 함수를 보존할 수 있습니다. 클래스 바로 앞의 선택적 `export`를 지원합니다. 클래스는 실제 모듈 바인딩으로 파싱·보존하므로 클래스와 함수의 이름 중복 및 내부 타입 이름 가림을 무시하지 않습니다. 초기값·static 블록과 멤버·메서드·상속·decorator·계산된 이름 등 미지원 형태는 `UNKNOWN`이며 선택한 소스에서 클래스를 제거하지 않습니다. `source_policy_declaration` 레코드는 `source-policy-declarations-1`과 경로·소스 해시·행 범위·lexer 토큰 인덱스 범위, 비정책 선정 상태와 런타임 한계를 보존합니다. 선언 관측이며 실행 가능한 정책 계산식이나 런타임 필드 값의 증거가 아닙니다. 별도 `sourceDeclarationCoverage`는 봉인된 정책 요약과 MCP에 남으며 정책 규칙 분자를 늘리거나 업무 정책 완전성을 증명하지 않습니다. 기존 예산을 유지하며 선언 레코드 누락 시 새 스냅샷 승격을 차단합니다. 이 lexer의 위치 정보는 문자·바이트 offset을 주장하지 않습니다.

지역 `var` 타입 근거는 정확한 초기화식 레코드를 통해 제한된 플랫폼 상속 근거를 이어받을 수 있습니다. `platformTypeProofs`의 `kind=local_initializer` 직접 출처는 실제 출력된 지역 선언과 `/expression/staticType` 증명을 가리키며, 각 소비 위치는 별도 증명 ID를 유지합니다. 필요한 검사·카탈로그 정의만 기존 한도 안에서 중복 없이 전달합니다. 실제 지역 바인딩, 선언·사용 범위와 메서드 소유자도 대조합니다. 누락·철회·충돌·한도 초과 의존성은 `UNKNOWN`이며 원문 구조와 커버리지를 보존합니다. 정적 타입 연결이며 런타임 값·실행·정확한 호출 해석을 입증하지 않습니다.

별도 소스 선언 커버리지는 봉인된 정책 집계에서 소스 HTML·업무 후보 커버리지·읽기 전용 MCP·업무 HTML까지 전달합니다. 검토·철회 후에도 원래 소스 분모를 유지합니다. 구버전 또는 비 TypeScript 집계가 없으면 0으로 추정하지 않고 UNKNOWN으로 표시합니다. 고정된 범위·사유 코드와 음수가 아닌 정수 카운터·명시적인 완전성 표시만 전달합니다. 선언 목록은 정책 규칙 수를 늘리거나 업무 정책 완전성을 입증하지 않습니다.

직접 필드 목록은 예약된 선언 식별자, 중복·충돌 필드 modifier, 잘못된 wildcard bound, 빈 초기화식과 뒤에 남은 토큰도 거부합니다. enum 인자와 record 컴포넌트 헤더에도 같은 보수적 구문 경계를 적용합니다. 공유 식 파서를 재사용해도 javac가 되지는 않습니다. 비어 있지 않은 anonymous 멤버 본문·타입/애너테이션/중첩 또는 미소비 구문이 있는 미지원 람다·generic method 인자 등 제한 IR이 구분하지 못하는 문법은 UNKNOWN입니다. 따라서 근접한 유효 구문도 명시적인 inventory 사유와 함께 보류될 수 있습니다. 따옴표 literal은 값을 보존하지 않고 구문만 검사합니다. 지원하는 선언 구문에 대한 검사이며 compiler 유효성·대입 타입 호환성·실행·실제 대상 JDK는 미검증입니다.

정확한 소스 메서드 선언 범위가 있으면 제어 흐름 소유자에 별도 declarationSpan을 보존합니다. 기존의 어휘적 span은 유지하며 애너테이션과 여러 행의 헤더가 전체 선언을 그 앞까지 확장할 수 있습니다. 두 범위는 동일 소스 해시와 문자 위치에 연결됩니다. 계보의 위치를 정밀화하며 선언·호출·정책 의미나 실행 근거를 늘리지 않습니다. 미해결 어휘적 소유자에는 선언 범위를 추정해 넣지 않습니다.

## 업무 후보 분할 저장

기본 후보 생성은 선택한 소스 스냅샷 전체를 순회합니다. 변경 불가능한 SQLite 조각은 각각 최대 10,000행·64MiB이며 기존 소스 작업공간의 기록 수·출력 용량·처리 기한 안에서 생성합니다. 개별 기록·JSON 깊이·조회·개인정보·접근권한 한도는 유지합니다. --max-records를 명시하면 제한된 미리보기를 요청하며, 원래 분모와 처리하지 못한 모든 입력의 상태를 남깁니다. --partition-size는 조각별 행 수를 정합니다. 검토는 요청당 최대 10,000개 개념으로 제한하고 자동 후보 전체·독립 승인 이력·sourceCandidates 분모를 보존합니다. 소스·명세·권한 고정, 게시 잠금, 포인터 대조와 원자적 게시가 필수입니다. 소스 기록이 문자·바이트 좌표를 함께 제공하면 각각 검증하고 변환이나 대체 없이 보존합니다. 현재 소스·명세·권한이 일치하는 기존 v1 JSON도 읽습니다. 후보를 모두 저장해도 의미 완전성을 뜻하지 않으며 업무 의미는 PARTIAL, 전체 업무 규칙의 커버리지는 UNKNOWN으로 유지합니다.

조회 필터나 합계를 신뢰하기 전에 캐시되지 않은 각 조각을 순회해 인덱스의 id·kind·domain·대소문자 정규화 이름을 정규 본문·개념 ID와 대조하고, 반환 행도 다시 검증합니다. 프로세스 내부 LRU는 성공한 메타데이터 결과만 최대 64개 보관하며 정확한 경로·전체 파일 식별 정보·산출물 SHA·스키마·생산 명세로 구분합니다. 기록 값은 캐시하지 않습니다. 복사·교체·해시나 명세 변경·캐시 제거 후에는 재검사하고, 실패한 조회기는 보류된 캐시를 반영하지 않습니다. 무결성 검증과 업무 의미 완전성은 별도로 판단합니다.

## 원시 기록의 공용 전달 형식

내려받는 원시 JSON은 기존 직렬화 바이트를 보존합니다. 별도 JavaScript 전달 파일은 반복 키·문자열을 결정적 사전과 한도가 있는 공용 디코더로 표현할 수 있으며, 복원한 값은 기존 JSON.parse 전달 방식과 같습니다. 사전 전달 파일이 기존 파일보다 작지 않은 페이지와 JavaScript에서 비유한 숫자로 반올림되는 유효한 JSON 정수가 있는 페이지는 기존 방식을 사용합니다. 브라우저의 기존 숫자 정밀도·범위 한계를 유지하며 JavaScript 숫자를 정확한 십진 산술로 바꾸지는 않습니다. 원래 숫자 표현이 필요한 소비자는 원시 JSON을 사용할 수 있습니다. 사전 디코더는 허용 태그·참조·중복 키·기록 수·깊이·바이트 한도를 검증합니다. 5개 언어의 오프라인 탐색·원시 파일 다운로드·기존 3D 페이지 범위를 유지하고 fetch나 HTTP 서버를 요구하지 않습니다. 전달 형식 검증과 실제 브라우저·접근성·성능·정책 의미 검증은 별도로 판단합니다.

## Java 생성자와 제네릭 생성식의 제한된 멤버 목록

직접 멤버 이름 검사에서 소유 타입명과 일치하는 클래스·열거형 생성자 헤더와 레코드의 간결 생성자를 인식한 뒤, 균형이 맞는 몸통을 건너뜁니다. 지원하는 접근 제어자·타입 매개변수·형식 매개변수·마지막 가변 인자·throws 절은 끝까지 해석되어야 합니다. 각 타입의 `constructorInventory`에 소스에 묶인 헤더·몸통 범위를 한 번만 기록하고, `constructor_body_semantics_not_modeled`, 탐지된 제한 구문의 유한 개수, 분석한 몸통 0개, Java 전체 선언 분모 `UNKNOWN`을 명시합니다. 생성자 문장·초기화·생성자 CALLS·컴파일·실행은 분석하지 않습니다.

끝까지 해석되는 제네릭·다이아몬드 생성 초기화식은 뒤따르는 필드 이름을 보존합니다. 중첩 참조 타입 인자와 `List<int[]>` 같은 기본 타입 배열의 참조 타입 인자를 지원합니다. `List<int>`, 생성 타입의 직접 와일드카드 인자, 잘못되거나 남은 토큰, 내용이 있는 익명 몸통, 타입/애너테이션/중첩 또는 미소비 구문이 있는 미지원 람다, 수신자 매개변수와 미지원 애너테이션은 `UNKNOWN`을 유지합니다. 실제 필드·멤버 타입·구성요소·열거형의 이름 가림, 알 수 없는 부모와 유니코드 이스케이프 보호는 종속 API 의미 메타데이터을 계속 철회합니다. 원래 ID·CALLS·대상·선언 범위·표현식 값·실행 상태 미확인은 보존하며, 지원하는 파생 정적 근거만 복원합니다. Windows·Linux 네이티브 검증은 Python 3.9 macOS 검증과 구분합니다.

제한된 무타입 람다 초기화식은 매개변수·화살표·본문·나머지 선언자를 완전히 확인한 뒤 직접 필드명만 확인합니다. 타입·주석이 붙은 매개변수, 중첩 람다, 지역 선언, 미지원 익명 본문, 잘못된 구문과 예산 초과는 UNKNOWN을 유지합니다. 람다 실행·본문 타입 호환성·값은 모델링하지 않습니다. 선택된 static wildcard 필드는 정확한 직접 owner와 소스에 결속된 선언으로만 인정하며, 상속 가림·모호성·불완전 목록의 차단은 유지합니다.

단일·와일드카드 static 필드 사용은 declarationProofVersion=1을 요구합니다. 실제 전달된 필드의 declaredType 및 해석된 타입 표기는 소스에 결속된 owner ID·이름·종류·경로·digest·선언/헤더/본문 범위와 맞아야 합니다. 타입마다 directMemberInventory를 한 번 기록하며, 플랫폼 부모가 없는 경우를 포함한 이름 부재 검사는 실제 목록과 일치해야 합니다. 누락·모순은 종속 근거를 철회합니다. 문자열·문자·빈 리터럴 토큰은 값을 보존하지 않고 구문만 확인합니다. 식 토큰 512개, 매개변수/문장 64개, 직접 멤버 영역 1,024개, 중첩 32개 제한을 유지합니다. 람다 매개변수의 이름 가림은 해당 지역에 적용하며 생성자 본문은 모델링하지 않습니다.

선택된 static 필드는 실제 타입의 직접 멤버 선언 목록과도 일치해야 합니다. 헤더 modifier·static/final 자격·원래 타입·정확한 선언/초기화식 범위를 실제 비호출부 필드 역할과 함께 확인하며, 지역 선언이나 초기화 블록을 필드로 인정하지 않습니다. 실제 caller 선언과 완전한 import 메타데이터로 단일 import 우선순위 또는 모든 활성 wildcard namespace를 확인합니다. 직접 lexical 참조에 import 의무를 추가하지 않습니다. 목록은 탐지·미지원·예산 누락 수를 보존하며 후보 영역 최대 1,024개·선언 64 KiB, caller namespace는 import/검사 최대 64개·64 KiB로 제한합니다. 완전성은 제한된 인덱스 선언에만 해당하며 대입 호환성·초기화식 평가·컴파일·전체 Java 필드 범위는 UNKNOWN입니다.

진행 중인 호출은 이미 검증한 정책 스냅샷으로 끝날 수 있습니다. 후속 호출은 정책을 다시 읽습니다.

## 선택적 명시 업무 계약

property_type은 정밀도·소수 자릿수·반올림·단위·통화·시간 정보를 보존합니다. formula_mapping은 현재 source pins, 실제 rule digest, 정확한 property ID·매개변수·반환 타입과 /program·/returnType anchor를 요구하며 이름으로 추정하지 않습니다. policy_composition은 고유 우선순위와 명시한 배타성·중첩 방식으로 최대16개를 선택합니다. 누락·충돌·철회·비교 불가는 UNKNOWN입니다. 계산 참조의 중복·순환만 거부하고 일반 업무 관계 그래프 순환은 허용합니다. 현재 eligibility·exclusions는 명시적 NOT_APPLICABLE만 지원합니다.

정책 전용 응답은 목록 안에 중첩된 계산식 연결에서도 원본 스냅샷 결속 정보와 레코드·수치 문맥 해시를 숨깁니다. 근거 조회 권한이 있는 응답과 정식 내보내기는 이 증명을 유지하며, 축약된 응답을 검토 매니페스트로 재사용할 수는 없습니다. 정책 조합의 모든 단계에서 적용·제외 조건을 명시해야 합니다. 시간대가 있는 업무 시각은 원본의 날짜 유효기간과 별도로 검사합니다. 날짜 제한이 없는 원본 함수는 평가할 수 있지만, 날짜 제한과 업무 시각을 연결하는 근거가 없으면 UNKNOWN입니다. 호스트 시각이나 임의로 잘라 낸 날짜를 사용하지 않습니다.

### 정확한 차원과 결과 기여 정책

명시적 수량·금액 계약은 소스 `int` 타입을 유지하며 연결할 수 있습니다. 전달 값은 문자열로 보존하며, `int`에는 정확한 정수 표기만 허용합니다. 분수, `2.0` 같은 소수 표기, 실수 값, 범위 초과, 정밀도·소수 자릿수 불일치는 반올림하지 않고 미지원으로 남깁니다. 금액은 명시적으로 검토한 단위와 통화를 함께 보존할 수 있습니다. 단위는 선언된 차원이며 가격 관행이나 통화 변환을 추정하지 않습니다. 기존 선언 요소와도 정확히 일치해야 합니다.

`selectedPolicyIds`는 전체 의존 목록을 유지합니다. `activeMemberPolicyIds`는 적용 가능한 직접 하위 정책, `selectedMemberPolicyIds`는 우선순위·합산 규칙 이후 결과에 기여한 직접 하위 정책입니다. `contributingPolicyIds`와 `contributingSourceRuleIds`는 기여한 최하위 정책과 정확한 소스 규칙입니다. 최솟값·최댓값이 같으면 모든 동률 기여자를 보존하며, 중첩 선택과 유한 문맥별 최선 결과에도 각각 계보를 제공합니다. 미해결·충돌 시 기여 목록은 null이며 승자를 추정하지 않습니다. 원래 정책·문맥 분모와 `globalOptimum=UNKNOWN`을 유지합니다.

검토 예산으로 빠진 입력은 커버리지 요약과 원래 입력 처리 기록 양쪽에 동일하게 집계하며, 미처리 입력을 분모에서 제거하지 않습니다.

소스 출처 해시 계산에는 JSON 깊이 128의 별도 한계를 적용하며, 인라인 업무 JSON의 깊이 제한 32는 유지합니다. 두 경로 모두 노드 2,000,000개, 인코딩된 크기 32 MiB, 문자열·키 길이와 유한 수 제한을 유지합니다. 깊은 소스 구조는 정확한 해시로 연결하며 업무 속성에 복사하거나 승인된 의미로 간주하지 않습니다. 한계를 넘는 입력은 원래 분모에 미지원으로 남깁니다. 기존에 허용된 정규 해시는 바뀌지 않습니다.

스트리밍 교환 파일은 모든 논리 레코드의 개인정보를 검사하고 봉인된 바이트와 해시를 보존합니다. 최신 상태 검사는 시작·종료와 제한된 묶음마다 실행합니다. 일반 출력은 최대 128개 레코드 또는 64 KiB이며, 각 레코드 뒤에서 경과 50ms도 협력적으로 확인합니다. 더 큰 레코드는 분할하지 않고 최대 4 MiB 한 개만 별도로 처리합니다. 묶음 중 취소·권한 철회는 레코드별 콜백보다 늦게 관측될 수 있고, 50ms는 블로킹 입출력이나 개인정보 검사의 강제 종료 시간이 아닙니다. 권한 판단을 캐시하지 않으며 최종 권한·프로필·스냅샷 검사와 원자적 공개 조건을 유지합니다. 분할 내보내기는 소스 RDF 준비 단계를 명시적으로 보고합니다.

## 제네릭 instanceof 구문의 유한 지원

Java 기능 어댑터는 `Map<?,?>`, `List<?>`처럼 지원하는 비한정 wildcard 형식에서 검사 대상, 한정·중첩 타입 구간, 참조 배열 차원, 패턴 이름, 부정과 분기 문맥을 보존합니다. 확장 타입 노드는 `op: type_reference`, `syntaxVersion: java.instanceof.type.v1`을 사용합니다. 구문 전용 `partial`이며 `instanceof_runtime_unresolved`를 남깁니다. 실제 타입 일치·컴파일 유효성·대상 Java 버전은 `UNKNOWN`입니다. 패턴 이름의 수신자 타입·필드값·실행·승인된 업무 의미는 추론하지 않습니다. Java SE 21은 구문 참고 규격이며 애플리케이션 컴파일러 설정의 근거가 아닙니다.

식 제한은 512토큰과 파서 재귀 진입 32단계입니다. 좌결합으로 만들어진 최종 트리의 모든 간선 깊이를 32로 제한한다는 뜻은 아닙니다. 확장 타입은 한정 구간·전체 wildcard 자리·배열 차원을 각각 32개까지 허용하며 공유 타입 판독기와 보수적 대체 스캔은 각각 최대 512토큰을 소비합니다. 기존 plain 한정 타입은 이전 식 제한을 유지합니다. bound·구체적/중첩 타입 인자·애너테이션/record 패턴·잘못된 구문·상한 초과는 원본 위치와 사유를 남기고 미지원/UNKNOWN입니다.

가능한 패턴 이름은 해당 callable 안에서 충돌하는 외부·플랫폼 결속을 보수적으로 보류합니다. callable 소유권을 모르면 로컬 블록이나 식에 한정합니다. 스캔 상한이나 소유권 미확인은 로컬 불확실성 사유로 남기며 다른 메서드·파일을 차단하지 않습니다. 기존 소스 ID와 CALLS는 이 구문 기능과 구분합니다. 원시 JSON/MCP/HTML과 소스 번들 SQLite는 구문을 보존하지만 그래프/RDF 투영은 그 전체 의미를 증명하지 않습니다. 필수 노드·버전을 해석하지 못하는 소비자는 타입·패턴 이름을 지우지 않고 UNKNOWN 또는 해석 거부를 유지해야 합니다. 독립 정책 작성자 검증과 실제 브라우저 동작은 별도 관문입니다. 특정 애플리케이션 파일·메서드·업무 단어 조건 없이 언어 구문과 출처 계약을 적용합니다.

중첩 lambda는 별도의 callable 경계이므로 내부 패턴이 독립적인 바깥 호출을 차단하지 않습니다. API 피연산자는 실제 lexical 사용 위치에서 확인하며, 이름만 집계한 참조 요약은 서로 다른 범위의 사용을 구분할 수 없으면 UNKNOWN을 유지합니다.


### 대입 구문과 record 선언의 경계

Java 의미 조각은 산술·비트·시프트 복합 대입을 포함한 원래 대입 연산자를 보존합니다. 한정된 지원 대상에는 조건부 읽기·수정·쓰기 계약을 부착할 수 있으며, 미지원 대상은 위치·사유·미완료 상태를 유지합니다. 이 계약은 식을 실행하거나 대상 값·부작용·실제 실행 동작을 확정하지 않습니다.

record 멤버 목록은 compact 생성자와 지원하는 명시적 생성자 헤더를 구분합니다. 한정된 오버로드 헤더와 compact 생성자가 함께 있어도 선언된 record 성분을 숨기지 않습니다. 헤더 인식은 컴파일 유효성, 생성자 본문 동작, 위임, 매개변수와 필드의 대응을 보장하지 않습니다. 모호한 시그니처·미지원 구문·충돌하는 선언은 UNKNOWN입니다. 직렬화된 영역 종류 `record_explicit`은 구문 메타데이터이며, 이를 모르는 소비자는 원본 레코드와 명시적 미지원 상태를 보존해야 합니다. 정적 선언·수신자 근거와 런타임 호출 선택은 별도로 구분합니다.

## 명시적 공급 숫자 관측값 비교

`compare_policy_cases`의 기본값은 `comparison_mode=source_contexts`이며, 소스 매개변수 이름이 `id`나 `value`여도 같습니다. 명시적 `supplied_values`는 `knowledge_view=business`, 기존의 구체적 source/business 핀과 정책 읽기 권한이 필요합니다. 소스 규칙이나 선택적 정책 조합을 호출하지 않으며 `sourceEvaluation`은 null, `sourceRuleEvaluated`는 false입니다. 기존 철회·충돌·승인 관문을 유지합니다. 업무 레코드 승인은 공급값의 진실성·적격성을 승인하지 않으며 실행·적격성은 UNKNOWN입니다.

각 사례는 정확히 `id`, `value`를 가집니다. ID는 제어문자 없는128자 이하의 고유한 비어 있지 않은 문자열입니다. 값은 원시 정수 또는 기존 typed `integer`, `decimal`, `quantity`, `money` 객체입니다. 정수 절댓값은10**100 이하이고, 소수 문자열은 기존의 지수 없는 일반 문법128자 이하입니다. 정밀도가 명시되면 검사하며 없으면 만들지 않습니다. 정수·소수 scalar는 함께 비교하고, 수량은 단위가 정확히 같아야 하며, 금액은 통화와 선택적 단위 tuple이 같아야 합니다. 종류·단위·통화가 섞이면 유효한 숫자 항목 모두를 비교 불가로 남기고 임의 기준 그룹이나 변환을 택하지 않습니다. 서버는 공급된 값을 정확히 비교하지만 클라이언트에서 이미 잃은 정밀도를 복원하지는 않습니다.

`suppliedComparison`은 원래 `inputIndex`, `/cases/<index>`, 유효한 ID, canonical 입력 digest, 처리 상태·사유를 보존합니다. 누락·미지원·잘못된 값과 중복 항목 모두 원래 분모에 남습니다. minimum·maximum·best는 동률인 모든 index/ID 참조를 원래 순서로 반환하고 값은 각 entries에 남깁니다. COMPLETE는 선택한 공급값 전부가 이 국소 비교에서 수락됐다는 뜻입니다. 미확인·거부가 있으면 PARTIAL이며 지원 부분집합을 전체 순위로 부르지 않습니다. 전역 최적성·정책 전체 완전성은 증명하지 않습니다.

원래 cases 전체를 후보·질의 hashing이나 부분 출력보다 먼저 privacy 검사하며, 거부하면 요청 전체를 거부합니다. 사례100개·canonical cases64KiB 상한과 기존 전체 요청 protocol 상한을 함께 적용합니다. 내부 초과는 미처리 frontier가 있는 BLOCKED로 반환합니다. 잘못되거나 상한을 넘은 protocol 요청은 호출 전에 거부되므로 항목별 처리 증거가 아닙니다. 질의 식별은 원래 사례·목표·모드·현재 핀·허용된 정책 투영에 묶습니다. 정책 전용 독자에게 숨겨진 레코드별 근거 digest를 추가로 노출하지 않습니다.


## 미완료 처리 상태 전달

인식한 타입 정책 함수에는 추출됨·미지원·미분석 상태와 원본 위치, 정해진 사유를 남깁니다. 이 기록은 커버리지 메타데이터이며 정책 의미 검증이나 실행 증거가 아닙니다. 기존 선언 기록 한도를 함께 사용하며, 남은 기록 예산이 0이어도 별도 요약에 인식·기록·미기록·처리 결과 수를 보존합니다. 분모는 인식된 후보 범위입니다. 전체 소스 함수의 분모와 업무 전체 완전성은 UNKNOWN입니다.

업무 MCP 상태 조회는 마지막으로 기록된 미게시 빌드와 게시된 스냅샷을 구분합니다. `read_evidence` 권한이 있고 원본 스냅샷이 일치하면 원래 선택한 소스 레코드 수를 분모로 처리·미처리 수와 게시 여부를 전달합니다. 실패를 유발한 개별 입력이나 모든 시도의 이력을 추정하지 않습니다. 기록 없음·잘못된 기록·읽는 중 변경·원본 불일치는 명시적으로 표시합니다. 정책만 읽는 사용자는 기록 조회 없이 WITHHELD를 받습니다. 다른 스냅샷의 기록 해시·개수·식별자는 공개하지 않으며, 이전 원본의 업무 스냅샷을 새 원본의 현행 결과로 표시하지 않습니다.


## 일부만 알려진 수치 속성

검토한 수치 속성은 전체 정밀도와 소수 자릿수 중 알려진 값만 보존하고 나머지는 UNKNOWN으로 둘 수 있습니다. 반올림 방식·단위·통화도 각각 알려진 사실만 유지하며, 누락된 값을 계산기의 기본값이나 값의 모양으로 채우지 않습니다. 두 값이 모두 알려져 있으면 소수 자릿수는 전체 정밀도 이하여야 합니다 (scale <= precision). 이는 지식 표현의 개선입니다. 숫자 값 검증은 그대로이며 소수 계산에는 완전한 정밀도·소수 자릿수·반올림 계약이 필요합니다. 검토 승인과 MCP 전달 성공은 실행이나 업무 의미의 완전성을 입증하지 않습니다.

### 비교 순서와 응답 상태의 유한 계약

`Comparator.comparing`, `comparingInt`, `comparingLong`, `comparingDouble`, 추출자 하나를 받는 대응 `thenComparing*`, `reversed()`는 기존 정적 API 계약 경로를 사용합니다. 키 callback은 직접 선언된 접근 가능한 유일한 소스 인스턴스 메서드로서 인자가 없고 static·제네릭·varargs가 아니어야 하며, 기존에 지원하는 record 접근자도 사용할 수 있습니다. 지원 형식은 비결속 `Type::key`와 입력 타입이 입증된 직접 식 lambda입니다. static·결속 참조, 오버로드 모호성, 상속 getter, 블록 lambda, 입력 타입 미확인과 다른 Comparator 오버로드는 UNKNOWN입니다.

선택적 revision-1 근거 `Method.callbackDeclaration`과 `Type.callbackMemberInventory`는 파싱한 선언을 기존 소유자·digest·범위에 결속합니다. callback 선택 전에 기존 직접 멤버 목록의 완전성과 모든 출력 메서드 레코드가 일치해야 합니다. 근거의 누락·중복·변경·접근 불가는 의존 의미를 철회합니다. callback·매개변수 범위는 디코딩된 Python `str`의 0부터 시작하는 끝 제외 문자 위치이며 UTF-8 바이트나 Java UTF-16 단위가 아닙니다.

primitive 키는 정확한 `int`, `long`, `double` 반환 타입을 요구합니다. 자연 순서 키는 명세로 확인한 정확한 명목 타입 `String`, `BigDecimal`, `Instant`, `Integer`, `Long`, `Double`만 허용하며 소스 재정의·하위 타입·입증되지 않은 제네릭 Comparable 관계는 제외합니다. 자연 순서의 동률은 `equals`가 아니라 `compareTo == 0`입니다. BigDecimal 비교는 scale을 무시하고 Double은 명세의 NaN·부호 있는 0 순서를 유지합니다. 키 우선순위는 유지하며 `reversed()`는 입증된 수신자 키들의 방향만 반전합니다. 이후 추가한 동률 해소 키는 정방향으로 시작합니다. 미확인 연결은 조합을 끊으며 변수·필드 초기화식을 대입하지 않습니다.

Spring `ResponseEntity.badRequest()`와 `notFound()`는 공개 명세 상수 400·404를 보존합니다. `status(int)`와 `status(HttpStatusCode)`는 인자 포인터와 값 UNKNOWN을 유지합니다. 기존 개인정보 처리를 통과한 한정된 정수 AST는 기존 `java_literal_type` int 증거가 정확히 일치할 때만 `status(int)`를 선택합니다. 기존 십진 문자열 wire 값은 그대로 보존하며 상태 metadata에 복사하거나 원문 토큰을 다시 읽지 않습니다. quoted-literal review 문법은 바꾸지 않으며 이 기존 숫자 경로에는 요구하지 않습니다. 마스킹·불투명·크기 초과·범위 초과·long·floating·위조·철회된 증거는 UNKNOWN입니다. 직접 연결된 지원 `build()`는 입증된 상태 관계와 성공 시 본문 없음 계약을 보존하며, 단독 builder에는 상태를 부여하지 않습니다. 실제 `BodyBuilder` 수신자와 `HeadersBuilder` 선언 멤버를 구분하고 한정된 명세상 수신자 bridge로 검증합니다.

Java SE 21과 Spring Framework 6.2.12는 별도의 참고 규격입니다. 실제 대상 버전·컴파일·callback 실행·호출 선택·정렬·HTTP 전달은 UNKNOWN입니다. 상한은 순서 키 16개, 조각당 callback 근거 레코드 16개, callback당 후보 메서드 64개, 추가 메타데이터 32 KiB이며 기존의 더 엄격한 예산도 적용합니다. 미지원·누락 입력은 원래 분모에 남깁니다. 소스 ID·범위·CALLS·기존 API 항목의 정규 바이트는 보존하며, 선택적 근거·계약 필드 추가로 레코드와 sourceSpec digest는 바뀝니다. 기존 enum·record 생성 근거는 별도로 유지합니다.

원시 JSON/MCP, HTML 레코드 상세, 소스 번들 SQLite는 선택적 근거를 보존합니다. 그래프/RDF는 기존 선언 투영을 유지하고 순서·상태·CALLS 간선을 만들지 않습니다. 원시 데이터 판독은 의미 호환성이 아닙니다. 해석에는 revision-1 callback·순서·응답 상태·수신자 bridge 기능 인식과 엄격한 catalog·소스 검증이 필요합니다. 상태 진단은 응답 상태 기능을 공유합니다. 이전·미확인 소비자는 명시적 UNKNOWN·거부 또는 표시된 원시 데이터를 제공해야 하며, 이전 소비자의 수신자 bridge 거부는 해석 호환 성공이 아닙니다. 새 UI·엔진·데이터베이스 스키마를 뜻하지 않습니다.

`capability`: `java-source-key-callback-1`, `java-comparator-ordering-1`, `spring-response-status-1`, `spring-response-receiver-bridge-1`.

명시적 메서드 타입 인자는 기존 입증 타입과 정확히 일치해야 합니다. primitive factory는 `<T>`, 자연순서 `comparing`은 `<T,U>`, 자연순서 `thenComparing`은 `<U>`를 요구합니다. T는 callback 입력 타입, U는 유한 Comparable 키 타입입니다. 개수 오류·미확인·불일치는 외부 계약을 UNKNOWN으로 남기며 독립적으로 입증된 수신자는 보존합니다. primitive 동률 키와 `reversed()`의 명시 인자는 이 한정 범위에서 미지원이며 Java 불법이라는 뜻은 아닙니다. 명시 lambda 매개변수 타입은 타입 이름 공간을 사용하므로 동명 값 매개변수·지역변수·필드만으로 차단하지 않습니다. `Type::method`는 값 이름 충돌 차단을 유지하며 실제 타입 shadow는 여전히 미지원입니다. 생산자와 전달 기록 검증자가 generic solver 없이 같은 구분을 적용합니다.

명시 T/U 검증에는 선택적 Type `callbackTypeNamespace` revision 1도 필요합니다. 실제 선택된 직접 멤버·지역/비멤버·같은 패키지 최상위 타입 이름을 전달된 Type ID, 경로, 소스 digest와 `/sourceRange` 문자 범위에 연결합니다. `complete`는 bool이 아닌 정확한 개수(`detectedDeclarations = len(declarations) + omittedDeclarations`), 누락 0과 기존 완전한 멤버 검사를 요구합니다. 목록 한도는 64이며 기존 의존 ID 62개·둘러싼 범위 16개·계약 32 KiB 한도를 유지합니다. 누락·변조·중복·불완전·제거·예산 초과 증거는 해당 명시 계약만 UNKNOWN으로 남깁니다. 지역 타입의 생존 범위와 호출자/둘러싼 타입의 상속은 이 유한 확장에서 해석하지 않아 UNKNOWN입니다. 동명 값은 타입 위치의 이름을 차단하지 않습니다. 암시 계약과 독립 수신자는 유지합니다. Type payload와 증거 digest는 바뀌지만 source ID·문자 범위·CALLS·기존 catalog entry bytes는 보존합니다. 기존 MCP/SQLite/HTML reader는 선택 필드를 보존하며, 구 소비자의 raw 가독성은 검증된 의미 호환성이 아닙니다.

타입 목록은 양방향으로 검증합니다. 각 항목은 실제 source Type과 연결되고, 독립적으로 알려진 callback owner·호출자·둘러싼 타입·참조 Type은 해당 complete 목록에 반드시 있어야 합니다. 같은 Type이 여러 증거 역할을 맡아 의존 ID가 다른 곳에 남더라도 목록에서 빠질 수 없습니다. `known_types`는 기존 lookup과 일치하는 실제 전달 Type record만 받으며 소비자는 직접 lexical child와 같은 패키지 최상위 Type으로 먼저 걸러 기존 64개 상한을 적용합니다. 개수 일치·ID 합집합·자기 digest는 부재 증명이 아닙니다. 미관측·상한 초과 증거는 명시 의미를 UNKNOWN으로 남깁니다. 내부 일관성 검사는 전체를 함께 위조하는 경우의 신뢰된 source/snapshot provenance를 대체하지 않으며 raw 보존과 의미 승인은 구분합니다.
