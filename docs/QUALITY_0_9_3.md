## Reusable fact-to-policy quality workflow

Create a fact worksheet before prose, with snapshot/evidence IDs and an evidence mapping for every required and already supported fact. Preserve all condition operands, AND/OR grouping, true/false branches, early exits, units, formulas, rounding, exceptions, authority, ownership, identifiers, states, exact time boundaries (`<` versus `<=`) and recovery behavior. Enumerate closed sets; explicitly mark redacted, unsupported and unknown members without guessing their values or treating them as absent. Classify a guard by its actual `controlFlow.kind`: `synchronized`, `try`, `if` and `switch` are not loops; only actual iteration constructs may be called loops.

Keep documentation contracts separate from implementation enforcement, and static observations separate from runtime evidence. Turn the worksheet into prose only after checking each obligation; then map every prose statement back to evidence and every required fact forward to the prose. An extracted worksheet is not a complete policy narrative. HTML may abstract presentation, but it cannot justify dropping required policy meaning. Keep six coverage dimensions separate: file processing, declarations/types, exact calls, policy semantics, MCP delivery and document coverage. Preserve each original denominator, failures, omissions and UNKNOWN rather than combining counts or inventing partial credit.

Prevent regressions by retaining the evidence mapping for supported facts. Validation may be reused only when exact unchanged hashes and the affected scope/reachability are demonstrated, with parent/new consumer pins made explicit; otherwise revalidate the changed scope. Hash equality does not waive privacy, ACL, source-binding or invalidation checks. This generic workflow adds no application-specific answers, runtime claims or broader parser support.

Raw expression lists, opaque guard labels and positional constructor tuples are not automatically human policy meaning. Before prose, join proved declaration/constructor/component/accessor/helper/provider bindings to named parameter and result-field roles, including complete state, effect, prerequisite, authority and exception meaning; undeclared units or effects remain UNKNOWN. Classify each relevant fact as ESSENTIAL → body paragraph, SUPPORTING → machine index, ALREADY_COVERED → a specific paragraph, or UNKNOWN → an explicit reason.
