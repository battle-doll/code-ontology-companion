[English](../PIPELINE_0_9_0.md) | [한국어](../ko/PIPELINE_0_9_0.md) | [日本語](PIPELINE_0_9_0.md) | [简体中文](../zh-CN/PIPELINE_0_9_0.md) | [Русский](../ru/PIPELINE_0_9_0.md)

開発者：**battle-doll（배틀돌）**。AIクライアントにはローカルMCPを提供し、人は生成されたオフラインHTMLを使います。Windows、macOS、Linuxを引き続き対象とします。実際のOSでの結果と実測容量は、単体テストとは分けて報告します。この手順ではプラグインの提出や公開は行いません。

## 現在の公開ソースパイプライン向け表示

公開`analyze`・`refresh`・通常の`pipeline-html`は、領域 → 主要構造モジュール → 概要という有界human表示が既定で、既定2階層・最大3階層です。1画面32ノード・64集計エッジ以内で、5言語UIはローカルscript chunkを共有し、検索は現在の要約ページのみです。全体モードは全範囲の集計rootへ戻り、カメラリセットは範囲を変更しません。ソースポリシーカードは意味UNKNOWNのopaque根拠タイルであり、条件・計算・例外の完全な自然言語説明ではありません。正確で深いデータはMCPに残ります。`--presentation records`・legacy workbench・明示的partitioned record exportは別の対応経路で、すべてのbusiness exportをhuman要約にするものではありません。HTMLの抽象化は回答や政策文書に必要な意味の省略を許しません。プライバシー・ACL・現在のソース結束・無効化検査は必須です。

政策文書の前に[事実worksheetと品質手順](QUALITY_0_9_3.md)を使います。Worksheetの完成は政策prose coverageではなく、各分母を分離します。

## 開始と更新

Python 3.9以降と信頼できるインストール済みバンドルを使います。以下の`COMPANION`は、バンドル内の`skills/manage-code-ontology/scripts/companion.py`を指します。Windowsでは`py -3`を使えます。許可されたソースの外に新しいワークスペースを選びます。HTMLや移行可能な形式へのエクスポート前に、`CODE_ONTOLOGY_PRIVACY_FILE`をソースおよび出力ルートの外にある非公開の個人識別情報拒否プロファイルへ設定してください。このプロファイルを知識成果物へコピーすることはありません。保護が設定されていない場合、エクスポートはエラーになります。

```sh
python3 "$COMPANION" analyze --repo /path/to/source --workspace /path/to/knowledge --authorized --language en
python3 "$COMPANION" refresh --workspace /path/to/knowledge --language en
python3 "$COMPANION" pipeline-status --workspace /path/to/knowledge
```

大量のソースでは`analyze`に`--capacity large`を追加します。上限は250,000ファイル、入力4 GiB、500万レコード、スナップショット出力8 GiB、7,200秒です。既定は25,000ファイル、入力512 MiBです。明示的な予算選択であり、すべての実プロジェクトの処理保証ではありません。HTML・バンドル出力の別枠1 GiB制限は維持します。確定知識だけが必要なら`--no-html`を使います。 ファイルごとのAST上限は既定20,000ノード、`--capacity large`では200,000ノードです。ソースのバイト数、規則IR、深さの制限は維持します。

最初のコマンドは封印された知識を構築し、非公開の所有者アクセス方針を作成し、MCP用にワークスペースを登録して、5言語のHTMLを生成します。`--source-root`は複数回指定できます。`--no-html`は解析のみを行います。`--label`には安全なプロジェクト別名を指定できます。更新では以前のスナップショットを保持し、変更のないファイルの事実を再利用しながらファイル間の解決を再構築します。キャンセルや失敗時は、以前に確定したスナップショットを保持します。`pipeline-recover --workspace /path/to/knowledge`は、検証済みの中断されたローカル実行を再開または完了します。実行中にソースまたはカタログの同一性が変わった場合、新しい世代は確定しません。

新しいパイプラインワークスペースは`pipeline.json`と、変更不可の分割SQLiteスナップショットを使います。既存の`init`/`sync`ワークスペースと大規模プロジェクトカタログは互換性を維持し、暗黙の変換や統合はしません。パイプラインの状態確認はソースファイルを開かずに保存済み成果物を検証し、`freshness=not_checked`を返します。ソースを再検証する操作は更新です。

## 解析対象

| 系統 | 実装された範囲 |
| --- | --- |
| Python | ASTによる宣言、インポート、対応する静的関係、および型付き純粋関数の制限されたポリシー抽出。動的実行は未確認です。 |
| Java、JavaScript/TypeScript、SQL、Vue、XML/MyBatis | 保守的な構文・宣言・インポートと、一部のフレームワークパターン。完全なコンパイラ、SQL方言、プログラム全体の証明ではありません。動的SQLやリフレクションは未解決です。 |
| Kotlin、C#、Go、Rust、C/C++、PHP | 制限付きの宣言・インポート認識。部分的な対応範囲と未解決の意味を明示します。 |
| Swift、Dart、Ruby、Scala | 制限付きの宣言・インポート認識。言語の完全な意味解析やポリシー抽出を意味しません。 |
| Bash/POSIX shell、PowerShell | Bashの関数、source参照、コマンド・パイプライン・制御フローの境界、およびPowerShellの宣言・インポート。スクリプト実行、展開、秘密を含む引数の収集は行いません。引用符やheredocが曖昧な領域は出力から除外します。 |
| LangChain/LangGraph、Kafka、Redis | 一部の宣言されたエージェント・ツール・グラフ、またはメッセージング・キャッシュ関係。環境が不明なリソースは別々に保持します。生のプロンプト、キー、値、認証情報、実行成功は収集しません。 |

各ファイルには、言語、アダプター・ルールのバージョン、ソースダイジェスト、根拠範囲、解析レベル、制限を示します。未対応の構文を解決済み知識へ暗黙に昇格させることはありません。保存された設計にある広範なフレームワークのバックログはロードマップであり、すべてのSDKやバージョンへの対応を主張するものではありません。

エンジンは制限付きのファイルバッチ、単一ライター、ディスク分割を使います。実装されている実行プロファイルは`workers=1`です。エンジンAPIからファイル数・バイト数・記録数の上限を明示的に増やせますが、大きい上限は安全上の制約値であり、実証済みの容量ではありません。グラフクエリはページ分割されます。完全なポリシー評価には別のルール数上限があり、ルール集合を暗黙に切り詰めて計算する代わりに失敗します。

## ポリシー知識とAIの利用

6つのドメイン候補は`product`、`order`、`display`、`claim`、`settlement`、`delivery`です。識別子に基づく分類は候補であり、業務上の所管の承認ではありません。ポリシーは条件、型付き入力、プログラムの順序、ソースの主張、未対応の境界を保持します。対応するPythonの部分集合には、型付きの真偽値・整数・Decimal、代入、早期return、真偽条件、明示的に対応する算術・丸め処理を含みます。JavaとTypeScriptは、型が明示された純粋な真偽条件関数に対応します。数値を扱うポリシー、フレームワークが制御するポリシー、動的にディスパッチされるポリシーは未対応です。未対応の呼び出し、例外、ループを検証済みポリシーにしません。正確な対応範囲は生成されたカバレッジを参照してください。

4つのポリシーMCPツールは`list_domain_policies`、`query_policy_rules`、`compare_policy_cases`、`explain_policy_result`です。さらに`ontology_pipeline_status`、`ontology_pipeline_search`、`ontology_pipeline_modules`、`ontology_pipeline_coverage`があります。完全パッケージには既存の12個を含めて20個の読み取り専用ツールがあります。Skills-onlyにはセットアップ案内とアナライザーを含み、MCPサーバーは含みません。

1. `ontology_list_workspaces`を使い、`pipeline`ワークスペースを選びます。
2. `ontology_pipeline_status`から具体的なスナップショットIDを取得します。
3. 関連するすべての読み取りをそのIDに固定します。`current`や任意のファイルシステムパスはクエリの固定先として受け付けません。
4. ルールを読み、説明や比較のために明示的な型付きコンテキストを指定します。ルールがDecimalを宣言する金額は小数文字列で渡します。

既定の権限ビューは`verified_implemented`です。`AI-proposed`は計算から除外します。`approved_business`には独立した明示的な承認メタデータが必要であり、抽出の成功から推定しません。モデルの同一性と意味の検証は別々です。既定のエンジンはモデルを使わず、`modelNotUsed` / `N/A`になります。クラウドAPI、モデルのインストール、自動的なモデル切り替え、ソース送信は追加しません。

ポリシーへの質問は封印されたポリシースナップショットを使い、コードの再読や稼働中のデータベース・ブローカー・キャッシュへの問い合わせは行いません。適格性、使用回数、設定、時刻の入力が足りない場合は`needs_context`または`UNKNOWN`を保ちます。与えられたサンプル内での最大値は`best_found`です。`proven_maximum`/`proven_minimum`には、完全に対応した範囲、正確なスナップショット・ルール集合の固定、独立して既知の有限入力の網羅が必要です。明示された範囲は、組織内のすべてのポリシーを意味しません。ソースから抽出した挙動は、業務上の承認や現在の適格性の証明ではありません。

ローカルMCPの応答は、ホストからリモートモデルへ転送される場合があります。ローカルソース解析の許可は、その転送の許可ではありません。送信する根拠の選択と承認は別に行ってください。

## 知識へのアクセス

`access.json`は非公開のローカル方針です。初期化では、運用者がバインドした仮名の所有者だけに権限を付与します。信頼できる起動環境で`CODE_ONTOLOGY_PRINCIPAL`を選び、既定値は`local-owner`です。ツール引数から主体や役割を選べません。信頼できる主体のバインドごとに、別々に設定したMCPプロセスを使います。これはローカルプロセス・OSアカウントの境界であり、リモートログインサービスやIDプロバイダーではありません。

権限は`read_structure`、`read_policy`、`read_evidence`、`export_html`、`export_bundle`、`manage_access`であり、特定のスナップショットIDに限定することもできます。不明な主体、欠落または安全でないACL、未対応の操作、スナップショットの不一致は、安全側に倒して拒否します。ポリシーのみのクエリ応答では不透明な根拠IDを保持し、ソースの位置情報は開示しません。その詳細には別の根拠読み取り権限が必要です。従来のワークスペースは引き続きローカル所有者のみが利用できます。権限変更は後続のリクエストで再読し、永続的な許可としてキャッシュしません。

明示的に実行するローカル運用者コマンドで主体の権限を置き換えます。このコマンドはMCPにはありません。

```sh
python3 "$COMPANION" pipeline-access --workspace /path/to/knowledge --principal policy-reader --action read_policy --snapshot SNAPSHOT_ID
```

`--action`を省略すると、その別名の操作権限を取り消します。制限のないアクセス管理者を少なくとも1人残す必要があります。実名やメールアドレスではなく別名を使います。ドメインの推論は認可ラベルではありません。このリリースでは、信頼できる行単位のドメイン分離を主張しません。機密性の境界ごとに、許可された別々のワークスペースを使ってください。

HTMLエクスポートには`export_html`と3つすべての読み取り権限が必要です。移行可能な形式のエクスポートには`export_bundle`と3つすべての読み取り権限が必要です。生成されたHTMLはオフラインのコピーであり、後でACLを変更しても、すでに作られたコピーは回収できません。出力ファイルと受取人は別に管理してください。POSIXの所有者・モードと利用可能なWindowsハンドルのACL検査は、不適合時に拒否します。実際のWindowsでの実行は別途検証が必要です。

## 人向けHTML、系譜、交換形式

**Legacy / 明示的records workbenchの範囲** — 生成されるHTMLは韓国語、英語、日本語、簡体字中国語、ロシア語に対応します。カタログ、モジュール、記録、ポリシー決定は、制限付きのページと正確な根拠アンカーを使います。検索と3Dは表示ページを対象とし、すべての記録へページ移動でアクセスできます。既存の3Dの選択拡大・全体表示、モーション低減、テキストによる移動、モバイルのタッチ領域を維持します。相対リンクは`fetch`や必須のHTTPサーバーなしでオフライン動作します。静的ページは、現在のソースや実行時の挙動を意味しません。

RDF 1.1 Turtleは、[PROV-O](https://www.w3.org/TR/prov-o/)を使って主張と来歴を表現します。[SHACL](https://www.w3.org/TR/shacl/)は必要な形状プロパティを検査するもので、真実性を認証しません。スナップショットのマニフェストは、成果物のチェックサム、解析仕様、カバレッジ、ソース確認時刻を結び付けます。チェックサムは完全性の根拠であり、信頼された署名ではありません。非公開のソースマニフェスト、キャッシュ、アクセス方針、ローカル設定は、移行可能な形式のエクスポートから除外します。移行可能であっても、アップロードの許可にはなりません。

以前の[0.9.0設計基準](NEXT_ARCHITECTURE_0_9_0.md)には、意図したアーキテクチャと受け入れ目標を記録しています。この実装ガイドと生成された検証記録が実際の対応を示し、未測定の性能、実機確認、将来のアダプターは明示的に未確認とします。公式提出、承認、公開は、このローカル手順の対象外です。
