Code Ontology Companion は、ユーザーが権限を有する Java／Spring または Python の
リポジトリを指定し、解析を要求した場合に限り、対応するソースファイルをローカルで処理します。

## データの種類と利用目的

アナライザーは、通常の `.java` および `.py` ファイルを読み取り、以下を導出する場合があります。

- シンボル名、アノテーション名、デコレーター名、および完全修飾名
- 認識された Java ポリシーアクセサーが使用する、検証済みのドット区切りポリシー識別子
- 静的な構造上の関係および言語ラベル
- リポジトリからの相対パス、件数、および解析警告

ソース本文、コメント、任意の文字列リテラル、認証情報、API キー、環境変数、
生のプロンプト、または生のモデル応答を意図的に保持することはありません。
ドット区切りのポリシー識別子は、意味的な `PolicyLeaf` としてのみ保持されます。
その設定値および周囲のソーステキストは、オントロジーには保存されません。

ローカルでの更新と完全性確保のため、プライベートワークスペースには以下が保持されます。

- リポジトリの絶対パス
- ファイルごとの相対パス、サイズ、言語ラベル、および SHA-256 値
- ローカルのスナップショット、ワークスペース、イベント、および任意の Git リビジョン識別子

これらのプライベートフィールドは、権限を有するリポジトリの特定、変更の検出、
スナップショットの完全性維持、およびリネージュの管理にのみ使用されます。
ポータブル RDF、オフライン HTML ワークベンチ、および通常の MCP 結果には、
リポジトリの絶対パスや完全なファイルフィンガープリントは含まれません。

ユーザーが任意のローカル LLM エンリッチメントを一つのワークスペースに対して
明示的に有効化した場合、プライベートなローカル状態にはさらに以下が保持されます。

- 固定されたループバックプロバイダーとエンドポイント、同意バージョンおよびデータスコープの
  バージョン、ならびに選択したモデルの名前、ダイジェスト、形式、サイズ、完了機能
- 既存のオントロジーノード ID を参照する正規化済みのモデル提案、提案されたパイプラインの
  役割、および信頼度
- 推論が行われた正確な実行を特定するために必要な、スナップショット、プロンプトスキーマ、
  入力、およびオントロジーのダイジェスト

これらの提案には `inferred` のラベルが付けられ、いかなる権限も付与されず、
作成専用の個別サイドカーに保存されます。観測済みオントロジー、RDF、リネージュ、
または MCP データに統合されることはありません。生のプロンプトおよび生の応答は保存されません。

シークレットを示唆するファイル名、秘密鍵およびキーストアの拡張子、シンボリックリンク／
リパースポイント、一般的な VCS／依存関係／ビルド／キャッシュ／仮想環境ディレクトリ、
特殊ファイル、ならびに設定された上限を超えるファイルは除外されます。

## ローカルストレージ、保持、および削除

`doctor` および `preflight` はファイルを作成しません。明示的な確認後、初期化により、
対象リポジトリの外部に不変の初期スナップショットを持つローカルワークスペースが書き込まれます。
更新では新しい不変のスナップショットが作成され、以前のスナップショットも保持されます。
リネージュ記録はローカルジャーナルに追記されます。

パブリッシャーがこれらの成果物のコピーを受け取ることはありません。これらは、ユーザーが通常の
ローカルファイル管理ツールを使用して、選択したワークスペースを削除し、必要に応じてローカルの
Companion レジストリからそのエントリを削除するまで保持されます。バージョン 0.4.0 は、
自動保持管理またはクラウドバックアップを提供しません。

## ネットワーク、受領者、および第三者

決定論的アナライザー、ワークスペース CLI、ワークベンチ、ランチャー、および MCP サーバーは、
以下のとおり動作します。

- ネットワークリクエストを行いません。
- テレメトリ、分析データ、Cookie、広告識別子、または IP ログを収集しません。
- 外部 API を呼び出さず、ソースまたはオントロジーデータをパブリッシャーに送信しません。
- パッケージ、モデル、データベース、デーモン、またはバックグラウンドウォッチャーをインストールしません。
- リッスン用ネットワークポートを開きません。

任意の `local_llm.py` ヘルパーは独立した境界です。検出時にはプロセスを実行せず、
接続を確立せず、ファイルを書き込みません。ユーザーがデータ開示を確認し、明示的に同意した後に限り、
このヘルパーは以下を行う場合があります。

- リテラル IPv4 ループバックエンドポイント `127.0.0.1:11434` に接続する
- 既存の Ollama モデルメタデータを検査し、リモート／クラウドのマーカーを報告する応答、
  または必須メタデータを欠く応答を拒否する
- シンボル名、完全修飾名、リポジトリからの相対パス、ノードタイプ、および観測された関係の
  メタデータからなる、上限付きのポータブルなサブセットのみを送信する
- 上限付きの JSON 補完を受信し、正規化された推論出力のみを保持する

このヘルパーは、ソース本文、コメント、任意の文字列、シークレット、認証情報、絶対パス、
プライベートマニフェスト、ソースフィンガープリント、または生のファイルハッシュを送信しません。
任意の URL、LAN／公開ホスト、プロキシ、リダイレクト、または API キーを受け付けず、
モデルのインストールやダウンロード、Ollama サービスの起動も行いません。許可されたエンリッチメントでは、
選択されたモデルが実行され、CPU／GPU メモリが割り当てられる場合があります。また、応答後の即時アンロードを
要求するため `keep_alive=0` を送信します。Ollama として提示されるループバックサービスおよび選択された
モデルは、ユーザーが管理する第三者の受領者です。Companion は、そのサービスを認証することも、
その外部ネットワーク動作や保持を保証または制御することもできません。ユーザーは自身の Ollama 環境を
確認して制限するか、エンリッチメントを無効のままにする必要があります。

`localMetadataVerified=true` は、Ollama の `/api/tags` および `/api/show` 応答によって報告された
フィールドが上限付きの検証に合格したことだけを記録します。モデルの重みバイトを証明するものでも、
ループバックサービスを認証するものでも、推論がローカルで実行されたことや Ollama が外部接続を
行わなかったことを証明するものでもありません。チャット応答内のリモートマーカーは拒否されますが、
その応答が到着するのは、開示済みのメタデータがすでにサービスへ送信された後です。

読み取り専用 MCP サーバーは、ローカルの Codex ホストと stdio を介して通信し、登録済みの
ワークスペース ID のみを受け付けます。ワークスペースを初期化、更新、記録、削除、または
アップロードすることはできません。

Codex がスキルまたは MCP ツールを呼び出す際、シンボル、完全修飾名、件数、警告、
スナップショット ID、相対パスなど、選択されたコマンドまたはツールの出力が、要求された機能を
提供するために OpenAI によって処理される場合があります。OpenAI は別個の受領者であり、
[適用される利用規約](https://openai.com/policies/terms-of-use/)および
[プライバシーポリシー](https://openai.com/policies/privacy-policy/)が適用されます。
オペレーティングシステムおよび Codex ホストには、それぞれの提供者の規約が適用されます。

## ユーザーによる管理

ユーザーは以下を行うことができます。

- 読み取り専用の preflight を確認した後、初期化前に停止する
- Windows、macOS、Linux 上でローカルワークスペースの場所を選択する
- ランタイムのインストールまたは外部転送を拒否する
- コア機能を失うことなく、任意のローカル LLM 検査を拒否する
- 以前の推論サイドカーを保持または手動削除しながら、ワークスペースごとのローカル LLM 設定を
  検査または無効化する
- JSON、Turtle、Markdown、および HTML 成果物を検査する
- フォアグラウンドでの監視をいつでも停止する
- ローカルワークスペースおよびレジストリデータを削除する
- エクスポートをローカルに保持するか、共有を別途許可する
