## 現在の公開ソースパイプライン向け表示

公開`analyze`・`refresh`・通常の`pipeline-html`は、領域 → 主要構造モジュール → 概要という有界human表示が既定で、既定2階層・最大3階層です。1画面32ノード・64集計エッジ以内で、5言語UIはローカルscript chunkを共有し、検索は現在の要約ページのみです。全体モードは全範囲の集計rootへ戻り、カメラリセットは範囲を変更しません。ソースポリシーカードは意味UNKNOWNのopaque根拠タイルであり、条件・計算・例外の完全な自然言語説明ではありません。正確で深いデータはMCPに残ります。`--presentation records`・legacy workbench・明示的partitioned record exportは別の対応経路で、すべてのbusiness exportをhuman要約にするものではありません。HTMLの抽象化は回答や政策文書に必要な意味の省略を許しません。プライバシー・ACL・現在のソース結束・無効化検査は必須です。

## 再利用可能な事実から政策文書への品質手順

Proseの前にsnapshot/根拠IDと、必須および既存対応事実ごとのevidence mappingを持つ事実worksheetを作ります。条件の全オペランド、AND/OR、真偽分岐、早期終了、単位、式、丸め、例外、権限、所有、ID、状態、正確な時間境界（`<`と`<=`）、回復動作を保ちます。閉じた集合を列挙し、秘匿・未対応・不明を明示して値を推測したり欠如と扱ったりしません。Guardは実際の`controlFlow.kind`で分類し、`synchronized`・`try`・`if`・`switch`はloopではなく、実際の反復構文のみloopと呼べます。

文書の契約と実装による強制、静的観測とruntime根拠を分離します。義務を確認してからproseに変換し、各文を根拠へ、各必須事実をproseへ双方向に照合します。抽出worksheet自体は完全な政策文書ではありません。HTMLの抽象化は必須の意味を落とす理由になりません。ファイル処理、宣言/型、exact calls、政策意味、MCP配信、文書coverageの6次元を分け、元の分母・失敗・欠落・UNKNOWNを保ち、合算や恣意的な部分点を作りません。

対応済み事実のevidence mappingを保持して回帰を防ぎます。厳密な同一hashと影響範囲/到達性を実証しparent/new consumer pinsを明示した場合だけ検証を再利用し、それ以外は変更範囲を再検証します。同一hashでもプライバシー・ACL・ソース結束・無効化検査を省略できません。この一般手順は特定アプリの答え、runtime主張、追加parser対応を作りません。

生の式一覧、opaqueなguard名、位置だけのコンストラクタtupleは自動的に人の政策意味にはなりません。Prose前に、証明済みの宣言/constructor/component/accessor/helper/provider bindingを名前付きパラメータ・結果フィールドの役割へ結び、状態・効果・前提・権限・例外の意味を完全に確認します。未宣言の単位・効果はUNKNOWNです。関連事実をESSENTIAL → 本文段落、SUPPORTING → 機械索引、ALREADY_COVERED → 特定段落、UNKNOWN → 明示理由に分類します。AST nodeの羅列で政策説明を置き換えたり、抽象化で必須事実を黙って捨てたりしません。文書意図・静的根拠・runtime強制は別です。

**Legacy / 明示的records workbenchの範囲** — 人向け HTML は `data/` のページ単位の生データを 5 言語で共有します。オフラインのスクリプトが読みやすい JSON 表示と値の検索を提供し、読み込めない場合も静的 JSON リンクで確認できます。全レコード、ソースの固定情報、プライバシー検査、出力上限を維持します。出力フォルダー全体を一緒に保存してください。

深い JSON フィールドは `companion.flat-json.v1` を使用する場合があります。順序付きの `nodes` と `$ref` から `root` を復元し、`originalSha256` と `sourceBinding` を確認してください。ID、根拠、ページ情報は維持されます。これは損失のない転送であり、新しい解析結果や権限ではありません。既存のバイト数、ノード数、深さ、プライバシー制限を維持します。

Java 宣言はジェネリック引数、注釈、throws、ヘッダー・宣言・本体の範囲を保持します。型ごとに原表記、解決された型または null、解決理由を提示します。宣言を一意に特定して静的呼び出しを結んでも、未解決の型情報は残します。曖昧な候補は正確な呼び出しに数えず、静的解決は実行時の実装選択を証明しません。

ポリシー断片は対応する構文の制御文脈と処理順序を保持します。不透明なリテラル、未解決の呼び出し、実行時ディスパッチ、不明な単位は明示します。構文だけでは業務規則の実行可能性、承認、意味の完全性を保証しません。

機密式は `structuralOnly` の呼び出し・参照・代入・制御構造を残し、数値・引用符付きの値・真偽値を `masked_value` に置き換えます。null はソース上の印のみです。入れ子の遅延実行本体にも機密文脈を引き継ぎます。これらは部分表現のままで、値・標準 API・単位・レコード形状の検証を付与しません。マスク値をゼロ、false、空文字列に置き換えたり、内容を推測したりしないでください。

対応する Java ライブラリ演算は、静的な型とオーバーロードの根拠で標準シグネチャを特定した場合だけ `expression.staticContract` を提供します。`contractId` は同じ断片の `standardApiContracts` で参照し、個別照会するレコードではありません。カタログは一次仕様とともに算術・丸め・単位・例外条件を記録しますが、値・実行・動的ディスパッチを証明しません。enum の生成子結合は引数順序と直接のフィールド代入を保持し、曖昧または条件付きの対応は候補に留めます。

選択されたアクセス可能な Java `record` では、受信側、コンポーネントの型、ソース範囲、宣言の証拠を確認できる場合、暗黙の引数なしアクセサーから宣言上の静的戻り値型を結び付けられます。`staticAccessorBinding` はコンポーネントの証拠を保持し、明示された引数なしアクセサー宣言を優先します。コンポーネントやファクトリーの戻り値をたどる際も、呼び出し元のパッケージと最上位型内のアクセス権を確認します。未対応のジェネリック型・ローカル record、アクセスできない型、名前の隠蔽、曖昧な場合は UNKNOWN のままです。この型の連結で正確な `CALLS` 辺を追加せず、値、実行時ディスパッチ、実行成功も証明しません。

固定したスナップショットの MCP ページを最後まで取得してください。バイト上限エラーではページを小さくし、空の成功とは扱いません。失敗 ID を配信の分母に残し、平坦化レコードを復元してから入れ子条件を解釈し、型契約が参照する呼び出し位置の根拠も取得します。この参照集合は全ソース呼び出しの分母ではありません。

参照の欠落を判断する前に、内包された `references[].declarations[]` を確認します。パラメーターの字句的 ID は、個別に照会できるレコードでなくても、ここにソース範囲・型とともに定義されます。それを含む実際の MCP 断片を引用し、定義の欠落と実行時の値が不明なことを区別します。

ソースハッシュ・範囲・受入基準を固定 → 知識生成 → 実際の MCP ページ取得 → オントロジーのみで文書作成 → ソースから独立して導出した基準と比較 → 合成テストで再現 → 製品修正 → 同じ入力で反復します。修正に使用しない検証事例も保持します。

ファイル処理、宣言と型、正確な呼び出し、ポリシー意味、MCP 配信、文書網羅率を分離します。失敗項目を元の分母に残します。部分記述の半点やソース補足の成功加算は行いません。ソース、スナップショット、解析、モデル/プロンプト、文書の変更は再検証が必要です。UNKNOWN/PARTIAL は有効な結果です。

任意の非公開 `companion.reviewed-literals.v1` 契約で、独立に確認した非機密のポリシー値を保持できます。`analyze --literal-review FILE` または `refresh --literal-review FILE` で明示的に選択します。ソースの指紋、ファイルハッシュ、正確な UTF-8 トークンのバイト範囲とハッシュに結び付け、値の一括許可リストは受け付けません。契約は非公開ワークスペースに更新・復旧用として保存します。入力変更時は再審査するか `refresh --clear-literal-review` で解除するまで再利用を拒否します。既存のプライバシー・機密文脈の拒否は維持します。全要求を許可・拒否・未観測として残し、許可だけでは抽出や文書の完全性を示しません。メタデータは信頼する呼び出し元の入力であり、身元証明や公開許可ではありません。解除は以後のスナップショットに適用し、既存のスナップショットやコピーは内容を保持します。

最上位は `format`、`purpose`（`private-policy-analysis`）、`sourceFingerprint`、`review`、`entries` です。`review` は `reviewId`、`reviewerKind`（`independent_source_review`）、`reviewedAt` を保持します。各項目は `path`、`sourceSha256`、`tokenByteStart`、`tokenByteEnd`（終端除外）、`tokenSha256`、`classification`（`nonsecret_policy`）、`reasonCode`、`usageContext`、`reviewId` を記録します。範囲には引用符を含め、理由・文脈コードには原文値を含めません。レビュー使用中は、従来の型付き小数抽出が扱う数値文字列も含め、未レビューの引用符付き値を不透明に保ちます。ファイルは非公開に保管します。CLI はソース文面から許可を推測せず、契約ファイルを自動探索しません。

配列初期化子とアノテーション引数は、ソースの順序・構造と出現位置に結び付いたレビュー証拠を保持します。対象はソース宣言の証拠であり、アノテーションの適用可否、フレームワーク経路、実行時の動作は UNKNOWN です。機密文脈の構造専用断片でも、正確なソースバイト、要求インデックス、プライバシー検査を通過したレビュー済みの長さ0の文字列は空の印として保持できます。他の機密値のマスク、出現位置の分離、取消しは維持します。

ファイル単位の `literalReviewDelivery` は出力断片ツリーの保持状況です。スナップショット要約の `literalReviewRetention` は許可・保持・未保持を分けて集計し、各 `SemanticCoverage` 記録に未保持の要求インデックスを残します。許可、出力保持、MCP配信、方針の意味の完全性は別々に検証します。許可対象が0件なら100%ではなく NOT_APPLICABLE と表示します。

Java ソースコメントには、別の任意の非公開契約 `companion.reviewed-documentation.v1` を使用します。`analyze --documentation-review FILE` または `refresh --documentation-review FILE` で明示的に選択します。既定では、認識したすべての行コメント・ブロックコメント・Javadoc について、本文を含まない不透明な位置・ハッシュ情報を保持します。独立に非機密と確認された正確な出現位置が既存のプライバシープロファイルと組み込み検査を通過した場合だけ、元のトークンを `sourceText` に格納します。原文と書式を正規化した検査用の表現をともに確認し、正規化した表現で出力原文を置き換えません。

文書レビュー manifest の最上位は `format`、`purpose`（`private-policy-analysis`）、`sourceFingerprint`、`review`、`entries` です。`review` は `reviewId`、`reviewerKind`（`independent_source_review`）、`reviewedAt` を含みます。各項目は `path`、`sourceSha256`、`tokenByteStart`、`tokenByteEnd`（終端除外）、`tokenSha256`、`classification`（`nonsecret_documentation`）、`reasonCode`、`usageContext`、`reviewId` を記録します。指紋、ファイルハッシュ、UTF-8 バイト範囲とハッシュは、区切り記号を含む正確なコメントトークン全体に結び付きます。行コメントの改行文字は除外し、部分文字列は受け付けません。manifest に原文や実際の値を入れません。上限は 512 KiB、5,000 項目、コメントトークン当たり 8,192 バイトです。

保持したコメントは信頼しない引用ソースデータであり、`instructionAuthority=none`、`documentation_claim`、`enforcement=UNKNOWN`、`target.resolution=UNKNOWN`、`businessMeaningVerified=false`、実行時 `not_observed` を維持します。コールバックの主張だけで宣言対象を確定しません。コメントの主張はコードの証拠を代替せず、実装による強制や公開権限も証明しません。レビューのメタデータは呼び出し元が提供する出所情報であり、本人確認ではありません。

非公開ワークスペースは更新・復旧用に選択した文書レビュー契約を保持します。入力が変わった場合は一致する新しいレビューを提供するか、`refresh --clear-documentation-review` で解除します。解除は将来のスナップショットだけに影響し、以前のスナップショットと出力コピーは内容を保持します。`DocumentationCoverage` は未レビューのコメント、許可・拒否・未観測の要求、欠落を明示します。認識したトークン一覧の網羅性と `lexicalComplete` は別です。未対応言語、Java Unicode 前処理、未確認の字句境界があればコメント全体の分母は UNKNOWN です。上限による欠落数と理由を残し、一覧を不完全とします。コメントと式の断片は既存のファイル単位の上限を共有し、許可や配信だけではポリシーの完全性を意味しません。

アンダースコアによる強調の境界が曖昧または未対応なら `unsupported_documentation_format` として拒否し、独立レビューでもこの制限を回避しません。

対応する拡張forヘッダーは、反復変数の宣言、反復対象の式、インラインの本体定義を保持します。配列要素の順序、本体の条件、早期終了、累積更新の候補をソースの関係で結びます。実際の走査、反復回数、到達値はUNKNOWNです。未対応のヘッダーと不透明なリテラルも明示します。

`resolution=selected_static_final_field`の場合、`staticFieldBinding`は、一意でアクセス可能な選択ソースのstatic-finalフィールドを宣言・初期化フラグメントに結びます。初期値の代入や実行時初期化の証明は行いません。`recordConstructorDeclarations`は、暗黙のcanonicalコンストラクター引数をrecordの宣言パラメーター位置に対応付けます。明示的・compactコンストラクターでは候補と値の伝達の不明状態を保持し、架空の正確なCALLSや実行時フィールド値を作りません。

文書化された標準オーバーロードには、小数の剰余とナノ秒の減算が含まれます。剰余は負にもなり、常に非負のmoduloとは異なります。MathContextは内部の整数商を制限し、剰余計算自体は正確です。時間契約は単位と例外条件を保持します。数値型だけで業務単位を確定しません。

`source-body:`、`source-binding:`、`source-record-constructor:`は、個別レコードを要求する前に格納フラグメント内の定義を確認します。ループ参照は定義フラグメントと本体位置、コンストラクター参照はローカル宣言カタログを示します。ソースフィールド参照には実在する宣言・初期化フラグメントが必要です。`sourceRange.charStart/charEnd`は0始まりのUnicodeコードポイント範囲で、終端を含みません。レビュー済みリテラル・コメントmanifestのUTF-8バイト範囲とは区別し、両方のsnapshot、ソースハッシュ、参照先定義を検証します。

最終レビューで定義が欠落、不一致、撤回となった場合、それに依存する型・アクセサー・コンストラクター・APIの証拠も撤回します。元の構文と独立した他の証拠は保持します。依存関係の確認が保留された状態では最終snapshotを確定せず、UNKNOWNを確定した主張へ昇格させません。

パイプライン RDF は、カバレッジ・省略・レビュー済み文書を含む意味フラグメントに既存の検索用 `co:Symbol` を維持し、`co:SemanticFragment` と実際の `co:extractorVersion` を追加します。架空の `ruleVersion` で置き換えません。SHACL は意味フラグメントに抽出器バージョンを要求し、通常のシンボル・アサーション・ポリシールールには従来の `ruleVersion` を引き続き要求します。これは限定的なメタデータ投影であり、式の AST やレビュー済みコメント全文を RDF に完全出力するものではありません。形状検証への適合は、完全な JSON/AST 同等性、完全な PROV 意味、ポリシーの完全性、実行時の動作を証明しません。生成だけでは独立 RDF 検証の `not_run` 状態は変わりません。

Java Record シンボルは、コンストラクター呼び出しとは独立して `recordComponents` を提供します。成分の順序・名前・宣言型・解決済み/UNKNOWN 型の組は、親 record ID、パス、ソースハッシュ、文字範囲に結び付きます。`recordHeaderRange` は成分リストの括弧を含み、`recordComponentCoverage` は判明した元の件数、出力、省略、未対応項目を区別します。出力は最大64成分ですが、共有パーサーや既存のフィールド・呼び出し分析は切り詰めません。長すぎるテキストは理由付きで伏せます。未確定型は null/UNKNOWN、不正な構文や不完全な一覧は PARTIAL のままです。アノテーション引数の値は含めません。宣言の観測は格納値、実行、追加の正確な CALLS を証明しません。

`staticFieldBinding` と `receiverStaticFieldBinding` は `resolution` ごとに解釈します。`selected_static_final_field` には、配信されたソースのフィールド宣言と初期化の根拠が必要です。`declared_record_component_field_type` は実際の親 Record とその `recordComponents` 宣言を照合し、初期化やコンストラクター呼び出しの一覧を要求しません。実行時の値は UNKNOWN です。レシーバーの結び付けは呼び出し結果の型ではなく `receiverStaticType` と照合します。未知の resolution は未対応です。競合する明示的 import の成分型は UNKNOWN、void 成分や末尾以外の varargs は観測一覧を減らさず unsupported/PARTIAL として記録します。

Java のブロック内の `var` ローカル変数は、ソースに結び付く式解析ですでに裏付けられた初期化式の静的型だけを引き継げます。`localTypeInference` は宣言・初期化式・字句スコープの範囲をファイルハッシュに結び付け、使用側は `localTypeBinding` で定義を参照します。参照は簡潔に保ち、既存の依存深度制限を守ります。不明、不正な構文、自己参照、複数宣言子、伏せられた値、未対応の初期化式は UNKNOWN です。定義の欠落・撤回時は依存する型/API 証拠も撤回し、元の構文と独立した証拠を保持します。出力された `var` 宣言の集計と元のフラグメント一覧の省略は区別します。値評価、確実な代入、一般的なジェネリック推論、実行を証明するものではありません。

初期化式の型を再利用するには、トークン範囲と Java インデックスで名前付き型とメソッドの所属が一致する必要があります。ローカルクラス、匿名クラス、所属情報の欠落・不一致、未証明の外側フィールド参照は UNKNOWN のままです。最も近いメンバー宣言を確認し、継承メンバーが外側のフィールドを隠す可能性を保持します。所属シンボルの欠落や使用位置の所属変更は依存する根拠を撤回します。既存の未対応文領域は分母に残します。

### 比較順序とレスポンス状態の限定契約

`Comparator.comparing`、`comparingInt`、`comparingLong`、`comparingDouble`、抽出関数を一つ受け取る対応する `thenComparing*`、`reversed()` は既存の静的 API 契約経路を使用します。キー callback には、直接宣言されたアクセス可能で一意な、非 static・非ジェネリック・非 varargs・引数なしのソースメソッド、または既に対応する record アクセサーが必要です。非束縛の `Type::key` と入力型が証明された直接式 lambda に限定します。static・束縛参照、曖昧なオーバーロード、継承 getter、ブロック lambda、不明な入力型、他の Comparator オーバーロードは UNKNOWN です。

任意の revision-1 根拠 `Method.callbackDeclaration` と `Type.callbackMemberInventory` は、解析した宣言を既存の所有者・digest・範囲に結び付けます。callback 選択前に、既存の直接メンバー一覧の完全性と、出力された全メソッドレコードが一致する必要があります。欠落・重複・変更・アクセス不可の根拠は依存する意味を取り消します。callback とパラメーターの範囲は、デコード済み Python `str` のゼロ始まり・終端を含まない文字位置であり、UTF-8 バイトや Java UTF-16 単位ではありません。

primitive キーには正確な `int`、`long`、`double` 戻り値型が必要です。自然順序キーは仕様で確認された正確な名目型 `String`、`BigDecimal`、`Instant`、`Integer`、`Long`、`Double` に限定し、ソースによる再定義・派生型・未証明のジェネリック Comparable 関係は認めません。同順位は `equals` ではなく `compareTo == 0` を意味します。BigDecimal の比較は scale を無視し、Double は仕様の NaN・符号付きゼロの順序を保持します。キーの優先順位は保持し、`reversed()` は証明されたレシーバー内のキーの方向を反転します。後から追加する同順位判定キーは順方向で始まります。不明な接続は合成を中断し、変数・フィールドの初期化式は代入しません。

Spring `ResponseEntity.badRequest()` と `notFound()` は公開仕様定数 400・404 を保持します。`status(int)` と `status(HttpStatusCode)` は引数ポインターと値 UNKNOWN を保持します。既存のプライバシー処理を通った限定的な整数 AST は、既存の `java_literal_type` int 証拠が正確に一致する場合だけ `status(int)` を選択できます。十進文字列の wire 値はそのまま保持し、状態 metadata への複製や生トークンの再読は行いません。quoted-literal review 文法は変更せず、この既存数値経路には要求しません。マスク済み・不透明・サイズ超過・範囲外・long・floating・偽造・失効した証拠は UNKNOWN です。直接接続された対応する `build()` は証明済みの状態関係と、正常構築時に本体がない契約を保持します。単独の builder に状態は付与しません。実際の `BodyBuilder` レシーバーと宣言元 `HeadersBuilder` メンバーは区別し、限定された仕様上のレシーバー bridge で検証します。

Java SE 21 と Spring Framework 6.2.12 は別々の参照仕様です。実際の対象バージョン・コンパイル・callback 実行・呼び出し選択・ソート・HTTP 配信は UNKNOWN です。上限は順序キー 16 個、断片当たり callback 根拠レコード 16 個、callback 当たり候補メソッド 64 個、追加メタデータ 32 KiB で、既存のより厳しい予算も適用します。未対応・省略された入力は元の分母に残します。ソース ID・範囲・CALLS・既存 API 項目の正規バイトを保持し、任意の根拠・契約フィールドの追加によりレコードと sourceSpec の digest は変わります。既存の enum・record 構築の根拠は独立して保持します。

生 JSON/MCP、HTML レコード詳細、ソースバンドル SQLite は任意の根拠を保持します。グラフ/RDF は既存の宣言投影を保ち、順序・状態・CALLS の辺を作りません。生データが読めることは意味の互換性ではありません。解釈には revision-1 の callback・順序・レスポンス状態・レシーバー bridge 機能の認識と、厳密な catalog・ソース検証が必要です。状態診断はレスポンス状態機能を共有します。旧・不明なコンシューマーは明示的な UNKNOWN・拒否、または識別された生データを示す必要があり、旧コンシューマーによる bridge 拒否は解釈上の互換性成功ではありません。新しい UI・エンジン・データベーススキーマを意味しません。

`capability`: `java-source-key-callback-1`, `java-comparator-ordering-1`, `spring-response-status-1`, `spring-response-receiver-bridge-1`.

明示的なメソッド型引数は既存の証明済み型と厳密に一致する必要があります。primitive factory は `<T>`、自然順序の `comparing` は `<T,U>`、自然順序の `thenComparing` は `<U>` を要求します。T は callback 入力型、U は有限 Comparable キー型です。個数の誤り、不明・不一致の引数は外側の契約を UNKNOWN にし、独立したレシーバー証拠は保持します。primitive 同順位キーと `reversed()` の明示引数は本範囲の未対応であり、Java の違法性を意味しません。明示 lambda パラメーター型は型名前空間を使うため、同名の値パラメーター・ローカル変数・フィールドだけでは遮蔽しません。`Type::method` の値名衝突拒否と実際の型 shadow の未対応は維持します。生成側と配信レコード検証側は generic solver なしで同じ区別を適用します。

明示 T/U の検証には任意の Type `callbackTypeNamespace` revision 1 も必要です。選択された直接メンバー型、ローカル/非メンバー型、同一パッケージのトップレベル型名を、配信された Type ID・パス・ソース digest・`/sourceRange` 文字範囲に結びます。`complete` は boolean ではない正確な件数 (`detectedDeclarations = len(declarations) + omittedDeclarations`)、欠落ゼロ、既存の完全なメンバー検査を要求します。リスト上限 64 と既存の依存 ID 62、囲むスコープ 16、契約 32 KiB を維持します。欠落・改変・重複・不完全・削除・予算超過の証拠は該当する明示契約だけを UNKNOWN にします。ローカル型の有効範囲と呼び出し側/外側型の継承はこの有限拡張では解決せず UNKNOWN です。同名の値は型位置の名前を妨げません。暗黙契約と独立レシーバーは保持します。Type payload と証拠 digest は変わりますが、source ID・文字範囲・CALLS・既存 catalog entry bytes は不変です。既存 MCP/SQLite/HTML reader の raw 保持は、旧消費者の意味互換性を証明しません。

型一覧は双方向に検証します。各項目を実際の source Type に結び、独立して既知の callback owner・呼び出し側・外側・参照 Type が関連する complete 一覧に存在することも要求します。同じ Type が複数の証拠役割を持ち、依存 ID が別の場所に残っていても一覧から省略できません。`known_types` は既存 lookup と一致する実際の配信 Type record のみを受け取り、直接 lexical child と同一パッケージのトップレベル型に先に絞って従来の上限 64 を適用します。件数一致、ID の和集合、自己 digest は不在証明ではありません。未観測・予算超過は明示的意味を UNKNOWN にします。内部整合性検査は一括偽造に対する信頼済み source/snapshot provenance を代替せず、raw 保持と意味承認を区別します。
