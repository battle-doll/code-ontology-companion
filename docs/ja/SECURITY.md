## 脆弱性の報告

公開 issue には、非公開ソース、シークレット、認証情報、ローカルの絶対パス、
オントロジー成果物を含めないでください。

次のリポジトリで GitHub の非公開脆弱性報告を使用してください。

https://github.com/battle-doll/code-ontology-companion

非公開報告を利用できない場合は、エクスプロイトの詳細や機密データを含めず、
非公開の連絡手段を求める最小限の公開 issue を作成してください。

## セキュリティモデル

0.8.3 公開候補の決定論的コアと拡張機能は、Windows、macOS、Linux で次のように動作します。上記の公開確認は過去の記録であり、この候補の公開完了を意味しません。

- Java／Spring および Python を静的に解析し、対象コードを import または実行しません。
- リンク／リパースポイントであるリポジトリルートとワークスペースルートを拒否します。
- リンクに似たファイル、特殊ファイル、機密性の高い名前、依存関係、VCS、生成ファイルをスキップします。
- ファイル単位、ソース全体、ソース数、グラフ、影響、HTTP、候補、提案に上限を適用します。
- 既定の 3D 空間マップはグループ・シンボル・関係・深さの上限とフレーム目標を持ち、非表示時にアニメーションを停止します。任意のテキスト表示を備え、CDN、WebGL 依存関係、worker、network primitive を追加しません。
- リンクの選択前に snapshot/entity/relationship/evidence ID の対応を検証し、古い、または無関係な根拠を別の根拠へ置き換えません。
- リポジトリ外に明示的に指定された新しいワークスペース内だけに成果物を作成します。
- 更新をステージング内で構築し、不変スナップショットをアトミックに昇格させます。
- 解析器または Companion のバージョンが変更された場合、リポジトリに変更がなくても更新します。
- 更新に失敗した後も、最終正常スナップショットを保持します。
- 決定論的解析、ワークスペース操作、RDF、リネージュ、HTML ワークベンチ、および MCP は
  ネットワークを使用せず、テレメトリを収集しません。
- Ollama を実行したり、ポートをプローブしたり、書き込みを行ったりせずに、オプションの Ollama を検出します。
- 別個のヘルパーが `127.0.0.1:11434` のみに接続する前に、ワークスペース単位の明示的な同意を要求します。
  報告されたリモート／クラウドのマーカーや必須 API メタデータの欠落を拒否し、
  出力は未検証の作成専用 inferred サイドカーとしてのみ保存します。
- Codex ホストによって有効化された場合、読み取り専用のローカル stdio MCP プロセスを起動します。
- MCP はポートを開かず、ファイルシステムパスではなく登録済みワークスペース ID を受け付け、
  書き込み、更新、インストール、削除、アップロード、実行ツールを公開しません。
- ランタイム、パッケージ、データベース、モデル、デーモン、バックグラウンドウォッチャーをインストールしません。

オプションのヘルパーによって Ollama が信頼済み解析器の一部になることはありません。
Ollama 自体のネットワーク接続、ロギング、モデルの動作、セキュリティは、引き続き
Companion の境界外です。ループバック限定の送信だけでは十分な保証にならない場合は、
エンリッチメントを無効のままにするか、オペレーティングシステムの制御を適用してください。
エンリッチメントは選択したモデルを実行し、CPU／GPU メモリを割り当てる場合があります。
ヘルパーは応答後の即時アンロードを要求するために `keep_alive=0` を送信しますが、
別途管理されているサービスがリソースを解放したことを証明できません。
`localMetadataVerified=true` は Ollama が報告した API メタデータの検証であって、
モデルの重み、ループバックサービスの同一性、ローカル実行、Ollama から外部への通信がないことの証明ではありません。

生成された出力は、自動的に公開して安全なものになるわけではありません。
シンボルと相対パスから、機密アーキテクチャが明らかになる可能性があります。

## 0.8.3 プライバシー制御と公開証拠

設定済みの非公開HMAC-SHA256プロファイルは、公開ソースに実名・個人メール原文を置かず、対応する生成成果物と読み取り結果の指定識別子を拒否できます。キーと指紋を持つプロファイル自体も非公開で、保護ソース・出力ルート外に保存し公開成果物にしません。任意プロファイルがなければ実名保護は確認されません。有限のテキスト・エンコーディング検査は未知の全名前、任意バイナリ・画像情報、第三者出力を網羅せず、POSIX確認はWindows ACLを認証しません。

公開PRの前に実際のGitHubアカウントのメール保護の新しい信頼確認記録と選択したソース・サービス生成commit ref監査が必要です。ローカルgit設定、手動主張、合成テスト、HEADだけの確認では代替できません。保持refの露出はサービスが削除を確認するまで未解決です。公開開発者名がbattle-doll以外の個人情報を示すなら公式アップロード、提出、公開をHOLDします。個人情報送信機能、telemetry、別HTML報告は作りません。

[プライバシー運用](PRIVACY_OPERATIONS.md)を参照します。テスト、サービス確認、アップロード、提出、承認、公開は別証拠です。
