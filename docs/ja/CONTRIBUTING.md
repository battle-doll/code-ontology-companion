# コントリビューション

[English](../../CONTRIBUTING.md) | [한국어](../ko/CONTRIBUTING.md) | [日本語](CONTRIBUTING.md) | [简体中文](../zh-CN/CONTRIBUTING.md)

コントリビューションでは、決定論的、ローカルファースト、最小権限という既定値を維持する必要があります。

## 文書のローカライズ

人が読む文書を変更する場合は、対応する英語、韓国語、日本語、簡体字中国語の文書を
同じ変更の中で更新する必要があります。提出前に
`python3 scripts/validate_documentation.py` を実行してください。
プライバシー、利用規約、商標、notice、第三者通知に関する翻訳は参考情報であり、
英語原文を正規版とする共通マーカーを維持する必要があります。
`LICENSE` または同梱された依存関係のライセンステキストを翻訳または置換しないでください。

変更を提案する前に、次を実行してください。

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate_package.py
```

## バージョンとリリース記録

追跡対象となるすべてのリリース変更には、新しいセマンティックバージョンと
日付付きの `CHANGELOG.md` エントリが必要です。既定ではパッチバージョンを使用し、
機能が拡張される場合はマイナーバージョン、互換性が損なわれる場合はメジャーバージョンを使用してください。
CI はプルリクエストをそのベースブランチと比較し、main ブランチへの push を直前のリビジョンと比較します。
追跡対象の変更は、マニフェストのバージョンがそのベースラインより大きく、
新しい変更履歴エントリが先頭にない限り失敗します。

リリースを公開する前に、次を実施してください。

1. プラグインマニフェスト、ランタイム定数、SBOM、評価メタデータ、リリースバリデーター、
   CI 成果物パス、テスト、現行バージョンの文書に記載されたバージョンを同期します。
2. 最終的なソース状態に対して、完全なテストスイートとパッケージバリデーターを実行します。
3. 2 種類の決定論的リリースプロファイルをそれぞれ 2 回再ビルドして検証し、
   バイト列とチェックサムが一致することを確認します。
4. 最終的にコミットされたソース状態から登録済みの自己オントロジーを更新し、
   宣言されたバージョンポリシーと検証済みリリース証拠のイベントをその系譜に追記します。
5. 最終コミットと必須 CI チェックが完了した後にのみ、リリースタグを作成します。
   公開済みのリリースタグは移動または置換しないでください。

合成フィクスチャだけを使用してください。非公開リポジトリ、第三者のソース抜粋、認証情報、
実プロジェクトのオントロジー成果物、モデルの重み、複製したプロプライエタリスキーマをコミットしないでください。

ネットワークアクセス、対象コードの実行、パッケージのインストール、認証、テレメトリ、
常駐サービス、フック、書き込み可能な MCP、外部データベース、自動モデルダウンロードを追加する変更には、
別途設計を行い、プライバシー、セキュリティ、脅威モデル、テスト、SBOM、提出内容のレビューを更新する必要があります。

コントリビューションを行うことで、その成果物を Apache-2.0 の下でライセンスする権利を
有していることを表明するものとします。
