# コントリビューション

[English](../../CONTRIBUTING.md) | [한국어](../ko/CONTRIBUTING.md) | [日本語](CONTRIBUTING.md) | [简体中文](../zh-CN/CONTRIBUTING.md) | [Русский](../ru/CONTRIBUTING.md)

コントリビューションでは、決定論的、ローカルファースト、最小権限という既定値を維持する必要があります。

## 文書のローカライズ

人が読む文書を変更する場合は、対応する英語、韓国語、日本語、簡体字中国語、ロシア語の文書を
同じ変更の中で更新する必要があります。提出前に
`python3 scripts/validate_documentation.py` を実行してください。
プライバシー、利用規約、商標、notice、第三者通知に関する翻訳は参考情報であり、
英語原文を正規版とする共通マーカーを維持する必要があります。
`LICENSE` または同梱された依存関係のライセンステキストを翻訳または置換しないでください。

変更を提案する前に、次を実行してください。

```bash
python3 -m unittest discover -s tests -v
python3 scripts/validate_package.py
```

## バージョンとリリース記録

追跡対象のリリース変更には、新しい A.B.C 製品バージョンと日付付きの `CHANGELOG.md` 項目が必要です。A は完全に別の製品、B は同じ製品の大規模な変更、C は一部機能の改善・修正を表します。機能追加だけで B を増やす必要はありません。現在は 0.8.x 系列を維持します。CI は PR をベースブランチ、main の push を直前のリビジョンと比較し、候補が正規化された基準バージョンより大きく、日付付きの項目が先頭にあることを求めます。明示的に記録された未公開 0.9.0 候補の基準だけを 0.8.2 と対応させ、任意のバージョン低下は認めません。公開済みタグ、コミットハッシュ、アーカイブ識別子と過去の証拠を保持します。

リリースを公開する前に、次を実施してください。

1. プラグインマニフェスト、ランタイム定数、SBOM、評価メタデータ、リリースバリデーター、
   CI 成果物パス、テスト、現行バージョンの文書に記載されたバージョンを同期します。
2. 最終的なソース状態に対して、完全なテストスイートとパッケージバリデーターを実行します。
3. 2 種類の決定論的リリースプロファイルをそれぞれ 2 回再ビルドして検証し、
   バイト列とチェックサムが一致することを確認します。
4. 最終的にコミットされたソース状態から登録済みの自己オントロジーを更新し、
   宣言されたバージョンポリシーと検証済みリリース証拠のイベントをその系譜に追記します。
5. 最終コミットと必須 CI チェックが完了した後にのみ、リリースタグを作成します。
   公開済みのリリースタグは移動または置換しないでください。

合成フィクスチャだけを使用してください。非公開リポジトリ、第三者のソース抜粋、認証情報、
実プロジェクトのオントロジー成果物、モデルの重み、複製したプロプライエタリスキーマをコミットしないでください。

ネットワークアクセス、対象コードの実行、パッケージのインストール、認証、テレメトリ、
常駐サービス、フック、書き込み可能な MCP、外部データベース、自動モデルダウンロードを追加する変更には、
別途設計を行い、プライバシー、セキュリティ、脅威モデル、テスト、SBOM、提出内容のレビューを更新する必要があります。

コントリビューションを行うことで、その成果物を Apache-2.0 の下でライセンスする権利を
有していることを表明するものとします。

## 0.8.3 プライバシー制御と公開証拠

設定済みの非公開HMAC-SHA256プロファイルは、公開ソースに実名・個人メール原文を置かず、対応する生成成果物と読み取り結果の指定識別子を拒否できます。キーと指紋を持つプロファイル自体も非公開で、保護ソース・出力ルート外に保存し公開成果物にしません。任意プロファイルがなければ実名保護は確認されません。有限のテキスト・エンコーディング検査は未知の全名前、任意バイナリ・画像情報、第三者出力を網羅せず、POSIX確認はWindows ACLを認証しません。

公開PRの前に実際のGitHubアカウントのメール保護の新しい信頼確認記録と選択したソース・サービス生成commit ref監査が必要です。ローカルgit設定、手動主張、合成テスト、HEADだけの確認では代替できません。保持refの露出はサービスが削除を確認するまで未解決です。公開開発者名がbattle-doll以外の個人情報を示すなら公式アップロード、提出、公開をHOLDします。個人情報送信機能、telemetry、別HTML報告は作りません。

[プライバシー運用](PRIVACY_OPERATIONS.md)を参照します。テスト、サービス確認、アップロード、提出、承認、公開は別証拠です。
