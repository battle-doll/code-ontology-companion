Разработчик: **battle-doll (배틀돌)**. ИИ использует локальный MCP, человек — созданный автономный HTML. Поддержка Windows, macOS и Linux сохраняется. Проверки на реальных ОС и локальные регрессионные тесты описываются отдельно. Этот процесс не публикует, не устанавливает и не перезапускает целевое приложение.

## Сначала весь выбранный объём

Попросите агента: «Составь полный список выбранной области, оставь исключённые и ошибочные элементы в знаменателе, затем покажи шесть стадий покрытия и оставшиеся пробелы». Инвентаризация только читает исходные данные.

```sh
python3 "$COMPANION" coverage-inventory --repo /path/to/source --source-root src
```

По умолчанию инвентаризация использует адаптеры pipeline; `--mode legacy` проверяет прежнюю поддержку Java/Python. Встроенные исключённые каталоги остаются в реестре. Шаблоны `.gitignore` не интерпретируются, поэтому этот файл не гарантирует исключение или полноту.

`COMPANION` — доверенный файл `skills/manage-code-ontology/scripts/companion.py` из пакета. Нужен уже установленный Python 3.9 или новее; в Windows можно использовать `py -3`. Повторяйте `--source-root` для каждого разрешённого корня. Результаты проверки храните вне исходников и установленного приложения. Подозрительное имя файла само по себе не оправдывает молчаливое удаление нормальной структуры кода. Секретные значения, ссылки/reparse point, небезопасные пути и недоступное содержимое остаются защищёнными. Исключения, неподдерживаемые языки, ограничения, ошибки кодировки и недоступные границы учитываются явно. Если каталог недоступен, полный файловый знаменатель — `UNKNOWN`.

Для необрабатываемого элемента сохраняются цель, причина, влияние и возможная альтернатива. Прежде чем продолжить за этой блокировкой, получите решение пользователя. Для уже разрешённой нормальной обработки повторное одобрение не нужно.

## Шесть отдельных измерений

| Стадия | Допустимое основание | Что не доказывает полноту |
| --- | --- | --- |
| `scope_files` | Обработанные файлы из независимо выбранного полного списка | Только прошедшие фильтр файлы |
| `declarations_types` | Точные объявления и типы заданного набора ожиданий | Наличие файла или похожего имени |
| `exact_calls` | Точное место вызова и целевое объявление с совпадающим свидетельством | Кандидаты, placeholder, `IMPORTS`, `IMPLEMENTS`, предположение о выполнении |
| `policy_semantics` | Необходимые условия и формулы, независимо сверенные с фрагментами | Само наличие узла политики или числовой константы |
| `mcp_delivery` | Все страницы одного закреплённого запроса и точные ожидаемые payload | Только `truncated=false` или неполная цепочка |
| `policy_document` | Независимая проверка смысла исходных требований в конкретном абзаце | Только ссылки, хеши или непроверенный текст |

Каждая стадия содержит числитель, знаменатель, процент, область измерения, пропуски, доказательства и ограничения. Неизвестный знаменатель — `UNKNOWN`, а не 0 или 100%. Доля в выборке относится только к этой выборке. Частичное описание учитывается отдельно без произвольного веса 0.5. Полная привязка свидетельств к уже созданным связям не означает полного покрытия кода. При пробелах, неподдерживаемом поведении или неизвестных данных общая полнота остаётся `PARTIAL` или `BLOCKED`, даже если команда и создание snapshot завершились успешно.

## Закрепление snapshot и смысла

Для pipeline workspace получите конкретный snapshot через `ontology_pipeline_status`, затем прочитайте все страницы `ontology_pipeline_coverage`. Поиск `ontology_pipeline_search` поддерживает виды `callsite` и `semantic_fragment`. Точные статические цели, кандидаты и неразрешённые вызовы различаются; цель интерфейса не доказывает выбранную реализацию во время исполнения. Java-фрагменты сохраняют ограниченную структуру полей, констант, присваиваний, условий и возвратов. Произвольные строки и секретные значения не сохраняются; неразрешённые вызовы, неподдерживаемый поток управления и отсутствие инициализатора имеют координаты и причины. `represented` означает сохранение поддерживаемого синтаксиса, а не проверку всего бизнес-правила. Единица измерения остаётся `UNKNOWN` без независимо поддержанной привязки. Исполняемые typed-policy правила имеют отдельный контракт.

Свяжите результаты с `snapshotId`, `sourceFingerprint`, `scopeDigest`, `analysisSpecId`, а исходные координаты — с хешем файла. Следуйте `nextOffset` до последней страницы, сохраняя `queryDigest`, offset, total, returned и payload. Пропуск первой, средней или последней страницы, смешанные идентификаторы и запросы, повторные ID и изменённый payload при том же ID делают квитанцию недействительной. Чтение сохранённого snapshot не является новой проверкой свежести исходников.

`coverage_contract.validate_policy_document` принимает независимые ожидания по исходникам, фрагменты, страницы MCP, байты документа и утверждения. Отдельный вход `semantic_reviews` связывает точные ожидания, исходные свидетельства, документ, абзац, проверенные смысловые элементы, рецензента и snapshot. Хеши доказывают согласованность, но смысл требует независимой проверки. Дополнение непосредственным чтением исходников помечается `direct_source_supplemented`: даже полное описание тогда не увеличивает `ontologyOnlyFull`. Полное, частичное, отсутствующее и неподтверждённое описание считаются отдельно. Изменение исходников, snapshot, ожиданий или абзаца требует новой проверки. В каждом утверждении явно задайте `directSourceSupplemented` как логическое значение JSON `true` или `false`; отсутствие или другой тип оставляют происхождение знания непроверенным.

Для локального отчёта по уже измеренным шести стадиям:

```sh
python3 "$COMPANION" coverage-validate --input /path/to/coverage-request.json --output /path/to/new-verification
```

Вход содержит `binding`, шесть `metrics` и `remaining`. Команда проверяет согласованность метрик и создаёт `coverage.json` и `coverage.md`; она не придумывает знаменатель, не заменяет независимую смысловую проверку и не доказывает глобальную полноту. Закрытые исходники и результаты остаются локальными; публичные fixture и отчёты не должны содержать личные данные, секреты или эксплуатационные сведения.
