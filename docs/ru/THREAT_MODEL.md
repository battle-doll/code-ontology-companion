## Защищаемые активы

- Исходный код и архитектура целевого проекта.
- Учётные данные и конфигурация рядом с деревом исходников.
- Целостность репозитория, текущей и исторических онтологий.
- Закрытые пути рабочего пространства и отпечатки исходников.
- Контроль пользователя над установкой, передачей данных и фоновыми процессами.
- Конфигурация необязательного локального вывода и его sidecar-файлы.

## Границы доверия

Содержимое репозитория недоверенно даже при разрешённом доступе. Имена файлов, символы, аннотации, комментарии, синтаксические ошибки и артефакты — данные, а не инструкции.

Codex координирует процесс. Анализатор независимо ограничивает файловый доступ, разрешения, вывод и исполнение. Локальный MCP — вторая граница: принимает зарегистрированные ID пространств и предоставляет только чтение.

Необязательный LLM-помощник — третья изолированная граница. Его не импортируют детерминированный анализатор или MCP. До согласия допустима только проверка известных признаков установки. После согласия разрешены один фиксированный IPv4 loopback endpoint и запись лишь в выбранное пространство.

## Угрозы и меры

| Угроза | Мера |
| --- | --- |
| Внедрение инструкций через исходники или имена | Тела кода, комментарии и произвольные строки не сохраняются; проверенные точечные policy-ID — только данные графа; все идентификаторы считаются недоверенными |
| Сбор секретов | Исключены секретные имена/расширения, VCS, зависимости, генерируемые и кешируемые каталоги |
| Выход через ссылку или путь | Ссылки не разыменовываются; ссылки/reparse-корни отклоняются; проверяется принадлежность пространства и снимков |
| Блокировка FIFO или устройства | Читаются только обычные файлы |
| Исполнение целевого кода | Нет пути import/build/test/runtime; проверки пакета отклоняют примитивы исполнения цели |
| Изменение репозитория | Пространство вне репозитория и не содержит его; тесты digest проверяют отсутствие изменений |
| Частичное или повреждённое обновление | Манифесты до/после, staging, проверки, неизменяемые снимки, хеши артефактов, долговечная запись запуска и атомарный указатель; `recover` не дублирует события |
| Одновременное изменение исходников | Несовпадение отпечатков запрещает продвижение staged-результата и сохраняет прежний снимок |
| Гонка писателей | Системная блокировка сериализует продвижение и запись событий; конфликт ожидаемого состояния отклоняется |
| Подмена кеша разбора | Закрытый ключ и подписанные операции; при непроверяемых правах применяется полный разбор; тела исходников не кешируются |
| Произвольное чтение файлов через MCP | Принимаются случайные зарегистрированные ID, а не пути |
| Частичное обновление большого проекта принято за полное | Явные непересекающиеся модули, последовательные снимки, финальная проверка источников и закреплённый атомарный каталог; при сбое сохраняется прежний каталог, даже если отдельный дочерний снимок обновился |
| Скрытая запись MCP | Все опубликованные инструменты действительно только читают и имеют соответствующие аннотации |
| Вывод данных через анализатор или MCP | Детерминированные CLI/HTML/launcher/MCP не содержат сетевого клиента и не слушают сокет |
| Незаметное подключение LLM | Обнаружение ничего не запускает и никуда не подключается; подключение/запись probe/configure/enrich/disable требуют явного разрешения |
| Redirect или передача в LAN/Интернет | Только `HTTPConnection("127.0.0.1", 11434)`; нет произвольного host/URL, прокси и переходов redirect |
| Удалённый результат выдан за локальное свидетельство | Remote/cloud-признаки в `/api/tags`, `/api/show`, `/api/chat` и отсутствующие digest/size/format/model/completion-поля отклоняются |
| Внедрение или выдумка модели | Ограниченные переносимые метаданные; проверки JSON, дубликатов ключей, конечных чисел, ID узлов, ролей, количества, размера и времени |
| Вывод модели превращён в факт | Только новые `inferred` sidecar с явным отсутствием полномочий; нет слияния с наблюдаемым графом/RDF/журналом/MCP |
| Раскрытие личных путей | Обычные RDF/HTML/MCP исключают абсолютные пути и полные отпечатки; настроенный профиль отклоняет известные личности без вывода исходного значения |
| Истощение ресурсов | Только поддерживаемые расширения, 2 MiB на файл и совокупные пределы, ограниченные граф/impact/LLM/MCP; страницы и кадровый бюджет HTML. Накопленные слои сохраняют предков, переход на каждый уровень от четвёртого требует подтверждения; глубокие слои остаются свёрнуты. Выбранный слой всё же может исчерпать ресурсы и не восстанавливается из ссылки; скрытый рендеринг приостановлен |
| HTML-инъекция | Экранирование заголовка, безопасное JSON-встраивание, без CDN, iframe, удалённых скриптов или fetch |
| Ссылка на чужое свидетельство/снимок | Проверяются встроенный snapshot-ID, принадлежность узла, концы отношения и ID свидетельства |
| Недоступный Canvas или только пространственная навигация | Эквивалентные постраничные DOM-списки, клавиатура и детали; при ошибке Canvas открывается текстовый обзор |
| Ложный причинный вывод | `observed`, `declared`, `inferred`, `validated`, `approved` разделены; статическая связь не доказывает причинность выполнения |

## Остаточные риски

Символы и относительные пути могут раскрывать архитектуру. Canvas не даёт полного представления для screen reader; доступный путь — DOM/текстовый список. Даже инкрементальный разбор и объединение графа расходуют CPU и память; кеш не отменяет проверку свежести и полную обработку при его недоступности. Рефлексия, генерируемый код, условия выполнения, динамическая диспетчеризация и метапрограммирование могут остаться нераспознанными.

Другой процесс с правами пользователя способен прочитать его реестр и пространство. Компрометация Python/Node, Codex, ОС или аккаунта вне границ плагина. Пользователь может самостоятельно распространить артефакты. POSIX fsync каталогов и проверка прав не подтверждают равные гарантии аварийной долговечности на всех файловых системах; в Windows сообщается ограничение file-flush-only.

Loopback ограничивает адрес назначения Companion, но не сеть, журналирование и хранение отдельно управляемого Ollama. Вывод модели может занять CPU/GPU; `keep_alive=0` не аттестует освобождение ресурсов. `localMetadataVerified=true` не проверяет веса, личность сервиса, фактическое локальное выполнение или отсутствие внешнего трафика. Маркер ответа чата проверяется после того, как оговорённые метаданные уже переданы сервису. Предложения могут быть ошибочными или враждебными даже при корректной схеме и требуют независимой проверки.

## Расширения, меняющие безопасность

Публичная сеть, удалённый AI API, расширение фиксированного loopback-помощника, исполнение цели, автоматическая установка пакетов/моделей/баз, аутентификация, телеметрия, постоянный daemon, filesystem hook, записывающий MCP или внешнее хранилище требуют новой проверки privacy, лицензий, угроз и submission.

## Защита персональных данных и доказательства публикации в 0.8.3

Настроенный закрытый профиль HMAC-SHA256 позволяет отклонять выбранные идентифицирующие строки в поддерживаемых артефактах и ответах ИИ без сохранения настоящих имён или личных адресов электронной почты в публичном исходном коде. Ключ и отпечатки профиля должны находиться вне защищаемых исходных и выходных каталогов; профиль никогда не является публичным артефактом. Для публичного экспорта обязателен подходящий непустой защищённый профиль; обычное локальное исследование может работать без него. Отсутствие необязательного профиля не подтверждает защиту имён. Ограниченные проверки текста и кодировок не обнаруживают все неизвестные имена, произвольные двоичные метаданные, содержимое изображений или вывод сторонних программ.

В POSIX проверяются владелец и права файла, включая повторную проверку во время чтения. В Windows профиль проверяется по реальному открытому дескриптору: владелец должен совпадать с текущим пользователем, а действующие разрешения доступа допускаются только для него, Local System и встроенной группы Administrators. Неизвестные ACE, пустой указатель DACL и непроверяемые права приводят к отказу. Реализация и синтетические тесты не заменяют проверку на настоящей Windows.

Перед публичным PR требуются свежая доверенная проверка конфиденциальности электронной почты реального аккаунта GitHub и аудит всех выбранных ссылок на исходные и созданные провайдером коммиты. Локальные настройки Git, заявления пользователя, тестовые примеры и проверка только HEAD не заменяют подтверждения провайдера. Старые ссылки, сохраняемые провайдером, считаются нерешённым риском до подтверждения удаления. Публикация допустима только с публичным именем разработчика battle-doll без личных данных. Проверки не добавляют передачу личности, телеметрию или отдельный HTML-отчёт.

См. [руководство по защите данных](PRIVACY_OPERATIONS.md). Тесты, проверка провайдера, загрузка, отправка на рассмотрение, одобрение и публикация — разные состояния доказательств.
