## Сохранение выбора пользователя

GPT-6 Astra и GPT-6.1 Sol могут получать одни и те же ограниченные доказательства из исходного кода через реально доступные инструменты хоста. Сохраняйте выбранные пользователем модель и уровень рассуждения. Плагин не выбирает модель и не требует конкретной модели, удалённого API или платной учётной записи. Улучшенный поиск не доказывает измеренного преимущества модели; результатов модельного A/B-теста нет.

## Для AI: локальный MCP и закреплённые доказательства

Используйте Windows, macOS или Linux и уже установленный Python 3.9+. Официальный пакет Skills-only содержит анализатор, офлайн HTML и инструкции настройки локального MCP. Для локального stdio-сервера нужен полный пакет той же версии; размещённый в сети сервер не требуется. Меняйте только запрошенную локальную настройку, сохраняйте остальные записи и проверяйте доступность инструментов в новом процессе хоста. Установка файлов сама по себе не делает инструменты доступными.

Сначала проверьте зарегистрированное рабочее пространство и актуальность исходников. Полный пакет содержит одиннадцать инструментов только для чтения: прежние семь для пространств, состояния, поиска, связей, истории, изменений и происхождения, плюс `ontology_large_modules`, `ontology_large_search`, `ontology_large_neighbors`, `ontology_evidence_bundle`. Для обычного пространства закрепляйте связанное чтение за одним снимком и используйте компактный набор доказательств для конкретного вопроса. Для крупного проекта сначала перечислите модули, закрепите каталог, ищите в точных корнях модулей и исследуйте пути внутри одного выбранного модуля. Межмодульные вызовы не разрешаются.

Инициализация и обновление остаются отдельно разрешёнными операциями записи CLI. MCP принимает зарегистрированные ID, а не произвольные пути; он не устанавливает программы, не обновляет данные, не исполняет целевой код и не загружает исходники. Указывайте ограничения страниц и глубины обхода.

## Для людей: офлайн HTML

Откройте `graph.html` локально. Начните с обзора модулей, найдите и выберите символ, затем проверьте исходные позиции и доказательства связей. Структура, влияние и изменения отвечают на разные вопросы. Поиск и текстовые страницы позволяют добраться до свёрнутых и невидимых элементов. Счётчики видимых элементов описывают область отображения, а не всю кодовую базу.

Слои отображения и подсветка вызовов на один, два или три шага независимы. Добавляйте слой за слоем; расширение до четвёртого и более глубокого слоя требует подтверждения. Фокус камеры, масштаб и перемещение Shift-перетаскиванием используются отдельно. Доступны клавиатура, уменьшение движения и текстовый список. Агрегаты и движения камеры не являются новыми доказательствами кода или исполнения.

## Доказательства, конфиденциальность и проверка

Разделяйте исходные связи `observed`, предложения `inferred` и `runtime_unknown`. Указывайте путь, строки и правила, актуальность, охват парсера, неразрешённые цели и усечение. Статический анализ не доказывает успешную работу или прибыльность.

Пользовательские пространства остаются локальными. Публичные пакеты и демонстрации используют только этот открытый проект или синтетические fixture; нельзя публиковать тела исходников, реальные имена, адреса, учётные данные, личные home-пути или материалы частных проектов. Издатель использует только псевдоним battle-doll. Необязательный локальный вывод требует отдельного явного согласия.

Модульные тесты, проверка распакованного пакета, удобство браузера, реальные OS, проверка портала, отправка, одобрение и публикация — разные состояния доказательств. Локальный кандидат не считается опубликованным. Этот основной гид доступен на пяти языках; прежние подробные правовые, защитные и справочные документы доступны на английском, корейском, японском и упрощённом китайском. См. [охват переводов](../TRANSLATION_COVERAGE.md).

## Контракты получения 0.8.0

`ontology_list_workspaces` помечает крупное родительское пространство как `mode: "large"`. `ontology_large_modules` использует зарегистрированный `workspace_id`, необязательный `catalog_snapshot_id`, запрос и параметры страницы. `ontology_large_search` требует точные `module_roots` и `term`, а `ontology_large_neighbors` — один `module_root` и `symbol`; пути остаются внутри одного модуля. Проверяйте реально доступную схему входа.

`ontology_evidence_bundle` работает только с обычным пространством: `workspace_id`, необязательный `snapshot_id` и 1–8 `requests`. Каждый запрос имеет уникальный `id`, `operation: "search"` или `"neighbors"` и параметры этой операции. Снимок закрепляется один раз в начале; элементы имеют `ok/error`, общий результат — `ok/partial`. Общий предел — 200 результатов и 262144 UTF-8 byte канонического структурированного JSON; слишком большой элемент становится безопасной ошибкой. Дублированный протокольный текст иwire byte не входят в этот предел. Не считайте неудачный элемент успешным ответом и не смешивайте ID каталога с ID обычного снимка.

## Измеренные ограничения пакетного запроса

Синтетический пример на Mac (1 002 узла, 2 000 связей, 20 локальных измерений) сохранил результаты восьми поисков и сократил число запросов MCP с 8 до 1. Число чтений онтологии осталось равным 8. Структурированный ответ вырос с 32 380 до 33 108 bytes, локальная медиана p50 — с 14.073 до 16.066 ms. Это проверка координации запросов и согласованности снимка, а не доказательство ускорения вычислений сервера, повышения качества модели или производительности на других ОС.
