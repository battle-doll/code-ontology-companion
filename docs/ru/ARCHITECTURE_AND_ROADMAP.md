# Архитектура Code Ontology Companion

> В 0.9.0 добавлены дисковые разделы, запечатанные правила и доступ только владельцу по умолчанию. Полный пакет 0.9.2 содержит **20 MCP-инструментов только для чтения (12 прежних + 8 новых)**. Ниже описана прежняя совместимость, если явно не названа команда конвейера. Для новых многоязычных пространств и правил используйте руководство реализации. [0.9.0](https://github.com/battle-doll/code-ontology-companion/blob/main/docs/ru/PIPELINE_0_9_0.md)

[English](../ARCHITECTURE_AND_ROADMAP.md) | [한국어](../ko/ARCHITECTURE_AND_ROADMAP.md) | [日本語](../ja/ARCHITECTURE_AND_ROADMAP.md) | [简体中文](../zh-CN/ARCHITECTURE_AND_ROADMAP.md) | [Русский](ARCHITECTURE_AND_ROADMAP.md)

Документ описывает кандидат 0.9.0; публикация — отдельное решение. Плагин преобразует разрешённый Java/Spring или Python-репозиторий в неизменяемые локальные снимки онтологии без импорта, сборки, тестирования или исполнения целевого кода. Детерминированный анализатор и читающий MCP не делают прямых сетевых запросов. Поддерживаются Python 3.9+, Windows, macOS и Linux. Заявленная поддержка не равна подтверждённой проверке конкретного кандидата на каждой ОС.

## 1. Компоненты

| Компонент | Поддерживаемая обязанность |
| --- | --- |
| `apply-code-ontology`, `apply_workflow.py` | Маршрутизация текущего разговора, реальный первый запрос, чтения одного снимка, разрешённые checkpoints поддерживаемых изменений без постоянного activation-state |
| `manage-code-ontology` | Разрешения, preflight, жизненный цикл пространства, запросы/свидетельства, локальный MCP и согласие для необязательного LLM |
| `code_ontology_core.py` | Детерминированный статический Java/Spring и Python, свидетельства отношений, покрытие адаптеров, ограниченные JSON/RDF/отчёт/HTML |
| `parse_cache.py` | Закрытый подписанный кеш операций разбора; повторное объединение графа после изменения файла; безопасный полный разбор при недоступности кеша |
| `companion.py` | Читающие проверки, неизменяемые снимки, обновление/восстановление, query, impact, history, diff и происхождение |
| `privacy_guard.py` | Ограниченная проверка текста и кодировок, известные личности через закрытый HMAC-профиль, проверка прав файла |
| `mcp/server.py` | 12 читающих инструментов зарегистрированных пространств через локальный stdio |
| `local_llm.py` | Отдельно разрешённое обогащение метаданных Ollama по фиксированному loopback; непроверенные inferred-sidecar |
| Автономный HTML | Поиск полного индекса, 3D-карта, Structure/Impact/Changes, независимый текстовый список, свидетельства, сравнение до/после и пять языков |

Рантайм использует стандартную библиотеку Python и автономный HTML. Трёхмерная проекция рисуется встроенным Canvas2D; новая библиотека или WebGL не нужны. Нет CDN, установки пакетов, worker, телеметрии или сетевого сервиса.

Применение различает установленные файлы, обнаруженный skill, доступный MCP и проверенный CLI. Наблюдаемый план хоста не является доказательством исполнения. Помощник выполняет Code CLI-чтения и разрешённый sync; другие продукты не наследуют полномочия Code. Context нуждается в выбранных подтверждённых записях и read-back; Contracts — в реальном выбранном артефакте. Неподдерживаемые языки и незавершённые передачи явно отмечаются.

## 2. Поток данных

```text
разрешённый репозиторий
  -> защищённое обнаружение источников и выбранная область
  -> закрытый стабильный манифест файлов
  -> детерминированный разбор / проверенный кеш изменённых файлов
  -> типизированный граф, правила, ограничения и исходные свидетельства
  -> проверки JSON / RDF Turtle / privacy / HTML
  -> полный неизменяемый снимок и хеши артефактов
  -> долговечная закрытая запись запуска
  -> журнал / Turtle / атомарный указатель текущего снимка
  -> CLI и MCP закреплённых свидетельств; HTML для человека
  -> необязательный отдельно согласованный Ollama inferred-sidecar
```

`doctor` и `preflight` только читают. `init` требует разрешения и нового пространства вне цели. `sync` работает через staging, продвигая только полный стабильный снимок. Изменение источников или ошибка проверки сохраняет прежний снимок. Если сбой случился после записи подготовленной транзакции, `doctor --workspace` показывает необходимость восстановления; `recover` проверяет хеши/ожидаемое состояние и завершает запись без повторного анализа и дублирования событий. Противоречащее текущее состояние не откатывается. На POSIX метаданные каталогов синхронизируются fsync; для Windows заявляется лишь file-flush-only, без недоказанной эквивалентности при отключении питания.

## 3. Статический анализ

### Java и Spring

Извлекаются пакеты, импорты, классы, интерфейсы, records, методы, конструкторы, поля, наследование, аннотации, вызовы и основные зависимости. Распознаются распространённые Spring stereotypes, `@Bean`, constructor/field injection, AspectJ advice и признаки transaction/async/cache/authorization/retry proxy. Проверенные точечные policy-accessor ID связываются с охраняемыми ветвями без сохранения окружающих строк.

Разрешение Java-вызовов консервативно: неквалифицированный вызов или `this.method(...)` связывается с методом того же владельца, только если имя и количество аргументов дают единственного кандидата. Распознанный импортированный `Type.method(...)` создаёт `ExternalCallable`. Перегрузки той же арности, динамические receiver, декларации, конструкторы, аннотации, управляющие слова, комментарии и литералы не порождают вымышленных вызовов.

### Python

Извлекаются модули, импорты, классы, функции/async, декораторы, вызовы и наследование. Поддерживаются распространённые alias, относительные импорты, лексические области, вложенные функции, явные `self`/`cls` и `src/` layout. Детерминированные эвристики отмечают роли Extract, Transform, Load, Validate, Orchestrate.

### Ресурсы и файловые границы

Читаются только обычные `.java`/`.py` в установленных пределах размера, числа и графа. Исключены секретные имена, env, приватные ключи, ссылки/reparse, специальные файлы, зависимости, VCS, генерируемые результаты, IDE, кеши и виртуальные среды. Проверки границ репозитория, пространства, staging и снимков закрываются при ошибке.

### Свидетельства отношений и покрытие

Сохранены прежние тройки `source`, `target`, `type` и стабильные ID. Каждый элемент `evidence` включает `rule_id`; качественный `basis` (`direct_syntax`, `resolved_static`, `framework_semantic`, `name_heuristic`); `runtime_status` (`not_applicable` либо `runtime_unknown`); необязательные относительные `path`, `line_start`, `line_end`; ограниченный список `limitations`.

Контракт `document.quality` версии `1.0` содержит `relationship_evidence`: `total_edges`, `documented_edges`, `missing_evidence`, `coverage_percent`, `basis_counts`, `runtime_status_counts`. Матрица `adapters` сообщает для Java/Python `status`, `capabilities`, `unsupported_runtime`, `detected`; оба продуктовых адаптера описаны даже при одном языке в снимке. `interpretation` удерживает статическую границу. Basis не является вероятностью, а ноль предупреждений — доказательством полноты.

## 4. Снимки, происхождение и HTML

Снимок содержит `ontology.json` для запросов; `ontology.ttl` для RDF 1.1; `report.md`; автономный `graph.html`; метаданные/счётчики `snapshot.json`; закрытый `source-manifest.json`; публичный `artifact-manifest.json` с хешами результатов. Закрытые `.transactions/<runId>.json` и кеш не входят в публичный манифест.

Пространство хранит логически дополняемый `lineage.jsonl` и переносимый `lineage.ttl`. Запись журнала атомарна; повторное восстановление того же `runId` не добавляет копию события. Классы `observed`, `declared`, `inferred`, `validated`, `approved` различаются. Стабильный `co:`-словарь и ограниченное PROV-O-представление совместимы с импортом Turtle в RDF 1.1-хранилища; собственные индексы/правила хранилища задают отдельно. Сохраняются прежние прямые тройки, дополнительные `RelationshipEvidence` описывают правило, основание, строки, runtime и ограничения. Независимые RDF/SHACL проверки структуры не подтверждают истинность исходного анализа или полное соответствие PROV.

### Пространственная карта

Основной HTML предлагает Structure, Impact и Changes. Начальный уровень группирует пакеты/модули, далее раскрывается выбранный модуль и его классы/отдельные функции, затем выбранный компонент и методы/policy-контекст. Остальные области свёрнуты. Группы сохраняют число и исходные свидетельства канонических связей, но не становятся новыми узлами онтологии. Явные страницы и раскрытие обеспечивают доступ ко всему индексу с различением показанного, свёрнутого и вне страницы.

Подсветка вызовов независима: один, два или три направленных шага `CALLS` прослеживаются до проекции на группы. Это не имитация выполнения; пространственные кольца — оформление, не отношения. При отказе Canvas открывается текстовый список. Плоский 2D-режим и его библиотеки удалены; текстовый обзор показывает полный состав связей через ограниченные страницы.

Есть видимые/клавиатурные поиск, выбор, zoom, reset и история. Deep-link проверяет снимок/узел/отношение/evidence-ID; несовпадающие или чужие свидетельства отклоняются. Impact повторяет whitelist зависимостей и исключение общих концептов CLI и показывает статические кандидаты, не последствия runtime. Changes использует общий канонический diff, включая изменения свидетельств, и свойства до/после. Пять языков интерфейса и самостоятельный список сохраняют общий выбор и фильтры с картой.

Карта учитывает reduced motion и forced colors, сообщает статус выбора и останавливает анимацию в скрытой вкладке. Есть бюджеты узлов/рёбер/кадра и снижение частоты при превышении цели. Накопленные слои могут показывать всё до выбранной глубины, но каждый подъём от четвёртого уровня требует подтверждения; более глубокие отношения остаются свёрнутыми. Статические и функциональные тесты не доказывают визуальное качество, поведение assistive technology или WCAG — необходима отдельная браузерная/AT-проверка.

## 5. Локальный MCP

Stdio-сервер не слушает порт и принимает зарегистрированный `workspace_id`, а не произвольный путь. 12 инструментов перечислены в [настройке MCP](references/local-mcp.md). Прежние search/neighbors/history/changes/lineage и большие модульные запросы совместимы. `ontology_evidence_bundle` сохраняет прежний контракт; новый `ontology_evidence_pack` разделяет общие метаданные, устраняет повторение свидетельств, выбирает поля и возвращает закреплённое продолжение в ограничении полного wire-ответа.

У всех инструментов `readOnlyHint=true`, `openWorldHint=false`, `destructiveHint=false`, `idempotentHint=true`. Init, sync, recover, запись происхождения, удаление, загрузка, установка и исполнение цели — явные CLI-операции. Полный пакет содержит сервер/launcher; прямой Python stdio поддерживает Windows (`py -3`), macOS/Linux (`python3`).

## 6. Необязательное Ollama-обогащение

Анализ полноценен без модели. Detection ничего не исполняет, не подключает и не пишет. Сначала проверяется уже сохранённая настройка пространства. До consent раскрываются `127.0.0.1:11434`, переносимые метаданные, ресурсы, хранение и остаточные риски, затем возможны проверка существующих моделей и выбор подходящей completion-модели.

Передаются ограниченные node-ID, имена/типы, квалифицированные имена, относительные пути, аннотации и наблюдаемые связи. Тела кода, комментарии, произвольные строки, секреты, абсолютные пути, манифесты и сырые хеши исключены. Стабильные batch-запросы — до 20 кандидатов и 16 KiB; `think=false`, `num_ctx=8192`, `num_predict=2048`, таймаут до 180 секунд. Все ответы проходят строгую JSON-схему до создания одного нового inferred-sidecar. Сырые промпты/ответы не хранятся; наблюдаемые граф и RDF не меняются.

## 7. Конфиденциальность и пределы доказательств

Переносимый вывод и обычный MCP не показывают абсолютный путь и полные отпечатки. Закрытая конфигурация хранит путь; закрытый манифест — относительные пути, размеры, SHA-256 для свежести/целостности. Имена и относительные пути всё ещё конфиденциальны и остаются локальными без отдельного разрешения на передачу. Известные личности защищает настроенный HMAC-профиль; это не универсальное обнаружение неизвестных персональных данных.

Статические связи не доказывают выполнение, активную конфигурацию фреймворка, безопасность, корректность или причинность. Рефлексия, генерируемый код, bean-условия, динамические proxy, версии зависимостей, внешние настройки, динамические импорты и метапрограммирование требуют независимых runtime-свидетельств.

## 8. Распространение и проверки

Два детерминированных архива: полный ZIP со skills, сервером/launcher, политиками, reviewer-cases и историей; официальный Skills-only ZIP с workflow, анализатором, HTML, LLM-помощником и инструкцией MCP, без сервера. Каждый собирается дважды с побайтным сравнением. Перед выпуском выполняются проверки исходников, структуры/сумм ZIP, безопасный extracted smoke, документации, компиляции Python и unit-suite. CI предусматривает Python 3.9/3.12 на Ubuntu/macOS/Windows; факт конкретного выполнения сообщается отдельно.

Контракт версий охватывает `.codex-plugin/plugin.json`, константы, MCP/eval-метаданные, `CHANGELOG.md`, SBOM, имена артефактов, валидаторы и CI-пути. Golden/forbidden-gates проверяют ожидаемые/запрещённые узлы, связи, свидетельства, coverage и детерминизм без запуска цели. HTML-gate проверяет автономность, 3D/текст, конечные бюджеты и координаты, детерминированное позиционирование, motion/hidden, клавиатуру/указатель, high contrast, legacy и безопасный fallback. Его `validation_scope=static_contract`, `requires_browser_qa=true`; он не заменяет визуальный просмотр. Тесты восстановления, равенства полного/инкрементального анализа и бюджетов MCP проверяют свои узкие контракты, не производительность модели или публикацию.

## 9. План развития

Исторические версии 0.5.x добавили качество свидетельств, ограниченное покрытие адаптеров, консервативное разрешение Java-вызовов, golden/forbidden-gates и локальную пространственную визуализацию. Позднее появились основной 3D-атлас, Structure/Impact/Changes, глубины и подсветка, полные страницы, постоянный source scope, отказ при конфликте деклараций и точные ссылки на свидетельства.

Кандидат 0.9.0 добавляет проверяемое восстановление, раздельные манифесты, компактную передачу свидетельств, инкрементальный разбор файлов, усиленные проверки RDF/графа и приватного профиля, человеческое сравнение до/после и пять языков подробной документации/интерфейса.

Дальнейшие направления, без обещания сроков: улучшение диагностики и progress; foreground watcher/debounce/single-flight; новые парсеры только с достаточными fixtures и privacy; необязательные RDF store/SPARQL/большие графы без обязательной базы и ослабления снимков; отдельно ограниченные build/config/authenticated read-only runtime-адаптеры без превращения статического свидетельства в runtime-факт.

JS/TS-анализ, межмодульный call graph, исполнение цели, live tracing, автономные изменения/развёртывание, security-вердикты и продвижение inference в observed не входят в 0.9.0. Нет встроенной graph database, SPARQL/REST-профиля, live-layout сервиса или неограниченного одновременного отображения всех исходных символов.

## Создаваемый HTML для людей в 0.9.0

Создаваемый автономный HTML начинает работу в **режиме фокуса**; отдельно доступен **полный режим**. Первый уровень фокуса показывает входы в модули. Выберите элемент на карте или в списке и войдите в него, чтобы увидеть только объявленные им дочерние элементы, вплоть до уровня 4. Кнопки пути возвращают к родителю. Одна страница карты выбранной области содержит не более **60 узлов и 160 отображаемых рёбер** и на мобильном, и на настольном устройстве; остальные элементы и связи доступны через явные страницы и текстовый список. Это пределы отображения, а не анализа исходников. Прежний полный/накопительный обзор сохраняет свои пределы и подтверждение перехода на уровень 4 и глубже.

Режим фокуса размещает и анимирует только ограниченный граф выбранной области, но всё ещё разбирает весь встроенный набор данных и строит иерархию. Это не полная отложенная загрузка репозиториев произвольного размера. Настройка уменьшения движения подавляет анимацию входа; навигация отменяет устаревшее движение. Карта сохраняет статические свидетельства исходников и не подтверждает поведение при исполнении. Локальные тесты DOM, геометрии и модульные тесты не доказывают удобство на реальном устройстве или измеренное ускорение. Сохраняются локальный MCP, пять языков UI/документации и поддержка Windows, macOS и Linux.
