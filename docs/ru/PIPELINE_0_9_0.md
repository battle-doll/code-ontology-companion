# Локальный конвейер онтологии 0.9.0

[English](../PIPELINE_0_9_0.md) | [한국어](../ko/PIPELINE_0_9_0.md) | [日本語](../ja/PIPELINE_0_9_0.md) | [简体中文](../zh-CN/PIPELINE_0_9_0.md) | [Русский](PIPELINE_0_9_0.md)

Разработчик: **battle-doll (배틀돌)**. Локальный MCP обслуживает ИИ-клиенты; люди используют созданный автономный HTML. Целевыми системами остаются Windows, macOS и Linux. Результаты на реальных операционных системах и измеренная ёмкость сообщаются отдельно от модульных тестов. Этот процесс не отправляет и не публикует плагин.

**0.9.1 HTML** — Создаваемый HTML снова открывается в анимированном 3D-интерфейсе. Кнопка «Все записи» открывает каталог и правила; карта сохраняет ограниченные страницы, общий/фокусный режимы и настройку уменьшения движения.

## Запуск и обновление

Используйте Python 3.9 или новее и доверенный установленный пакет. Ниже `COMPANION` обозначает его файл `skills/manage-code-ontology/scripts/companion.py`; в Windows можно использовать `py -3`. Выберите новую рабочую область вне разрешённого исходного кода. Перед экспортом HTML или переносимого пакета задайте `CODE_ONTOLOGY_PRIVACY_FILE`, указав частный профиль запрета персональных идентификаторов вне корневых каталогов исходного кода и результатов. Профиль никогда не копируется в артефакты знаний. Отсутствие защиты является ошибкой экспорта.

```sh
python3 "$COMPANION" analyze --repo /path/to/source --workspace /path/to/knowledge --authorized --language en
python3 "$COMPANION" refresh --workspace /path/to/knowledge --language en
python3 "$COMPANION" pipeline-status --workspace /path/to/knowledge
```

Для большого набора добавьте к `analyze` параметр `--capacity large`: пределы составят 250 000 файлов, 4 GiB входа, 5 миллионов записей, 8 GiB снимка и 7 200 секунд. По умолчанию — 25 000 файлов и 512 MiB входа. Это явный выбор бюджета, а не гарантия для любого реального проекта. Отдельный предел HTML и переносимого экспорта остаётся 1 GiB; для одних запечатанных знаний используйте `--no-html`. Предел AST на файл — 20 000 узлов по умолчанию и 200 000 с `--capacity large`; ограничения байтов исходника, IR правил и глубины сохраняются.

Первая команда строит запечатанные знания, создаёт частную политику доступа владельца, регистрирует рабочую область для MCP и генерирует HTML на пяти языках. Параметр `--source-root` можно повторять. `--no-html` выполняет только анализ. `--label` принимает безопасный псевдоним проекта. Обновление сохраняет старые снимки и повторно использует факты неизменённых файлов, заново разрешая межфайловые связи. Отмена или ошибка сохраняет предыдущий опубликованный снимок; `pipeline-recover --workspace /path/to/knowledge` возобновляет или завершает проверенный прерванный локальный запуск. Новое поколение не публикуется, если во время запуска изменились идентичность исходного кода или каталога.

Новые рабочие области конвейера используют `pipeline.json` и неизменяемые секционированные снимки SQLite. Существующие рабочие области `init`/`sync` и каталоги крупных проектов остаются совместимыми; они не преобразуются и не объединяются без явного действия. Проверка состояния конвейера проверяет сохранённые артефакты, не открывая исходные файлы, и сообщает `freshness=not_checked`. Повторную проверку исходного кода выполняет обновление.

Для каждого файла указываются язык, версия адаптера и правил, дайджест исходного кода, диапазон основания, уровень анализа и ограничения. Неподдерживаемая конструкция никогда не становится разрешённым знанием без явного подтверждения. Более широкий список будущих фреймворков в архивном проекте остаётся дорожной картой, а не заявлением о поддержке всех SDK или версий.

Движок использует ограниченные партии файлов, одного писателя и дисковые секции. Реализованный профиль выполнения — `workers=1`. Через API движка можно явно увеличить бюджеты файлов, байтов и записей; большие лимиты являются защитными пределами, а не доказанной ёмкостью. Запросы графа разбиты на страницы. Полная оценка политик имеет отдельный бюджет правил и завершается ошибкой вместо вычисления по незаметно усечённому набору.

## Знания о политиках и использование ИИ

Шесть кандидатов доменов: `product`, `order`, `display`, `claim`, `settlement` и `delivery`. Классификация по идентификаторам является кандидатом, а не утверждением бизнес-принадлежности. Политики сохраняют условия, типизированные входы, порядок программы, исходные утверждения и неподдерживаемые границы. Поддерживаемое подмножество Python включает типизированные логические значения, целые числа и Decimal, присваивания, ранние возвраты, логические условия и явно поддерживаемую арифметику и округление. Java и TypeScript поддерживают чистые функции логических условий с явными типами; числовые политики, политики под управлением фреймворков и политики с динамической диспетчеризацией пока не поддерживаются. Неподдерживаемые вызовы, исключения и циклы не становятся проверенными политиками. Точное поддерживаемое подмножество указано в сформированном отчёте об охвате.

Четыре инструмента MCP для политик — `list_domain_policies`, `query_policy_rules`, `compare_policy_cases` и `explain_policy_result`. Ещё три инструмента — `ontology_pipeline_status`, `ontology_pipeline_search` и `ontology_pipeline_modules`. Полный пакет содержит 19 инструментов только для чтения, включая 12 существующих. Skills-only содержит инструкции по настройке и анализатор, но не сервер MCP.

1. Используйте `ontology_list_workspaces` и выберите рабочую область `pipeline`.
2. Получите конкретный ID снимка через `ontology_pipeline_status`.
3. Зафиксируйте этот ID во всех связанных чтениях. `current` и произвольные пути файловой системы не принимаются как фиксированные идентификаторы запросов.
4. Прочитайте правило, затем передайте явный типизированный контекст для объяснения или сравнения. Суммы передаются десятичными строками, если правило объявляет Decimal.

Представление полномочий по умолчанию — `verified_implemented`. `AI-proposed` исключается из вычислений. `approved_business` требует независимых явных метаданных одобрения и никогда не выводится из успешного извлечения. Идентичность модели и семантическая проверка — разные вещи. По умолчанию движок не использует модель: `modelNotUsed` / `N/A`. Облачный API, установка моделей, автоматическая смена модели и передача исходного кода не добавляются.

Вопросы о политиках используют запечатанный снимок политик; они не перечитывают код и не обращаются к действующим базам данных, брокерам или кэшам. Отсутствующие данные об условиях участия, количестве использований, конфигурации или времени остаются `needs_context` либо `UNKNOWN`. Максимум среди предоставленных примеров обозначается `best_found`. `proven_maximum`/`proven_minimum` требует полного поддерживаемого охвата, точной фиксации снимка и набора правил и исчерпывающего перебора независимо известных конечных входов; заявленная область никогда не означает все политики организации. Извлечённое из кода поведение не является бизнес-одобрением или доказательством текущего права на применение.

Хост может пересылать ответы локального MCP удалённой модели. Разрешение локального анализа исходного кода не разрешает такую передачу. Отдельно выбирайте и одобряйте основания для отправки.

## Доступ к знаниям

`access.json` — частная локальная политика. Инициализация выдаёт права только владельцу с псевдонимом, привязанным оператором. Доверенная среда запуска выбирает `CODE_ONTOLOGY_PRINCIPAL`; значение по умолчанию — `local-owner`. Аргумент инструмента не может выбирать субъект или роль. Для разных доверенных привязок субъектов запускайте отдельно настроенные процессы MCP. Это граница локального процесса и учётной записи ОС, а не удалённая служба входа или поставщик удостоверений.

Разрешения: `read_structure`, `read_policy`, `read_evidence`, `export_html`, `export_bundle` и `manage_access`; их можно дополнительно ограничить конкретными ID снимков. Неизвестные субъекты, отсутствующие или небезопасные ACL, неподдерживаемые действия и несовпадения снимков приводят к отказу по умолчанию. Ответы на запросы только политик сохраняют непрозрачные ID оснований, но скрывают сведения о расположении исходного кода; для этих подробностей нужно отдельное разрешение на основания. Старые рабочие области остаются доступными только локальному владельцу. Изменения прав перечитываются при следующих запросах, а не кэшируются как постоянные разрешения.

Явно вызванная локальная команда оператора заменяет права субъекта; в MCP её нет:

```sh
python3 "$COMPANION" pipeline-access --workspace /path/to/knowledge --principal policy-reader --action read_policy --snapshot SNAPSHOT_ID
```

Если опустить `--action`, права на операции для этого псевдонима отзываются. Должен оставаться хотя бы один администратор доступа без ограничений. Используйте псевдонимы, а не настоящие имена или адреса электронной почты. Выведенный домен не является меткой авторизации: этот выпуск не заявляет надёжную построчную изоляцию доменов. Для отдельных границ конфиденциальности используйте разные разрешённые рабочие области.

Экспорт HTML требует `export_html` и всех трёх разрешений на чтение. Переносимый экспорт требует `export_bundle` и всех трёх разрешений на чтение. Созданный HTML является автономной копией: последующие изменения ACL не отзывают уже сделанные копии. Отдельно защищайте файлы экспорта и контролируйте их получателей. Проверки владельца и режимов POSIX и доступные проверки ACL дескрипторов Windows отказывают при небезопасных условиях; выполнение на реальной Windows требует независимой проверки.

## HTML для человека, происхождение и обмен

Сформированный HTML имеет корейскую, английскую, японскую, китайскую упрощённую и русскую версии. Каталоги, модули, записи и решения политик используют ограниченные страницы и точные якоря оснований. Поиск и 3D охватывают отображаемую страницу; все записи доступны через пагинацию. Существующие режимы 3D с увеличением выбранного и общим обзором, уменьшение движения, текстовая навигация и сенсорные цели для мобильных устройств сохраняются. Относительные ссылки работают автономно без `fetch` и обязательного HTTP-сервера. Статическая страница не подразумевает текущее состояние исходного кода или поведение при выполнении.

RDF 1.1 Turtle представляет утверждения и происхождение с помощью [PROV-O](https://www.w3.org/TR/prov-o/). [SHACL](https://www.w3.org/TR/shacl/) проверяет обязательные свойства формы, но не удостоверяет истинность. Манифесты снимков связывают контрольные суммы артефактов, спецификацию анализа, охват и время проверки исходного кода. Контрольные суммы — свидетельство целостности, а не доверенные подписи. Частные манифесты исходного кода, кэши, политика доступа и локальная конфигурация исключены из переносимого экспорта. Переносимость никогда не даёт разрешение на загрузку во внешнюю систему.

Предыдущая [базовая архитектура 0.9.0](NEXT_ARCHITECTURE_0_9_0.md) фиксирует задуманный проект и цели приёмки. Это руководство по реализации и сформированные протоколы проверки описывают фактическую поддержку; неизмеренная производительность, проверки реальных устройств и будущие адаптеры явно остаются непроверенными. Официальная отправка, одобрение и публикация не входят в этот локальный процесс.
