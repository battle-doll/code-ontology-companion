# Локальный процесс версии 0.9.0

[English](../../../skills/manage-code-ontology/references/v090-workflow.md) | [한국어](../../ko/references/v090-workflow.md) | [日本語](../../ja/references/v090-workflow.md) | [简体中文](../../zh-CN/references/v090-workflow.md) | [Русский](v090-workflow.md)

Code Ontology Companion остаётся локальным конвейером преобразования исходников Java/Spring и Python в онтологию. Поддерживаются Python 3.9+, Windows, macOS и Linux. AI читает онтологию через локальный MCP, человек использует созданный офлайн HTML. Имя разработчика — **battle-doll (배틀돌)**. Выбранные модель и уровень рассуждения сохраняются; преимущества конкретной модели по качеству, токенам или скорости не заявляются.

## Проверка актуальности и восстановление

`ontology_status` отдельно сообщает `freshness` исходников и `generatorFreshness` генератора (`current`, `stale`, `unknown`). Отпечаток генератора охватывает вспомогательные модули анализа и ресурсы интерфейса. Исходники могут быть актуальны, а HTML требовать пересоздания. Старый снимок без отпечатка получает `unknown`; `sync` создаёт снимок текущего формата, не считая отсутствие метаданных доказательством актуальности.

Сначала завершаются файлы снимка и SHA-256 manifest артефактов. Затем подготовленная запись запуска используется для добавления происхождения и атомарной замены указателя текущего снимка. Прерывание может оставить незавершённую запись или несогласованный производный экспорт происхождения. `doctor --workspace` читает состояние целостности и восстановления. `recover` проверяет хеши и связи того же запуска, завершает его без дублирования событий и восстанавливает производный Turtle. Несовпадение хешей, конфликт состояния или несколько незавершённых запусков останавливают восстановление. Все файлы не объединяются в одну транзакцию файловой системы: Windows сообщает file-flush-only вместо POSIX fsync каталога.

Используйте `recover`, когда диагностика обнаружила прерывание в разрешённой рабочей области; затем выполните `sync`, если исходники или генератор устарели. MCP остаётся доступным только для чтения и не выполняет восстановление или обновление.

```bash
python3 skills/manage-code-ontology/scripts/companion.py status --workspace "/path/outside/repo/ontology"
python3 skills/manage-code-ontology/scripts/companion.py doctor --workspace "/path/outside/repo/ontology"
python3 skills/manage-code-ontology/scripts/companion.py recover --workspace "/path/outside/repo/ontology"
python3 skills/manage-code-ontology/scripts/companion.py sync --workspace "/path/outside/repo/ontology"
```

## Закрытый инкрементальный анализ

В macOS и Linux Companion использует одноразовый `.parse-cache` вне репозитория исходников, доступный только владельцу. При совпадении исходника и контекста анализа повторно используются аутентифицированные операции парсера, а не резервные копии текста исходников. Граф строится из операций заново, затем связи разрешаются повторно. Изменения области, контекста импортов/типов или анализатора отменяют соответствующие записи кеша. Повторное использование кеша не доказывает точность анализа. Пока нет настройки DACL для закрытого кеша, Windows не сохраняет его и выполняет эквивалентный полный анализ, сохраняя поддержку платформы.

Кеш, профиль идентификации, записи запусков и `source-manifest.json` должны оставаться закрытыми. `CODE_ONTOLOGY_PRIVACY_FILE` проверяет известные идентификаторы и общие чувствительные шаблоны, но не распознаёт все неизвестные реальные имена. Подготовка публичного пакета с `--public` требует защищённого профиля и проверки конфиденциальности. Не загружайте внутренние файлы рабочей области, реальные имена или личные адреса почты.

## Ограниченные доказательства для AI

Сохранены 11 прежних инструментов чтения; добавлен необязательный двенадцатый `ontology_evidence_pack`. Он выполняет 1–8 запросов поиска/соседей с уникальными ID на одном неизменяемом снимке. Метаданные снимка и качества передаются один раз. Ссылки `n:` и `e:` обозначают точные проекции узлов и доказательств. Используйте возвращённые ссылки, а не предполагайте, что ID узла описывает любое его представление.

```json
{
  "workspace_id": "registered-workspace-id",
  "requests": [
    {"id": "symbols", "operation": "search", "term": "OrderService", "limit": 20},
    {"id": "callers", "operation": "neighbors", "symbol": "OrderService", "direction": "incoming", "limit": 100}
  ],
  "node_fields": ["qualifiedName", "path", "metadata"],
  "max_results": 100,
  "max_payload_bytes": 65536,
  "max_wire_bytes": 150000
}
```

- `node_fields` выбирает `qualifiedName`, `path`, `metadata`; по умолчанию включены все, `[]` исключает их. Доступные поля идентификации сохраняются, а `omittedNodeFields` сообщает об исключениях.
- `max_results` ограничивает ответ 1–200 строками. `max_payload_bytes` задаёт 16384–262144 байт канонического структурированного JSON в UTF-8. `max_wire_bytes` задаёт 16384–1048576 байт фактического ответа JSON-RPC, включая ID запроса, дублированный текст для совместимости и перевод строки. `payloadBytes` и `wireBytes` измеряются отдельно и не являются оценкой токенов.
- Передавайте `continuation.tool` и `continuation.arguments` без изменений. Снимок, условия и бюджеты остаются закреплёнными. Поиск продвигает исходный offset; страницы соседей охватывают только первоначальный ограниченный обход. Даже на последней странице `query_limit` означает частичный результат, а не полноту графа.
- `excludedReasons`, ошибки элементов и исключённые поля указаны явно. Строка и доказательства её пути включаются вместе. Если не помещается ни одной строки, инструмент возвращает ошибку с рекомендацией изменить бюджет вместо курсора без продвижения. scope описывает исходный запрос, а не только текущую страницу.

## HTML для человека и проверка RDF

Откройте созданный `graph.html` локально. Выберите английский, корейский, японский, упрощённый китайский или русский; переключайтесь между картой и самостоятельным постраничным списком с сохранением выбора и фильтров. Просмотр изменений показывает прежние/текущие значения, а просмотр связей — статические доказательства пути. Пустые, отсутствующие и усечённые результаты сохраняют свои ограничения. Офлайн HTML показывает созданный снимок и не проверяет сегодняшние исходники или фактическое выполнение.

RDF 1.1 Turtle, `RelationshipEvidence` и ограниченное происхождение PROV-O остаются экспортами той же онтологии. В разработке/CI необязательные зависимости с фиксированными версиями из `requirements-validation.txt` позволяют выполнить независимый разбор RDF, SHACL и точную сверку троек JSON/Turtle. Они не нужны во время работы плагина. Отсутствие зависимости означает недоступную проверку, а не успешную.

```bash
python3 scripts/validate_rdf_contract.py --json "/path/ontology.json" --turtle "/path/ontology.ttl" --lineage "/path/lineage.ttl"
```

Успешная проверка структуры RDF не доказывает точность анализа исходников, полное соответствие PROV или успех выполнения. Сохраняются ограничения консервативной диспетчеризации Java и поведения Python во время определения/динамического выполнения. Анализ JS/TS и разрешение связей между модулями остаются вне поддерживаемого анализа графа этого выпуска.
