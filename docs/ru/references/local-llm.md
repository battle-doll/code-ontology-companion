# Необязательное обогащение локальной LLM

[English](../../../skills/manage-code-ontology/references/local-llm.md) | [한국어](../../ko/references/local-llm.md) | [日本語](../../ja/references/local-llm.md) | [简体中文](../../zh-CN/references/local-llm.md) | [Русский](local-llm.md)

Версия 0.9.3 может использовать существующую установку Ollama как необязательный локальный sidecar. Детерминированная онтология полноценна без него и остаётся источником наблюдаемых свидетельств.

## Последовательность согласия

1. Для инициализированного пространства сначала проверьте `status`. При enabled не спрашивайте и не настраивайте повторно. При disabled не спрашивайте снова без явного запроса включения. Дальнейшие шаги предназначены для `not_configured` или нового пространства.
2. `doctor` либо `local_llm.py detect` проверяет только известные признаки исполняемого файла/приложения; не запускает процесс, не подключается и не пишет.
3. Предлагайте функцию только при обнаруженном поддерживаемом Ollama и наличии инициализированного пространства. Для нового пространства дождитесь разрешённого `init`. До вопроса раскройте endpoint, область данных, выходной путь, класс свидетельств и остаточный риск.
4. Только после утвердительного ответа выполните `probe --authorized`: подключение лишь к `127.0.0.1:11434`, список существующих кандидатов с проверенными tag-метаданными; без запуска Ollama и установки/скачивания модели.
5. При одном кандидате покажите имя и digest и настройте его. Дополнительно нужны сведения и completion-возможность `/api/show`. При нескольких предложите выбор. При отсутствии кандидата, сбое проверки или недоступном сервисе не записывайте конфигурацию и продолжайте детерминированный процесс.
6. Настройка действует только для пространства. `disable --authorized` прекращает будущие обогащения, сохраняя старые sidecar.

Раскрытие перед согласием должно сообщать:

> Обнаружена существующая Ollama. При включении Companion обратится только к текущему сервису 127.0.0.1:11434 и отправит ограниченные переносимые метаданные онтологии; тела кода, комментарии, произвольные строки, секреты, абсолютные пути и закрытые хеши файлов не отправляются. Модель не устанавливается/скачивается, сервис не запускается. Разрешённое обогащение исполняет выбранную модель, может занять CPU/GPU и запросит немедленную выгрузку после ответа через `keep_alive=0`. Нормализованные предложения сохраняются в этом пространстве как непроверенные `inferred` и не входят в наблюдаемый граф. Собственное сетевое поведение Ollama не контролируется Companion. Разрешаете изучить существующие модели и настроить это пространство?

Отказ, истечение ожидания или недоступный сервис не являются ошибкой основного процесса. В этом же процессе не повторяйте вопрос после отказа.

## Команды

Найдите `LOCAL_LLM` рядом с проверенным bundled-скриптом Companion:

```bash
LOCAL_LLM="$SKILL_DIR/scripts/local_llm.py"

python3 "$LOCAL_LLM" detect
python3 "$LOCAL_LLM" probe --authorized
python3 "$LOCAL_LLM" configure   --workspace "/absolute/path/to/workspace"   --model "an-existing-local-model"   --authorized
python3 "$LOCAL_LLM" status --workspace "/absolute/path/to/workspace"
python3 "$LOCAL_LLM" enrich   --workspace "/absolute/path/to/workspace"   --authorized
python3 "$LOCAL_LLM" disable   --workspace "/absolute/path/to/workspace"   --authorized
```

После включения запускайте `enrich` только в относящемся к задаче анализе, запрошенном пользователем, и после проверки актуальности детерминированного снимка. Сохранённое согласие разрешает будущие запросы обогащения этого пространства, но каждый запуск следует сообщать. `init`, `sync`, `watch` и MCP никогда не вызывают помощник неявно.

## Фиксированные границы данных и сети

Поддерживается только Ollama на буквальном IPv4 `127.0.0.1`, порт `11434`. Произвольные URL, DNS-имена, LAN/публичные адреса, proxy, redirect, API-ключи, сообщённые remote/cloud-признаки и неполные/неверные метаданные отклоняются.

Рассматривается максимум 80 кандидатов-символов и 12 наблюдаемых связей каждого. Стабильное разбиение даёт запросы до 20 кандидатов и 16 KiB сериализованных переносимых метаданных. Тела кода, комментарии, произвольные строки, окружение, credentials, абсолютные пути, отпечатки источника, закрытые манифесты и сырые хеши файлов исключаются.

Запрашивается непотоковый JSON с temperature zero и строгой схемой, `think=false`, `num_ctx=8192`, `num_predict=2048`, ограниченным размером ответа, максимумом 180 секунд на запрос и `keep_alive=0`. Неподдерживаемые роли отбрасываются и считаются; одинаковые роли-дубликаты объединяются с меньшей уверенностью; узлы с конфликтующими ролями исключаются. Дубли ключей, бесконечные/NaN-числа, неизвестные узлы, неверный JSON и слишком большой вывод приводят к отказу.

`localMetadataVerified=true` означает проверку digest, размера, формата, информации о модели, completion и remote-маркеров, сообщённых `/api/tags` и `/api/show`. Это не проверка байтов весов, аутентификация loopback-процесса, доказательство локального исполнения или отсутствия внешнего запроса. Remote/cloud-маркер `/api/chat` также отклоняется, но после передачи сервису согласованных метаданных.

Loopback доказывает лишь адрес отправки Companion. Для гарантии air gap пользователь должен ограничить ОС и Ollama или оставить обогащение выключенным. Ollama может загрузить веса в CPU/GPU и расходовать вычислительные ресурсы. Запрос `keep_alive=0` не подтверждает освобождение ресурсов отдельно управляемым сервисом.

## Свидетельства и хранение

Закрытый `local-llm.json` хранится в выбранном пространстве: POSIX `0600`, Windows — ACL пространства. Он содержит провайдера, фиксированный endpoint, имя/digest модели, возможности и версии согласия/области; без API-ключа, executable-пути, произвольного URL или пути репозитория.

Только после успешной проверки всех batch-запросов атомарно создаётся один новый закрытый файл:

```text
enrichments/<snapshot-id>/<run-id>.json
```

Ошибка, неполная или частичная последовательность не оставляет sidecar. Файл хранит лишь нормализованные предложения, происхождение модели/схемы, digest входа/онтологии и явные false-полномочия. Сырые промпты/ответы не хранятся; `ontology.json`, RDF, исходники, журнал и downstream-артефакты не меняются. Предложение остаётся `inferred` независимо от confidence и не становится observed, validated или approved.
