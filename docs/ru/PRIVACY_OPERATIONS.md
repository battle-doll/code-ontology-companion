## Личные идентификаторы остаются локальными

Поддерживаемые создаваемые онтологии, ответы локального MCP и офлайн HTML проходят локальную проверку. Настроенный закрытый профиль отклоняет заданные настоящие имена и личные адреса почты; общая проверка отклоняет значения в форме личной почты. Публичные код, fixture, метаданные, отчёты и тестовый вывод не должны содержать реальные личные значения. Публичный издатель использует только псевдоним battle-doll.

`CODE_ONTOLOGY_PRIVACY_FILE` указывает закрытый профиль вне защищённых корней исходников и вывода. Он хранит закрытый ключ, ограниченные длины и отпечатки HMAC-SHA256, а не исходный текст личности. Это тоже закрытый материал: не публикуйте, не загружайте и не выводите ключ или отпечатки, не включайте их в HTML/JSON/MCP. Файл заново читается при проверке; ссылки, reparse point, неверные и слишком большие профили отклоняются. В POSIX требуется режим `0600`. В Windows до и после чтения проверяются владелец и DACL реального открытого дескриптора профиля. Действующие разрешения допускаются только для текущего пользователя, Local System и встроенной группы Administrators; null DACL, неподдерживаемые ACE и непроверяемые права отклоняются. Реальное выполнение в Windows требует отдельной проверки; POSIX и mock-тесты её не заменяют. Используйте реальный runtime-контракт, не выдумывайте команду настройки.

В 0.8.3 публичный экспорт требует защищённого непустого identity-профиля; обычное локальное исследование сохраняет необязательность профиля. Публичный манифест не включает закрытый source-manifest, ключ кеша и записи запуска. Инкрементальный разбор файлов использует закрытый аутентифицированный кеш, если его безопасный доступ подтверждён; иначе выполняется полный разбор. Сохранение кеша в Windows пока отключено до проверки безопасного создания каталога/ключа; полный анализ доступен. Это отдельно от уже реализованной проверки DACL identity-профиля.

Ошибка раскрывает только категорию, а не совпавшее значение. Без необязательного профиля защиты личных имён нет; все неизвестные имена автоматически не обнаруживаются. JSON/HTML entity/percent/unicode-escape декодируются максимум три раза; всё ещё декодируемое значение отклоняется как `encoding_depth`. Нормализация ограничена; любые бинарные метаданные, текст на изображениях, сторонний вывод и все кодировки не гарантируются. Локальный PASS не означает отсутствие личных данных везде.

## Проверка каждого канала публикации

Перед публичным PR требуется свежая доверенная запись, проверяющая защиту почты реальной учётной записи GitHub. Ручная запись, локальный `git config`, настроенный файл или модульный тест не являются текущим свидетельством провайдера. Проверяйте все выбранные исходные и автоматически созданные сервисом commit ref; один HEAD не включает часть сохранённых PR merge ref. Прямой branch-тест проверяет код, а не безопасность будущих созданных сервисом commit.

Отдельно проверяйте реальную публичную личность разработчика официального каталога. Если показывается личная информация вместо одного battle-doll, применяйте **HOLD** перед загрузкой, отправкой и публикацией. Файл, проверка черновика портала, одобрение и публичный listing — разные состояния. Сохранённый ref остаётся проблемой до подтверждения удаления провайдером; изменение branch или локального репозитория не доказывает глобального удаления.

## Сохранение продукта и границ проверки

В полном исходном checkout или полном выпуске после безопасной настройки `CODE_ONTOLOGY_PRIVACY_FILE` запустите проверку издателя только для чтения, используя Python3.9+ и авторизованный GitHub CLI:

```sh
python scripts/check_publication_privacy.py
```

Профиль должен содержать непустые deny-списки имён и почты. Проверяются manifest только с псевдонимом, локальные Git `--all` идентификаторы, сообщения и имена ref общим scanner, публичный профиль GitHub (name null/пустое/battle-doll/배틀돌, email null), заголовки/текст PR и author/committer/сообщение каждого записанного REST `merge_commit_sha`. Предел —100PR и двеAPI наPR; полная страница100записей, недоступные данные и истёкший лимит времени остаютсяUNKNOWN. Не включены незагруженные, удалённые и внутренние ref провайдера, исторические исходные blob, issue/comments, CI-логи и пиксели изображений. Настройки защиты почты GitHub вUI и выбранную подтверждённую личность OpenAI проверить нельзя, поэтому даже при успехе механических проверок сохраняются **HOLD** и код выхода1. Ручного обхода `--verified` нет. Необязательный `--output` сохраняет очищенную JSON-запись вне исходников; findings содержат только правило, номерPR и количество. Запись не разрешает PR или загрузку. ЭтотCLI обслуживания выпуска отсутствует вskills-only и не добавляет сетевое поведение генератору, MCP или HTML.

Windows, macOS и Linux сохраняются. AI использует локальный MCP только для чтения, человек — запрошенный созданный офлайн HTML. Этот patch не создаёт отдельный HTML-отчёт, удалённый endpoint, telemetry или процедуру загрузки личной идентификации. Выбранные модель и уровень рассуждения не меняются.

Поле копирования выбранного объекта вHTML использует относительный snapshot/entity/edge query вместо полного локального file URL. Свободный текст поиска не сохраняется и не воспроизводится черезURL/history; исходные ошибки native JSON parse не выводятся вUI.

Проверяйте исходники, выбранные ref, распакованный пакет и оба exact release profile на окончательном кандидате. Существующий тег 0.8.0 не изменяется. Синтетические тесты доказывают поведение детектора только в этих случаях; реальные хосты E2E, профессиональный перевод, полная доступность и удаление внешним сервисом требуют своих доказательств. [Охват переводов](../TRANSLATION_COVERAGE.md) описывает пять языков и реальный объём.
