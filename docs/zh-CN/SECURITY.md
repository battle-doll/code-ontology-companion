## 支持的版本

安全修复仅提供给最新发布版本。

## 报告漏洞

请勿在公开 issue 中包含私有源代码、机密、凭据、本地绝对路径或本体制品。

请通过 GitHub 私有漏洞报告功能向以下仓库报告：

https://github.com/battle-doll/code-ontology-companion

如果私有报告不可用，请仅创建一个最小公开 issue，请求建立私密沟通渠道，不要包含利用细节或机密数据。

## 安全模型

版本 0.4.0 的安全模型：

- 执行静态解析，绝不导入或执行目标代码；
- 拒绝属于链接/重解析点的仓库和工作区根目录；
- 跳过类似链接的文件、特殊文件、名称敏感文件、依赖项、VCS 和生成文件；
- 强制执行单文件、源代码总量、源文件数量、图谱、影响分析、HTTP、候选和建议限制；
- 仅在仓库之外一个新的、明确指定的工作区中创建制品；
- 在 staging 中构建刷新，并以原子方式提升不可变快照；
- 当分析器或 Companion 版本变化时刷新未变更的仓库；
- 刷新失败后保留最后一个已知良好的快照；
- 确定性分析、工作区操作和工作台均不联网，也不收集遥测；
- 检测可选 Ollama 时不执行它、不探测端口也不写入；
- 在独立辅助程序仅联系 `127.0.0.1:11434` 之前要求明确的工作区级同意，拒绝报告的 remote/cloud 标记或缺失的 API 元数据，且仅将输出存储为未经验证、仅创建的 inferred sidecar；
- 在 Codex 宿主启用时启动只读 stdio MCP 进程；
- MCP 不开放端口，并接受已注册工作区 ID 而非文件系统路径；
- MCP 只公开工作区列表、状态、搜索、邻居、历史、快照比较和血缘查询，不公开写入、刷新、安装、删除、上传或执行工具；
- 不安装运行时、软件包、数据库、模型、守护进程或后台 watcher。

可选辅助程序不会使 Ollama 成为可信分析器的一部分。Ollama 自身的网络、日志记录、模型行为和安全性不在 Companion 边界内。如果仅限回环的传输不能提供充分保证，请保持增强禁用或实施操作系统级控制。增强会运行选定模型并可能分配 CPU/GPU 内存；辅助程序发送 `keep_alive=0` 以请求在响应后立即卸载，但无法证明独立管理的服务已释放资源。`localMetadataVerified=true` 是对 Ollama 报告的 API 元数据进行的验证，并非对模型权重、回环服务身份、本地执行或 Ollama 无出站通信的证明。

生成的输出不会自动变得适合公开。符号和相对路径可能泄露机密架构。
