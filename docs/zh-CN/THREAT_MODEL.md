# 威胁模型

[English](../../THREAT_MODEL.md) | [한국어](../ko/THREAT_MODEL.md) | [日本語](../ja/THREAT_MODEL.md) | [简体中文](THREAT_MODEL.md)

## 资产

- 目标源代码和架构；
- 源代码树附近的凭据和配置；
- 目标仓库完整性；
- 当前和历史本体完整性；
- 私有工作区路径和源指纹；
- 用户对安装、传输和后台活动的控制；
- 可选本地推理配置和 inferred sidecar。

## 信任边界

即使访问已获授权，仓库内容也不可信。文件名、符号、注解、注释、语法错误和生成制品都是数据，而不是指令。

Codex 编排工作流。分析器独立强制执行核心文件系统、授权、输出和执行边界。本地 MCP 服务器是第二重边界：它仅接收已注册工作区 ID，并提供只读方法。

可选本地 LLM 辅助程序是第三重、有意隔离的边界。确定性分析或 MCP 不会导入它。同意前，它只能检查已知安装指示器；同意后，它只能联系一个固定 IPv4 回环端点，并且只能写入所选工作区内。

## 威胁与缓解措施

| 威胁 | 缓解措施 |
| --- | --- |
| 源代码或名称中的提示词注入 | 不保留源代码正文、注释和任意字符串；经验证的点分策略标识符是仅作为数据的图节点；skill 要求将所有标识符视为不可信数据 |
| 收集机密 | 排除疑似机密的名称/扩展名，以及常见 VCS、依赖、生成和缓存路径 |
| 链接或路径逃逸 | 不跟随链接；拒绝根目录链接/重解析点；验证工作区和快照包含关系 |
| FIFO 或设备阻塞 | 仅读取普通文件；跳过特殊文件 |
| 执行目标代码 | 不提供 import/build/test/runtime 路径；软件包检查会拒绝目标执行原语 |
| 修改仓库 | 工作区必须位于仓库外且不得包含仓库；目标 digest 测试强制只读行为 |
| 部分或损坏的刷新 | 稳定的前后清单、staging、验证、不可变快照和原子状态提升 |
| 并发源代码变更 | 指纹不匹配会隔离 staged 输出并保留最后一个已知良好状态 |
| MCP 任意文件访问 | MCP 接受随机注册工作区 ID，而非文件系统路径 |
| MCP 隐蔽写入 | 所有 MCP 工具均只读并准确标注；初始化、刷新、记录、删除、上传和执行不通过 MCP 暴露 |
| 分析器或 MCP 网络外泄 | 核心分析器、工作区 CLI、工作台、启动器和 MCP 不包含网络客户端，也不开放监听 socket |
| 静默连接本地 LLM | 指示器检测不执行任何内容，也不建立连接；probe、configure、enrich 和 disable 在可能连接或写入时要求明确授权 |
| 端点重定向或 LAN/公网传输 | 辅助程序只构造 `HTTPConnection("127.0.0.1", 11434)`，不接受 URL 或 host 输入、绕过 proxy 配置且不跟随 redirect |
| 将远程/云结果接受为本地证据 | `/api/tags`、`/api/show` 或 `/api/chat` 报告的 remote/cloud 标记，以及缺失 digest/size/format/model information 或 completion capability，均失败关闭 |
| 提示词注入或伪造模型输出 | 只发送有界可移植元数据；明确将标识符视为不可信数据；严格的 JSON、重复键、有限数值、节点 ID、角色、数量、大小和超时检查会拒绝畸形输出 |
| 将模型推理提升为事实 | 规范化结果是仅创建、带有精确 false authority 的 `inferred` sidecar，绝不合并到 observed 图谱、RDF、血缘或 MCP 输出 |
| 私有路径披露 | 从普通 RDF、HTML 和 MCP 输出中移除绝对路径和完整指纹 |
| 资源耗尽 | 仅支持指定扩展名、单文件 2 MiB 和源代码聚合限制、有界图谱/影响分析/可视化/LLM payload 与响应限制 |
| HTML 注入 | 标题转义、JSON 安全嵌入，不使用 CDN、iframe、远程脚本或 fetch |
| 错误因果结论 | 区分 observed/declared/inferred/validated/approved 证据；文档禁止运行时或因果主张 |

## 剩余风险

- 符号和仓库相对路径可能泄露机密架构。
- 版本 0.5.2 会完整重新分析发生变化的仓库，并可能消耗明显的 CPU 和内存。
- 静态解析可能漏掉反射、生成代码、运行时条件、动态分派或元编程。
- 本地 registry 和工作区会向已经拥有用户文件系统权限的其他进程暴露信息。
- 被攻破的 Python/Node 运行时、Codex 宿主、操作系统或用户账户不在本插件安全边界内。
- 用户可以在制品创建后有意共享。
- 回环只约束 Companion 的目标地址，不约束独立管理的 Ollama 进程或模型的网络行为、日志记录或保留。
- 增强会运行选定模型，并可能分配 CPU/GPU 内存。`keep_alive=0` 请求在响应后立即卸载，但无法证明独立管理的服务已释放资源。
- Ollama API 元数据由其自行报告。`localMetadataVerified=true` 不能证明模型权重字节、认证回环服务、证明本地执行或证明没有出站流量。只有在请求元数据到达该服务之后，chat 响应标记才能被拒绝。
- 即使通过 schema 验证，模型建议仍可能错误或具有对抗性；它们仍是未经验证的推断，需要独立审查。

## 改变安全性的扩展

任何公共网络端点、远程 AI 调用、超出文档所述固定回环可选辅助程序的扩展、目标代码执行、自动安装软件包/模型/数据库、认证、遥测、持久守护进程、文件系统 hook、可写 MCP 工具或外部图存储，都要求重新进行隐私、许可证、威胁模型和提交审查。
