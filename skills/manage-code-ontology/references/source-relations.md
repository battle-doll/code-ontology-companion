# Bounded source relations and local source analysis

The static Java producer adds `sourceRelations` version `source-relations-3` / schemaVersion 3 to existing `semantic_fragment` records. It does not create a new record kind, execute source, infer business authority or observe runtime values. `source-relations.schema.json` defines the closed relation/details shape. Source argument, parameter and element order is retained; evidence sets and the non-semantic inheritance-check collection are canonicalized.

Parser/unsupported evidence is classified separately from privacy withholding and permission revocation, with original fixed reasons retained.

Every relation references existing emitted IR through exact `recordId`/`jsonPointer`, path/source digest and a canonical pointer-value hash. The versioned relation closure binds its kind, constraints, source range and references. It never copies an expression AST, literal, comment or source body into a relation. `analysisSpecBinding=snapshot_metadata` requires the containing sealed snapshot's real analysis specification; it does not invent a new specification inside a source fragment.

A represented relation proves only its named source relationship. Candidate/partial/denied/unknown/unsupported/omitted counts remain separate. Detected relation candidates are a bounded feature denominator, never a denominator for all code or business rules. Runtime status remains `not_observed`, runtime values and stored component values remain `UNKNOWN`, and `businessMeaningVerified` remains false. Pointer/provider/owner/closure changes withdraw the relation with a fixed cause and audit hash (parser unsupported, privacy denied, permission revoked and unavailable dependencies retain separate dispositions); downstream readers must require both represented resolution and verified emitted-IR validation.

Version3 closes source inputs through scalar `inputClosure` version `source-relation-inputs-2` for the complete same-file parser and exact symbol/callsite inventories. The parser projection excludes only sourceRelations, transport kind/module/modulePath/language/basis/status, and representationStatus/unsupportedReasons/dependencyClosure. The latter three are completely bound, with presence/value, in per-relation current owner/provider admissibility and rechecked at use. Every other field and nested ordered value remains bound. A complete current inventory is required; incomplete context is invalidated/UNKNOWN, without source rereads or count-fitting. Root pointer "" is restricted to nonrecursive symbol/callsite objects.

`finalize_dependencies(..., inventory_lookup=...)` and `finalize_source_relations(..., inventory_lookup=...)` require current complete same-file symbol/callsite metadata. The official store enumerates staged SQLite records. A direct caller omitting this boundary fails closed. Both inventory digests are computed once per file per build/finalization invocation. Every owner and referenced provider is also checked for parser/privacy/revocation/dependency status, separately from pointer equality. Complete Record provider roots close constructor-component/body eligibility, including the direct finalizer.

Implemented families:

- Exact selected-source, nonvirtual private/static/final helpers: one fully covered return body, exact argument types and a checked parameter-only pure expression or an empty-body implicit record construction. The selected callsite must be exact and target the Method originalSymbolId. Modifiers use the separate top-level Method.sourceMethodModifiers metadata, included in whole-Method hashes; the legacy closed callbackDeclaration retains its original ten-key shape. Independently resolved overloads are allowed; receiver aliases, arbitrary dispatch, mutation, recursion, extra statements, effects, generics, varargs and declared exceptions remain partial. A helper summary references its existing return and caller argument nodes.
- Constructor parameter/component transfer on normal return: implicit canonical order, strict explicit canonical direct assignments and bounded pure compact parameter transformations. Complete component declarations and conservative expression types are required for represented transfers. Caller applicability and initialized/stored values are separate unknown claims. Early throw/control, delegation, repeated writes, effects and unbound ordinary constructors remain partial.
- Primitive local straight-line reaching definitions: complete source-body coverage and local declarations only. Branches, loops, field aliasing and incomplete bodies remain partial. Lexical return contexts are explicitly source syntax, not execution or durability. Existing control-flow source-order fields are reused rather than duplicated as additional relations.
- Enum declaration positions and declared array element positions. A finite association uses an exact selected enum parameter and the lexically resolved array declaration. It preserves runtime ordinal/index/capacity/array mutation uncertainty. Same-name nested enums and unrelated arrays are not merged.
- Callback body pointers preserve source shape; callback trigger, persistence, completion effects, global lifecycle and authorization are not inferred.

Caps of 40,000 relations per source file, 256 evidence references per relation, 48 KiB of relations per fragment and a conservative 192 KiB target for augmented source records preserve omitted/unknown denominators. Existing source records already over that target are retained, with their new relation candidates omitted; this feature does not claim to shrink pre-existing source records. Byte/count exhaustion records `bounded_source_relation_budget` without deleting the source fragment or shrinking candidate counts. Privacy-withdrawn or missing source IR cannot supply a represented relation. Explicit unit evidence is not added by this feature; unresolved units remain unknown. Non-Java semantic extraction remains explicitly unsupported while other language inventory/structural facts are unchanged.

## Explicit local comment disclosure

Default comment handling and the existing independent documentation review remain unchanged. `localSourceAccess` is a separate, explicit configuration receipt with format `companion.local-source-analysis-access.v1`, purpose `local-source-analysis`. No model or spelling classifier issues the receipt. An operator supplies it after the human authorizes the selected scope. It has no personal approver name/email or public-sharing authority.

The receipt binds an opaque permission ID, selected immutable source fingerprint, scope digest, explicit configured source roots, private workspace ID, canonical current privacy-profile hash, access-policy byte hash, revocation ID/state, and every complete comment occurrence's path/source hash/byte range/token hash. `selectedScope=["."]` is the explicit receipt representation of the pipeline's existing empty-root configuration. Expiry is optional: `expiresAt=null` remains valid until the bound scope/source snapshot, destination, profile, ACL or receipt changes or it is explicitly revoked. A reader never rereads application source to recover withheld content.

An exact local permission may supply a complete comment token only after the current built-in/profile/registered-value and normalized documentation privacy checks pass. Rejected tokens retain their occurrence/count and fixed reason; no partial masking claims completeness. It does not override a rejected/revoked independent review. Existing independently reviewed evidence and local capture have separate counts. Locally captured text has `semanticReview=UNREVIEWED`, `instructionAuthority=none`, enforcement `UNKNOWN`, `businessMeaningVerified=false` and `publicDisclosureAuthorized=false`.

The existing `semantic_fragment.sourceText` field is reused with separate `localCapturePermission` metadata containing only opaque IDs, binding digests, byte coordinates and claim limits. There is no new tool, vault, general role or business contract. Source search through MCP and CLI already requires both `read_policy` and `read_evidence` for semantic fragments; an unspecified source kind requires all source read permissions. Policy-only business projection/name/facets do not inherit sourceText. General policy queries remain restricted to policy records.

The source spec adds `localSourceAccessSha256` independently of documentation review hashes only when configured. Snapshot opening, every stable read checkpoint and publication revalidate the current receipt, profile, ACL, scope/destination and optional expiry. A changed or cleared receipt, stale profile/ACL or explicit revocation makes older captured snapshots fail closed through official readers and exports. Immediate receipt revocation does not read source or generate a snapshot. A later authorized source refresh produces opaque future comment records; it does not silently relabel the old snapshot. Raw source is never queried as a fallback. Immutable snapshots bind their captured source fingerprint; deletion of application source does not itself invalidate the unchanged sealed evidence.

Source HTML and portable bundle creation continue to require evidence plus their existing export/read permissions. JSON payloads retain the complete authorized source record. RDF emits lossless JSON literals for `co:sourceRelations` and authorized `co:documentationEvidence`, through the same evidence-gated exports. Privacy/permission changes block future serialization from the source workspace. Existing private offline copies remain copies and cannot be physically recalled by changing a local ACL; creating/exporting one requires the existing explicit export authorization.

Trusted in-process API:

- `pipeline_store.load_local_source_access(path)` reads an explicitly selected private receipt file.
- `pipeline_store.sync(workspace, local_source_access=receipt)` pins the independent receipt/config and analysis specification.
- `pipeline_store.revoke_local_source_access(workspace)` (or `sync(..., clear_local_source_access=True)`) clears local permission immediately without reading source or generating a snapshot. A later authorized refresh produces opaque source evidence.

The CLI patch adds mutually exclusive `refresh --authorized --local-source-access PATH` and `refresh --authorized --clear-local-source-access`. Grant/replacement requires the existing `manage_access` plus `read_evidence` actions; revocation requires `manage_access` only and reads current snapshot/ACL/configuration without source. The low-level store API is a trusted in-process caller / filesystem-owner boundary; it creates no MCP write tool. It does not auto-create or approve a receipt. A new pipeline's workspace ID is generated during initialization, so the receipt is issued for a known prepared/existing private workspace. Source generation and actual application operation are separate actions.

## Typed source names and presentation

The declared typed-input contract preserves original source name absence, empty string and null through the name-presence marker and inputClosure. Ordinary Java parsing does not currently emit null return names; null/empty verification uses an explicitly labeled neutral parser-input wrapper. `pipeline_store.indexed_record_name` returns a valid string for SQL/presentation: existing strings remain exact (including empty), and only an explicit semantic_fragment name=null uses the fixed `Unnamed source fragment` label. Other kinds or invalid/missing names fail. Source JSON payloads are never rewritten to that label. Portable SQLite uses the same independent index label while retaining the complete canonical JSON payload.

RDF is a projection. `co:label` uses a presentation string, while `co:sourceRelations` JSON literals are exact. RDF alone does not reconstruct every parser/provider input, typed source name or source AST; independent closure verification uses authorized source JSON inventories. HTML raw JSON and source-deleted MCP records preserve the typed payload exactly. No privacy permission, semantic authority or runtime claim is inferred from a display/index label.

## Version3 availability and first-seal boundary

The global source input projection version is `source-relation-inputs-2`. It excludes precisely sourceRelations, transport kind/module/modulePath/language/basis/status, and the three availability diagnostics representationStatus/unsupportedReasons/dependencyClosure. All other fields, typed expressions, unknown future fields and ordered nested arrays remain bound. Availability is independently bound for every owner and directly referenced provider: `admissibility` contains version, sealed/pending status, ownerRecordId, recordCount and a scalar statesSha256. The canonical digest frames complete sorted owner+sourceEvidenceIds state objects, with exact kind/path/sourceDigest and explicit presence/value for all three diagnostic fields. Every current owner/provider predicate is still checked. Unrelated diagnostic lifecycle changes cannot withdraw an independent helper; actual used-provider unsupported/privacy/revocation/pending/invalidated changes still do.

A fresh nonserialized SourceRelationBuildContext registers each newly parsed file's exact compact relation bundle and source input closure. Official global dependency finalization consumes it once and may issue only the first final-IR admissibility seal. Serialized pending flags cannot authorize a seal, rearm a prior proof or rebase changed inputs. Default finalizers reject unbound/pending witnesses. Recovery reparses serialized pending facts. Normal standalone extraction seals its complete current IR immediately. No witness repeats AST, whole-file IDs or per-provider state lists in the output.

## Explicit RDF projection bindings

Low-level RDF emission defaults to no documentation body projection when trusted bindings are None. Actual generation supplies RdfDocumentationBindings constructed from final staged doc rows and current admitted review/local contexts. Each row must match the complete occurrence/token, path/source hash, full record, claim and authority-proof digests, and still-current in-process permission status. Explicit missing/changed permission, token/claim/proof/status mismatch or binding-budget failure raises a fixed error, reports original coverage and prevents snapshot promotion. It is not a silent omission. Already denied/omitted comment populations and RDF text-bearing-record coverage remain separate. Authorized literals are exact JSON projections; the complete source graph is not losslessly reconstructed from RDF.

## Optional reader resource policy

`open_reader` and SnapshotReader accept keyword resource_policy=None or exact `bounded_memory_v1`. None performs no resource SQL. The opted fresh-child mode only reads an already established integer hard_heap_limit in (0,134217728], verifies exactly one compile TEMP_STORE=1/2/3, then sets temp_store=MEMORY and requires exact readback2 before ATTACH/data SQL. It never sets/lowers a global heap limit. Missing cap/unsupported compile or readback fails with fixed reasons and closes the new connection. Existing immutable read-only attachments, query_only, current permissions and stable identities remain unchanged. No new MCP option/action/permission is introduced.
