Code Ontology Companion — независимый плагин Codex для ведения локального
графа знаний об авторизованном репозитории Java/Spring или Python с учетом
конфиденциальности.

Он объединяет детерминированный статический анализ, проверяемые свидетельства
для связей, неизменяемые снимки, экспорт RDF 1.1 Turtle, историю происхождения,
совместимую с PROV-O, интерактивный автономный рабочий интерфейс и локальный
MCP-сервер только для чтения. Детерминированный анализатор и MCP-сервер не
исполняют целевой код, не устанавливают ПО, не отправляют телеметрию и не
выполняют сетевые запросы. Отдельно авторизуемый необязательный помощник может
передавать ограниченные переносимые метаданные онтологии существующему сервису
Ollama по фиксированному loopback-адресу `127.0.0.1:11434`; его непроверенные
предложения остаются за пределами наблюдаемого графа.

Используйте плагин, чтобы на уровне исходного кода выполнить обратный анализ
существующей авторизованной кодовой базы и получить навигационную онтологию. Он
читает поддерживаемую структуру Java/Spring и Python без исполнения целевого
проекта, записывает символы и статические связи в неизменяемый снимок и создает
JSON, RDF/Turtle и автономный интерактивный интерфейс для исследования и
планирования изменений.

Для выполнения запрошенного рабочего процесса Codex может обрабатывать вывод
команд, например символы, счетчики и пути относительно репозитория. Такая
обработка платформой регулируется [применимыми условиями OpenAI](https://openai.com/policies/terms-of-use/)
и [политикой конфиденциальности](https://openai.com/policies/privacy-policy/).
Установка этого плагина не делает Codex автономным офлайн-продуктом.

## Возможности версии 0.5.2

Плагин поддерживает следующие рабочие процессы:

- Отображает пакеты, импорты, типы, методы, наследование и базовые зависимости
  Java.
- Распознает распространенные стереотипы Spring, `@Bean`, внедрение через
  конструктор и поля, advice AspectJ, а также признаки proxy для transaction,
  async, cache, authorization и retry.
- Отображает модули, импорты, типы, функции, декораторы, вызовы и наследование
  Python, а также эвристические роли Extract/Transform/Load/Validate/Orchestrate.
- Добавляет к каждой связи массив `evidence`. Каждый его элемент содержит
  стабильный `rule_id`, одно качественное значение `basis` (`direct_syntax`,
  `resolved_static`, `framework_semantic` или `name_heuristic`),
  `runtime_status` со значением `not_applicable` или `runtime_unknown`,
  необязательные `path`, `line_start` и `line_end` относительно репозитория, а
  также ограниченный список `limitations`.
- Публикует контракт `document.quality` версии `1.0` с покрытием и количеством
  свидетельств связей, состояниями адаптеров Java и Python, их возможностями и
  индикаторами неподдерживаемого runtime. Нулевое число предупреждений разбора
  не означает полноту статического или runtime-покрытия.
- Консервативно разрешает вызовы Java внутри одного владельца и явные вызовы
  через распознанные импортированные типы, пропуская неоднозначные кандидаты
  вместо создания недостоверных связей.
- Более консервативно разбирает generics, records, вложенные типы, несколько
  интерфейсов и случаи аннотаций/внедрения Spring в Java, а также aliases,
  относительные импорты, lexical shadowing, вложенные функции и layout `src/`
  в Python.
- Устанавливает строгие ограничения на объем исходного кода, графа, анализа
  влияния и вывода.
- После явного согласия в рамках workspace и проверки метаданных модели,
  сообщенных Ollama, может настроить одну существующую completion-модель Ollama;
  сохраняет только нормализованные sidecar-файлы `inferred`, не изменяя
  детерминированную онтологию.
- Пропускает обновление неизменившегося кода, используя приватный fingerprint
  исходников.
- Обновляет даже неизменившийся исходный код, если изменилась версия анализатора
  или Companion.
- Анализирует изменившийся репозиторий в staging и атомарно публикует
  неизменяемый снимок.
- Сохраняет последний корректный снимок, если анализ или проверка завершаются
  ошибкой.
- Сравнивает снимки и ведет историю происхождения с классами
  observed/declared/inferred/validated/approved.
- Экспортирует переносимый RDF/Turtle и самодостаточный интерактивный HTML без
  CDN, с поиском по полному индексу, ограниченными представлениями связей и
  понятными деталями.
- Переключает выбранную ограниченную окрестность между стандартным структурным
  видом 2D и необязательной 3D-констелляцией. 3D использует локальную
  перспективную отрисовку Canvas2D, детерминированные статические позиции и
  явные лимиты узлов, ребер и кадров; WebGL, дополнительные пакеты, workers,
  телеметрия и сеть не требуются.
- Позволяет исследовать 3D-сцену с помощью вращения и масштабирования указателем
  либо равноценных клавиатурных команд для вращения, масштабирования, сброса
  камеры, перехода между узлами, выбора и возврата к корневому узлу. Поиск в DOM,
  списки связей, сведения и 2D-граф остаются основными доступными способами
  работы с теми же узлами и связями.
- Учитывает предпочтения reduced-motion и forced-colors/высокой контрастности,
  передает вспомогательным технологиям сведения о режиме и выбранном элементе,
  приостанавливает отрисовку в скрытых вкладках и безопасно возвращается в 2D
  при сбое Canvas.
- Сравнивает текущий и предыдущий снимки непосредственно в рабочем интерфейсе,
  не раскрывая fingerprints исходников и абсолютные пути workspace.
- Предоставляет запросы к зарегистрированным workspace через семь локальных
  MCP-инструментов только для чтения.
- Сопоставляет распознанные чтения Java policy accessor с ветвями управления,
  которые они защищают, не сохраняя произвольные строковые литералы.
- Запускает детерминированный анализатор, локальный MCP-сервер и необязательный
  помощник Ollama в Windows, macOS и Linux с Python 3.9 или новее.
- Применяет исполняемый golden/forbidden quality gate к ожидаемым и запрещенным
  узлам, связям, метаданным evidence, покрытию адаптеров и детерминированному
  выводу, не исполняя целевой репозиторий.

Версия 0.5.2 выполняет полный повторный анализ изменившихся репозиториев.
Приватные отпечатки исходного кода позволяют избежать ненужных запусков, если
исходный код не изменился.

## Конфиденциальность и безопасные настройки по умолчанию

- Анализируйте только код, которым вы владеете или который имеете право
  проверять.
- Команды `doctor` и `preflight` работают только для чтения.
- Инициализация требует `--authorized` и нового workspace вне репозитория.
- Тела исходного кода, комментарии и произвольные строковые литералы не
  сохраняются. Проверенные идентификаторы политик с компонентами, разделенными
  точками, переданные распознанным акцессорам политик Java, могут сохраняться как
  узлы `PolicyLeaf`.
- Приватная локальная конфигурация хранит абсолютный путь к репозиторию, а
  приватный манифест — размер и значение SHA-256 каждого файла для проверки
  актуальности.
- Переносимые RDF- и HTML-экспорты и обычные ответы MCP не содержат абсолютных
  путей и полных отпечатков. Свидетельства связей могут содержать пути
  относительно репозитория и диапазоны строк; эти данные также могут быть
  конфиденциальными.
- Исключаются файлы, похожие на секреты, ссылки и точки повторной обработки,
  зависимости, содержимое VCS и сгенерированные результаты.
- Целевые проекты никогда не импортируются, не собираются, не тестируются и не
  запускаются.
- Процесс MCP использует stdio, не открывает порт для прослушивания и принимает
  идентификаторы рабочих пространств, а не произвольные пути файловой системы.
- Не устанавливаются демон, база данных графов, локальная модель, пакеты или
  средство отслеживания. Cytoscape.js и ELK.js встроены в создаваемый HTML в
  зафиксированных версиях; необязательная 3D-проекция использует встроенный
  Canvas2D. Не используются установка через npm, CDN, веб-воркеры, зависимость
  от WebGL, телеметрия или сетевой сервис.
- Обнаружение локальной LLM ничего не исполняет, никуда не подключается и ничего
  не записывает. Только после получения согласия необязательный помощник может
  обратиться к фиксированному адресу обратной петли IPv4, проверить метаданные,
  сообщенные Ollama, отклонить ответы с маркерами `remote`/`cloud`, записать
  приватную конфигурацию для рабочего пространства и создать свидетельства
  `inferred` без перезаписи существующих данных. В POSIX используется режим
  `0600`; в Windows наследуется список управления доступом выбранного
  пользователем рабочего пространства.

Имена символов и пути относительно репозитория также могут быть
конфиденциальными. Не передавайте workspace и экспорты, пока совместное
использование не будет отдельно разрешено.

## Требования

- Codex с поддержкой плагинов и skills
- Python 3.9 или новее
- Сторонние пакеты Python, graph database, Java runtime и локальный LLM не
  требуются

Если доступен Node.js, bundled MCP launcher может найти Python без запуска
shell. Прямая конфигурация Python stdio поддерживается на всех платформах.

## Обратный анализ существующего кода в онтологию

В macOS или Linux используйте `python3` в приведенных ниже командах. В Windows
используйте существующий интерпретатор Python 3.9 или новее, например `py -3`.

1. Запустите `doctor` и `preflight` для существующего репозитория, чтобы без
   записи файлов проверить поддерживаемый набор исходников.
2. Изучите результат, выберите новый workspace вне репозитория и выполните
   авторизованную команду `init`. Она проводит обратный анализ на уровне
   исходного кода и создает первый неизменяемый снимок онтологии.
3. Исследуйте `graph.html`, загрузите `ontology.ttl` в RDF-совместимый рабочий
   процесс или используйте CLI и необязательные локальные MCP-инструменты только
   для чтения для поиска символов и связей.
4. После изменения кода выполните `sync` и `diff`, чтобы создать и сравнить
   новый снимок, сохранив предыдущий и его lineage.

### Команды вручную

```bash
python3 skills/manage-code-ontology/scripts/companion.py \
  doctor --repo "/path/to/authorized/repository"

python3 skills/manage-code-ontology/scripts/companion.py \
  preflight --repo "/path/to/authorized/repository"
```

После проверки preflight и авторизации создания локальных artifacts:

```bash
python3 skills/manage-code-ontology/scripts/companion.py \
  init \
  --repo "/path/to/authorized/repository" \
  --workspace "/path/outside/repository/ontology-workspace" \
  --authorized
```

Обновление и запросы:

```bash
python3 skills/manage-code-ontology/scripts/companion.py \
  sync --workspace "/path/to/ontology-workspace"

python3 skills/manage-code-ontology/scripts/companion.py \
  query --workspace "/path/to/ontology-workspace" --term "OrderService"

python3 skills/manage-code-ontology/scripts/companion.py \
  diff --workspace "/path/to/ontology-workspace"
```

### Необязательный локальный MCP только для чтения

Полный пакет плагина содержит stdio-сервер с семью инструментами. Он не
открывает listening port и принимает зарегистрированные значения `workspace_id`,
а не произвольные пути репозитория. Если bundled launcher недоступен, настройте
сервер непосредственно в Codex с помощью команды Python для текущей платформы.

macOS или Linux:

```toml
[mcp_servers.code-ontology-companion]
command = "python3"
args = ["/absolute/path/to/code-ontology-companion/mcp/server.py"]
```

Windows:

```toml
[mcp_servers.code-ontology-companion]
command = "py"
args = ["-3", "C:\\absolute\\path\\to\\code-ontology-companion\\mcp\\server.py"]
```

После изменения конфигурации MCP перезапустите Codex или откройте новый процесс
Codex, затем проверьте список workspace, status и search. Полный порядок
настройки и проверки описан в
[local-mcp.md](skills/manage-code-ontology/references/local-mcp.md).

### Необязательное обогащение с помощью существующего сервиса Ollama

Для детерминированного рабочего процесса модель не требуется. При первом
подходящем рабочем процессе обнаружение выполняется только для чтения. Только
если обнаружен сервис Ollama, Companion должен запросить разрешение на просмотр
сведений о существующих локальных моделях. Согласие разрешает просмотр сведений
о моделях через фиксированный адрес обратной петли и настройку рабочего
пространства; оно не разрешает установку, скачивание, запуск сервера или
использование произвольных конечных точек. Модели и результаты, которые Ollama
помечает как `remote`/`cloud`, отклоняются.

```bash
python3 skills/manage-code-ontology/scripts/local_llm.py detect

# Выполняйте только после раскрытия сведений и явного согласия, описанных в skill.
python3 skills/manage-code-ontology/scripts/local_llm.py probe --authorized
python3 skills/manage-code-ontology/scripts/local_llm.py configure \
  --workspace "/path/to/ontology-workspace" \
  --model "an-existing-local-model" \
  --authorized
python3 skills/manage-code-ontology/scripts/local_llm.py enrich \
  --workspace "/path/to/ontology-workspace" \
  --authorized
```

Помощник передает ограниченные метаданные символов и наблюдаемые связи, но не
тела исходников, комментарии, произвольные строки, секреты, абсолютные пути или
приватные хеши файлов. Нормализованные предложения сохраняются в
`enrichments/<snapshot-id>/<run-id>.json` как свидетельства `inferred`;
необработанные запросы к модели и ответы не сохраняются. Версия 0.5.2 делит эти
метаданные в стабильном порядке на запросы не более чем по 20 кандидатов и
16 KiB, отключает режим рассуждения модели, ограничивает контекст каждого
запроса 8 192 токенами, вывод каждого ответа — 2 048 токенами, а время запроса —
180 секундами. Сопроводительный файл публикуется атомарно только после успешной
проверки всех пакетов запросов, поэтому неудачный или частичный запуск не
оставляет артефакта. Неподдерживаемые или противоречивые предложения ролей
пропускаются и подсчитываются, а не связываются. Сетевое поведение Ollama
остается вне контроля Companion. При обогащении выполняется выбранная модель,
которая может выделять память CPU/GPU; после каждого ответа помощник отправляет
`keep_alive=0`, запрашивая немедленную выгрузку. `localMetadataVerified=true`
означает лишь, что сообщенные API Ollama поля дайджеста, размера, формата,
сведений о модели, возможностей и маркеров `remote`/`cloud` прошли проверки
Companion. Это не подтверждает содержимое весов модели на уровне байтов,
подлинность сервиса на адресе обратной петли, исключительно локальное выполнение
или отсутствие исходящего трафика Ollama. Подробнее:
[local-llm.md](skills/manage-code-ontology/references/local-llm.md).

## Конвейер workspace

```text
authorized source
  -> private source manifest
  -> isolated staging analysis
  -> artifact validation
  -> immutable snapshot promotion
  -> current snapshot pointer
  -> RDF / interactive offline HTML / read-only MCP
```

Каждый снимок содержит `ontology.json`, `ontology.ttl`, `report.md`,
`graph.html`, `snapshot.json` и приватный `source-manifest.json`. Workspace также
содержит append-only `lineage.jsonl` и переносимый `lineage.ttl`.

## Переносимость RDF и lineage

Основной словарь сохраняет пространство имен Explorer 1.0 `co:`, поэтому прежние
экспорты остаются совместимыми. История происхождения использует W3C PROV-O и
документированное пространство имен Companion. Экспорты Turtle можно
импортировать в хранилища, совместимые с RDF 1.1. Для индексов, правил
логического вывода и расширений конкретного хранилища может потребоваться
сопоставление. Версия 0.5.2 сохраняет все прежние прямые триплеты связей и
стабильные идентификаторы, добавляя ресурсы `RelationshipEvidence` для правила,
основания, диапазона строк исходного файла, статуса времени выполнения и
метаданных ограничений.

## Ограничения статического анализа

Граф содержит свидетельства для навигации и планирования изменений; он не
является трассировкой выполнения, заключением о безопасности, доказательством
причинной связи или гарантией корректности. Рефлексия, сгенерированный код,
условия Spring, определяемые во время выполнения, динамические прокси, внешняя
конфигурация, версии зависимостей и метапрограммирование Python могут быть
отражены неполно. Перед использованием графа для планирования изменений
проверяйте категорию основания (`basis`), статус времени выполнения
(`runtime_status`), ограничения (`limitations`) каждой связи и матрицу покрытия
адаптеров. Связь со значением `runtime_unknown` представляет собой статическое
свидетельство, а не доказательство активации во время выполнения.
